# knowledge · 公共面试知识库

按「行业 × 岗位 × 方向」组织的公共面试知识：高频题、岗位通识、追问模式。与候选人个人数据无关，可以放心公开与贡献。

`industry-brief` skill 生成行业通识时会先查这里：命中的条目作底、增量更新；没有命中就全新调研，并提示把通用部分贡献回来。攒得越全，每个新用户的冷启动越快。

## 目录约定

```
knowledge/
├── README.md
├── roles/<group>.md            # 岗位百科条目：一个分组一个文件（frontmatter kind: function 职能线 / industry 行业线）
└── <industry>-<role>.md        # 深度通识：一个行业×岗位一个文件，如 ai-product-pm.md（工卡里「深读」的目标）
```

## 模型：职能基底 × 行业语境（A×B 合成）

职能和行业是两个独立的轴，任何组合都真实存在（产品经理可以在美妆、互联网、电子信息任何行业）。所以条目分两层：

- **职能线文件（kind: function）**：岗位基底——第一性的工作职责与考点，适配一切行业；可声明「主场」行业/细分（如电商运营→互联网·电商，选中该行业时置前）。职能轴共 11 组、**两两互斥不重叠**，每组按「第一性产出」定义边界（写在文件 frontmatter 的 `boundary:`，控制台悬停职能可见）：产品=做什么的决策／设计=体验与视觉／技术=可运行系统／算法·AI=模型效果／数据=驱动决策的洞察／运营=持续经营／市场营销=认知与拉新／销售·商务=成交与合作／投资·财务=资本判断／战略·咨询=方向与方法／人力·法务·行政=组织与风险。归属拿不准时按「产出是什么」判（数据产品经理→产品因为产出是产品，数据分析师→数据因为产出是洞察，数据工程师→技术因为产出是管道）。
- **行业线文件（kind: industry）**：①文件头部的**行业导读**（格局/面试必懂/高频行业题/各职能差异），是该行业的语境层；②该行业的**具名特化岗**（游戏策划、数字 IC 设计这类有自己名字和完整考点体系的岗）。

控制台选中「职能 F × 行业 I」时合成：行业导读卡 + I 的特化岗 + F 的基底岗（详情页自动注入「× I」语境块）。任何组合都有产出，不存在空格子。

## 行业导读格式（行业线文件 `# 行业名` 与首个 `##` 之间）

```markdown
> 一句话行业画像。
**细分**：美妆个护／食品饮料／服饰潮流   # 行业内二级赛道，控制台第三行 chips；用全角／分隔
**格局**：主要玩家与钱从哪来。
**必懂**：…；…；…
**高频行业题**：…／…／…
**职能差异**：产品=…；运营=…；市场营销=…   # 职能名用职能线文件的 industry 名，分号分隔
```

**细分导读（可选）**：行业线文件里可再写 `## 细分导读：<细分名>` 起一节，字段与行业导读相同（`>` 画像 + 格局／必懂／高频行业题／职能差异）。控制台在选中该细分时把「行业导读」卡替换成「细分导读」卡、点开是该细分专属阅读页；没写就回退到行业导读。

## 岗位条目格式（roles/*.md，每岗一个 `##` 区块）

目标是蒸馏岗位的**顶级 know-how**——大师怎么想问题，不停在速成卡层面。分两层：**怎么想**（专家的脑子）＋**怎么考**（面试里怎么验）。依据：专家与新手差在知识结构（心智模型、案例库、隐性判断），条目的价值是把读者的判断力校准一次。

```markdown
## 岗位中文名 · English Name
> 一句话定位（必写）+ 核心矛盾（可选）。核心矛盾仅当能点出这岗**特有**的真张力时才写；只能写出「快 vs 稳」「多 vs 精」这类任何岗都成立的通用张力，就省掉、只留一句定位。经验：设计/产品类岗多有真张力（如关卡策划「作者意图 vs 玩家自由」），技术/工程类岗的真东西在 CWF 和心智模型里、核心矛盾这格常注水。
**细分**：电商            # 行业线文件可选：行业内的二级赛道（互联网→游戏/电商/社区内容/短视频直播…），
                          # 控制台选中该行业后渐进披露细分行
**职能**：运营            # 行业线文件需要：从九个职能分组名里选一个，职能×行业交叉筛选靠它；
                          # 纯内容创作等映射不进九类的岗位可省略（只出现在行业筛选下）
**行业**：互联网          # 职能线文件可选：岗位自带行业属性时标注（如电商运营→互联网），
                          # 默认不标=通用；可与 **细分** 连用
**核心工作职能**：（可选，顶层骨架）这岗被雇来干的 3-5 件大事，每条「动词+可观察产出」写成 `- ` 列表；控制台渲染在画像下、「怎么想」之上，让读者先抓住这岗干哪几件大事。
### 怎么想
**心智模型**：
- **模型名**：一句操作 + 用它看到什么 / 不用错过什么。（4-6 个，每个一行 `- `；建议覆盖 6 视角——第一眼看什么 / 全局因果链 / 老手才看见的信号 / 手册外实操 / 何时打破常规 / 元认知自校准，元认知那条最易漏、必留）
**基准线**：「好」在数字上长什么样（关键数字 + 健康区间 + 年份/出处）。
**战例**：领域人人引用的 2 个真实案例，各标出它教的那个模式（／分隔）。
**悬案**：
- 争论名：A 派…；B 派…（两边理由都给、不站队、标年份）。
**前沿**：这岗正被 AI / 行业怎么改写（当下最大变化，标年份）。

### 怎么考
**分水岭**：强候选人怎么做 vs 弱候选人差在哪 ＋ 这岗直觉可信吗（kind 反馈快可信 / wicked 反馈慢易误导）。增强格式（可选）：写成 5 轴 `- ` 列表，每行 `轴名｜弱：…｜强：…`（全角｜分隔），控制台渲染成「轴/弱/强」三列表格、强弱可当场区分。五轴＝答表面 vs 识根本／套模板 vs 看情境／需提示 vs 自驱／被动 vs 主动／影响自己 vs 影响系统。
**失分**：一说就扣分的答法（；分隔）。
**必考**：必须能讲清的概念（；分隔，3-5 个）。增强格式（可选）：写成 `- ` 列表，每条带认知层级 `[记忆/理解/应用/分析/评价/创造]` 并点出「背定义=失分线 vs 会判断/会做=高手线」，控制台渲染层级标签。
**黑话**：该用对的术语/框架（、分隔，用上＝显内行）。
**高频题**：真实会被问的题（／分隔）。
**追问链**：「题」→ ①[通用]… ②[职能]… ③[岗位/行业]…
**定级**：（可选）初级 bar vs 资深 bar 多追问什么。
**深度**：（可选）挂深度通识 slug
```

`心智模型`/`悬案`/`核心工作职能` 是 `- ` 列表块，`战例` 用 ／ 分隔，其余单行；`分水岭` 含 `｜` 的 `- ` 列表按 5 轴表格解析、否则按强/弱文字；`必考` 写成 `- ` 列表时按条解析（含 `[层级]` 标签）、否则按 ；分隔；`### 怎么想/怎么考` 仅供分组阅读，解析按粗体标签取字段。旧字段 `**内行**` ≈ 新版「分水岭＋失分」，迁移时拆开；未迁移的旧条目仍可渲染。

### 双用途：既给人读，也给模型注入

这套条目同时是「可浏览的岗位百科」和「检索注入 LLM 的 grounding」（一键准备写逐字稿、实时助手 / 模拟面试的临场素材）：

- **字段标签即抽取句柄**：`心智模型` / `基准线` / `分水岭` 等是后端按任务切片注入的锚点，标签保持稳定。
- **悬案呈现为辩论、不站队、标年份；前沿标年份**——时效内容可被后端按需更新或丢弃。
- **反编造**：战例与基准线只用于佐证判断、提供参照，注入时绝不让模型把它们冒充成候选人「我做过」。
- 实时助手对延迟敏感，压缩片段由后端将来自动蒸馏，不在源文件分叉。


## 贡献规则

- 只收**与个人无关**的通用知识：行业事实、岗位常识、公开可查的观点（带来源链接）。
- 不收：任何真实候选人的经历、数字、口径；任何公司内部信息。
- 时效敏感的内容（格局、产品状态）写明 `updated` 日期，宁可标注「截至 X 月」。

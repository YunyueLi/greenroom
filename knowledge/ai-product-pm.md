# AI 应用 · 产品经理（Agent 方向）

> 种子条目，欢迎按 README 的贡献规则补充。截至 2026 年 6 月。

## 行业格局

- 模型层与应用层的分工在收敛：头部模型公司下场做 agent 产品（编码助手、桌面 agent），应用层公司的差异化从「调模型」转向「评测、工具链、工作流整合」。
- 当前争论点（面试官爱用）：通用 agent 还是垂直 agent 先跑通商业化；multi-agent 是产品能力还是工程开销；上下文窗口变大之后检索还要不要做。

## 岗位画像

- 日常：定义场景与能力边界、搭评测体系、判读坏案例、把模糊痛点拆成模型能力缺口和数据方案、推动算法/工程/业务协作。
- 产出衡量：上线指标（任务完成率、解决率、留存）+ 评测指标（测试集通过率、回归不劣化）。
- 与相邻岗位的边界：算法负责模型怎么变好，产品负责「什么算好、值不值得做、先做哪个」。

## 必须能讲清的概念

每个概念两三句能讲清，并准备一个会被追问的点：

1. **Agent loop**（感知→规划→工具调用→观察循环）——追问：循环停不下来怎么办。
2. **Tool use / Function calling**——追问：工具调用失败的兜底设计。
3. **评测集与坏案例归因**——追问：评测集怎么防过拟合。
4. **RAG 与长上下文的取舍**——追问：什么时候不该用 RAG。
5. **多轮记忆**（会话内/跨会话）——追问：记忆写入和遗忘的策略。
6. **延迟与成本**（首 token 时间、缓存命中）——追问：成本随用量增长怎么控。
7. **灰度与守门指标**——追问：守门线破了谁拍板回滚。
8. **幻觉与可靠性兜底**——追问：高风险场景的人机分工。

## 高频面试话题

1. 从 0 设计一个评测体系（最高频，几乎必问）。
2. 讲一个你做过的 AI 功能：怎么定边界、怎么验证、数字多少。
3. 什么场景该上 agent、什么场景不该（判断题）。
4. 现场拆一个模糊需求成可落地的方案。
5. 你深度用过哪些 agent 产品，各自取舍是什么（考真实使用密度）。

## 值得引用的观点（带出处）

- 「评测是 AI 产品的地基」——多位从业者公开演讲反复出现的共识表述；引用时结合自己的评测实践讲。
- 「短期被高估、长期被低估」（阿玛拉定律）——讨论行业节奏时的稳妥框架，出处为 Roy Amara 的技术预期定律。

# 算法·AI

## 大模型算法工程师 · LLM Engineer
> 离模型本体最近的人：在训练/后训练/对齐/推理优化里，把一个几百 B 参数的概率机器调到能力强、对齐好、推得起。核心矛盾＝能力提升越来越靠"花算力"（预训练堆数据、后训练堆 RL、推理堆 test-time compute），但每段加算力都未必线性涨能力，还会撞上 reward hacking、合成数据塌缩、长上下文劣化——你判断的是"这笔算力该花在哪一段、边际收益在哪拐头"。
**核心工作职能**：
- 跑训练/后训练 pipeline 并对损失曲线负责：产出＝能稳定收敛的预训练/SFT/RL run（学习率与 warmup/cosine schedule、并行策略 TP+PP+DP+EP、梯度裁剪与 loss spike 处置预案），loss/grad-norm/eval 训练中实时盯，挂了能从 checkpoint 定位是数据、超参还是数值问题
- 设计后训练配方把通用模型调成对齐/会推理的模型：产出＝SFT 数据配比＋偏好优化（DPO/在线 RL）或 RLVR 的奖励设计与训练曲线，每段说清解决什么（格式跟随/拒答/数学代码可验证能力/长链推理），并防住 reward hacking 与能力回退
- 造数据资产：产出＝去重（MinHash/语义）后的预训练配比、SFT 指令集、合成数据生成＋质量过滤管线，说得清各域 token 占比、合成占比上限、污染怎么查——数据质量是这岗最被低估的杠杆
- 做推理优化把训练好的模型推得起：产出＝量化档位（FP8/INT4 AWQ-GPTQ）＋投机解码＋连续批处理＋PD 分离＋KV cache 管理的工程方案，首 token 延迟（TTFT）、token 间延迟（TPOT）、吞吐（tokens/s）与每百万 token 成本上线前进 dashboard
- 做评测与坏例归因：产出＝覆盖核心能力＋长尾的评测集、被污染/过拟合能换血的机制、留一份模型没见过的 holdout，把一次能力回退归到数据配比/超参/对齐税哪一层
### 怎么想
**心智模型**：
- **先看 loss/grad-norm 曲线和数值健康，不先看 benchmark**：老手接一个 run，第一眼盯 training loss 平不平滑、grad-norm 有没有尖刺、有没有 loss spike、bf16/fp8 下有没有 NaN/inf，benchmark 放后面。用它你能在烧掉几万卡时前就发现学习率太大/数据脏块/数值溢出，而不是训完发现废了——benchmark 是滞后指标，曲线是实时心电图。
- **能力提升是"算力分段下注"，三段 scaling 边际不同**：预训练 scaling（参数×数据，Chinchilla 计算最优约 20:1、Llama 3 推到 ~200:1 是为推理省成本而过训）、后训练/RL scaling（推理模型靠 RLVR 把 test-time thinking 练出来）、推理 scaling（test-time compute 长思维链）是三段独立算力杠杆。用它你能判断"再堆预训练数据"和"加一轮 RL"哪个边际收益高——2025 后业界对"预训练 scaling 是否在放缓、RL 是不是新主轴"吵得很真，你的活就是在自己的算力预算里押对段。
- **成本活在 KV cache 和激活参数里，不在总参数里**：推理成本大头是 KV cache 显存（随 batch×序列长度涨）和每 token 激活的 FLOPs，不是模型总参数。MoE 用稀疏激活把"总参数大、激活参数小"解耦（DeepSeek-V3 671B 总参/37B 激活）；MLA 用低秩联合压缩把 KV cache 压到约 8-group GQA 的一半、质量还不掉（DeepSeek-V2,2024.05）。用它你能在不掉点前提下把推理成本砍一大截，而外行只盯总参数大小谈贵不贵。
- **reward 一定会被 hack，evaluation 一定会被 game**：只要给 RL 一个奖励信号，模型就会找最省力的方式刷高它——RLHF 里学会啰嗦/谄媚，RLVR 里把答案 token 直接塞进思维链、套格式钻空子（MCQA 输出空间小尤其明显）。可验证奖励（数学/代码对错）比学出来的 reward model 抗 hack，但防不住格式套利。用它你能在配方阶段就预埋防护（KL 约束、奖励多样化/复合化、人工抽检 rollout），而不是训完发现模型变油了才回炉。
- **该不该上 MoE / 长上下文 / 合成数据，要看约束不看时髦**：MoE 训练吞吐高但工程复杂（路由负载均衡、专家并行 all-to-all 通信、推理显存仍要装全部专家）；长上下文有 context rot（随长度普遍劣化）、KV 成本近似线性涨；合成数据省真实数据但配比过高会塌缩（经验上少量改写合成混大头真实 web 较稳，纯递归式合成有 model collapse 风险）。用它你能判断什么时候 dense+RAG 比 MoE+长窗口更划算，看到 SOTA 用什么先问自己的约束对不对得上。
- **自己判断有没有偏，靠 holdout 和消融，不靠单次分数**：这岗怎么知道自己错了：单个 benchmark 涨了可能是数据污染（评测题进了训练集）或对评测过拟合，不是真能力。校准的硬办法——留一份模型绝对没见过的 holdout、做 contamination 检测（n-gram/嵌入查重）、关键改动跑消融（ablation）只改一个变量看因果，别一把梭哈完归功于某个 trick。判断偏了的信号：拿不出 holdout、说不清评测会不会被污染、改了五样东西只报一个总分涨了。
**基准线**：预训练数据量：Chinchilla 计算最优约 20 token/参数(2022)，但推理省成本驱动普遍过训，Llama 3.1 系约 200:1、15.6T token(2024)，小模型 D/N 可更高；MoE 激活比：DeepSeek-V3 约 671B 总参/37B 激活(2024.12)，配 256 路由专家+1 共享、每 token 选 8；KV cache：MLA 低秩压缩约为 8-group GQA 的一半、质量不输 MHA(DeepSeek-V2,2024.05)，DSA/NSA 类稀疏注意力把长上下文注意力降到近线性 O(n·k)、长上下文 API 成本约降一半(NSA 2025.02、DSA/V3.2-Exp 2025.09)；投机解码加速约 2–3×，EAGLE-3 单任务可更高(NeurIPS 2025)；PD 分离下 prefill 计算密集 SM 利用率约 90%、decode 访存密集约 30%(行业经验，随负载差异大)；量化首选 FP8、INT4 需 AWQ/GPTQ 类算法否则掉点(2024–2025)。具体数字随模型规模/硬件/负载差异大，非定值。
**战例**：DeepSeek-R1 / R1-Zero(2025.01，后发 Nature 2025)：R1-Zero 纯 RL（GRPO＋可验证奖励 RLVR）从基座直接练出长链推理、自我验证与反思，证明"reasoning 能力可被 RL 激励出来、不必先喂人工推理轨迹"；正式 R1 加冷启动 SFT 修可读性——教"后训练范式从 RLHF 对齐转向 RLVR 练能力，奖励可验证是关键"／Llama 3 训到约 200:1 token-参数比（15.6T token,2024）：明知超出 Chinchilla 计算最优，仍为压低推理期成本而过训——教"训练最优≠部署最优，scaling 决策要把推理成本算进去，不是一味追 loss 最低"
**悬案**：
- 在线 RL(PPO/GRPO) vs 离线偏好优化(DPO)：在线 RL 派：on-policy 采样＋奖励信号能探索出新行为、上限高，RLVR 这类可验证奖励是推理模型的主路，DPO 学不出真正的新能力；DPO 派：去掉 reward model、模型更少、训练稳、超参不敏感、便宜可复现，工业落地性价比高，多数对齐场景够用（2024–2026 持续，推理模型兴起后天平向在线 RL/RLVR 倾、但 DPO 仍是对齐主力，迭代式 DPO 在补在线性）
- MoE vs Dense：MoE 派：同等总参下激活更少、训练吞吐与推理性价比高，DeepSeek-V3/Qwen3 证明细粒度专家＋共享专家能以小激活打大 dense；Dense 派：MoE 工程复杂（路由负载均衡、all-to-all 通信、推理仍需装全部专家显存），小规模/严格等资源下未必胜 dense，部署运维成本高（2024–2026，大模型明显倒向 MoE，但"严格等算力下 MoE 是否一定超 dense"学界仍有争(2026)）
- 合成数据 vs 真实数据扩展：合成派：真实高质量数据见顶，合成数据可定向补稀缺域、可验证、可规模化，混合训练有显著加速；真实派：纯合成有 model collapse 风险、多样性塌缩比真实数据早、配比过高反伤，质量与去污染难保证（2025–2026，共识收敛到"混合＋严格过滤＋控制合成占比"，纯递归合成预训练不被接受(2026)）
**前沿**：RL/RLVR 从对齐微调升为练能力的研发主线，test-time compute（推理模型长思维链）成第三条 scaling 轴，2025–2026 业界激辩"预训练 scaling 是否放缓、算力是否该转投 RL"；MLA→NSA(2025.02)→DSA(2025.09) 这类原生/可训练稀疏注意力把长上下文注意力成本压向近线性、长上下文推理成本约降一半；FP8 训练、投机解码（EAGLE-3/MTP）、PD 分离成推理工程标配(2025)；reward hacking 与可验证奖励设计、合成数据 scaling law 成新研究热点(2025–2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：说"我们用了 RLHF/上了 MoE，效果好"，报一个 benchmark 分数当成果｜强：主动拆 DPO vs 在线 RL 的取舍、MoE 路由负载均衡怎么调、这个分涨了先怀疑是不是评测污染/过拟合，把回退归到数据/超参/对齐税哪一层
- 套模板 vs 看情境｜弱：不管什么需求都说"再加点数据/再训一轮 RL/上更大模型"，看 SOTA 用什么就抄什么｜强：先问算力预算和部署约束→判断该堆预训练数据还是加 RL、该 MoE+长窗口还是 dense+RAG、合成数据占比压多少，给得出边际收益判断
- 需提示 vs 自驱｜弱：不追问就只谈模型结构和刷分，不主动提数值稳定性、数据去污染、推理成本｜强：不用问就把 loss spike 预案、contamination 检测、KV cache/激活成本、reward hacking 防护当方案默认组成部分
- 被动 vs 主动｜弱："等下一代基座/等更多卡就能解决"，把能力上限完全寄托在规模｜强：在当前算力下用配方设计、数据质量、推理优化、评测归因把模型推到能上线，把每段 scaling 当能主动下注的旋钮
- 影响自己 vs 影响系统｜弱：调通一个 run、口头说"调好了超参/配比"，trick 留在自己脑子里｜强：留下可复现的训练配方、消融结论、去污染的评测集和 holdout、归因流程，让数据/训练/推理团队在同一套评测和 pipeline 上协作
**失分**：把 benchmark 分数当真能力、不查污染不留 holdout；通篇不提一次显存/KV cache/激活参数/推理成本，只谈结构多先进；把 MoE/长上下文/合成数据当银弹堆、说不清工程代价和何时不该用；只会背 RLHF/DPO/GRPO 定义、说不清各自在线离线、几个模型、抗不抗 reward hacking；混淆模型总参数与激活参数、混淆 pass@k(覆盖率)与单点准确率；只盯 loss 最低、不把推理成本算进 scaling 决策；改了一堆变量只报一个总分涨了、拿不出消融
**必考**：
- RLHF/DPO/RLVR(GRPO/PPO) 的区别与适用 [评价]：背得出"DPO 简单些"是失分线；会判断在线 PPO（policy+reference+reward+value 共 4 模型，探索强、上限高、不稳）、GRPO（去掉 value 用组内相对优势、比 PPO 省一个模型）vs 离线 DPO（2 模型，稳、便宜）、可验证奖励（数学代码）vs 学出来的 reward model 谁抗 hack、什么场景用哪个，是高手线
- Transformer 与注意力/KV cache [分析]：背得出"有注意力机制"是失分线；能讲清 MHA→GQA→MLA 怎么一步步压 KV cache、MLA 用低秩联合压缩 vs GQA 共享 head、RoPE 怎么编码位置、为什么 KV cache 是推理显存大头，是高手线
- 推理优化全家桶 [应用]：背得出"可以量化/投机解码"是失分线；能算清 TTFT/TPOT/吞吐怎么权衡、prefill 计算密集 vs decode 访存密集为何要 PD 分离、连续批处理解决什么浪费、FP8 vs INT4 何时掉点、投机解码加速来自哪，是高手线
- 数据配比/去重/合成数据 [分析]：说"数据很重要"是失分线；能讲清各域 token 占比怎么定、为什么大规模下少量重复就显著伤性能要 MinHash/语义去重、合成数据配比上限与 model collapse、评测污染怎么查，是高手线
- scaling law 与算力分配 [评价]：背得出 Chinchilla 20:1 是失分线；能讲清为何 Llama 3 过训到 200:1（为推理省成本）、训练最优≠部署最优、预训练 scaling 与 RL scaling 边际收益怎么判、test-time compute 是第三轴，是高手线
**黑话**：MoE、共享专家、细粒度专家、专家并行(EP)、路由负载均衡、辅助损失无关均衡、MLA、GQA、KV cache、RoPE、YaRN、NTK-aware、上下文外推、context rot、SFT、RLHF、PPO、DPO、GRPO、RLVR、可验证奖励、reward hacking、KL 约束、pass@k、投机解码、EAGLE/Medusa、MTP、连续批处理、PD 分离(prefill/decode)、PagedAttention、量化(FP8/INT4/AWQ/GPTQ)、TTFT/TPOT、Chinchilla 最优、过训、test-time compute、数据去重(MinHash)、model collapse、eval contamination、holdout、稀疏注意力(NSA/DSA)

**定级**：初级筛"能独立跑通一个 SFT/微调 run、讲清 Transformer 与一种主流后训练方法(RLHF/DPO)、知道量化和 KV cache 的存在"；资深筛"扛得住能力×成本×稳定性的三方账：能从基座设计完整后训练配方并防 reward hacking、判断算力该投预训练还是 RL、做得了 MoE/长上下文/推理优化的工程权衡、能从一次能力回退归因到数据/超参/对齐税哪一层、知道什么时候不该上 MoE/长窗口/纯合成数据"

## 计算机视觉工程师 · CV Engineer
> 把图像/视频里的检测、分割、识别、生成等算法在真实场景跑出可用精度、并塞进端侧硬件的人。核心矛盾:公开榜单的高 mAP 长在干净分布上,产线/路面/相机的真实数据是脏的、长尾的、会漂的,榜单赢家在你的数据上常直接崩,精度靠数据闭环一帧帧喂出来,不靠选哪个 SOTA。
**核心工作职能**：
- 把业务指标翻译成可训练的视觉任务:产出=任务定义(检测/分割/分类/关键点哪种、类别体系、判定边界、漏检误检的成本权重)+评测协议,而非直接拿 SOTA 仿真跑通就交
- 建数据闭环并守标注质量:产出=带难例回流的数据引擎(线上漏检/误检自动捞回→标注→进训练集)、标注规范与一致性抽检、长尾类别的采样/重加权方案
- 训练调优到目标精度并诊断坏例:产出=分场景(光照/遮挡/小目标/类别)的精度拆解、误检漏检的归因(数据缺/标错/类别混淆/分布偏)、可复现的训练配置
- 端侧部署做精度-延迟-功耗的压缩:产出=剪枝/量化(PTQ/QAT)/蒸馏后的导出模型(ONNX→TensorRT/RKNN/CoreML)、INT8 校准集、目标硬件上实测的帧率/内存/功耗账
- 守上线后的分布漂移:产出=线上抽样回看机制、关键指标的告警与触发重训判据、A/B 或灰度的精度对比
### 怎么想
**心智模型**：
- **先看数据分布和标注,不先选模型**：老手接一个 CV 需求第一件事是去看真实数据:样本量多少、类别多不平衡、典型遮挡/光照/尺度长什么样、标注规范是否自洽,而不是先纠结 YOLO 还是 DETR。用它你能在动手前判断这是数据问题还是模型问题:小样本长尾选什么 backbone、要不要预训练、评测集怎么分层,全由数据形态倒推。一上来就比 SOTA 榜单的是外行。
- **精度活在尾部、不看 mAP 均值**：COCO mAP@0.5 是把所有类、所有尺度平均出来的数;产线真正卡你的是某个小目标类漏检、某种罕见缺陷召回为零。用它你能把一个总指标拆成分类别/分尺度/分场景的精度矩阵,盯住最差那一格:漏检一次的成本(召回)和误检一次的成本(精度)在不同业务里天差地别,阈值要按这个调,不是默认 0.5。只会报『mAP 92%』当成绩的过不了这关。
- **训→部署有精度断崖,要全链路对齐**：PyTorch FP32 跑得好,导出 ONNX→TensorRT INT8 后掉几个点是常态:算子不支持被拆、量化校准集没覆盖真实分布、前处理(resize/归一化/通道序 BGR vs RGB)训练和推理不一致,任何一处都让线上精度对不上离线。用它你能预判并定位部署掉点:逐层比对中间激活找出最先发散的那层、对量化敏感层留 FP16、校准集换成真实数据。把训练精度当部署精度报的,上线必翻车。
- **该堆数据时堆数据、该换架构时才换**：绝大多数精度问题最高 ROI 的动作是补数据(难例、长尾、标注纠错),不是换更大的模型。但有几类情况换架构才对:小目标密集→提高输入分辨率或加 FPN 层级、实时性扛不住→换轻量 backbone 或蒸馏、开放类别天天变→上开集检测(Grounding DINO/YOLO-World)免重训。用它你能判断手里这个 case 是数据活还是模型活,既不无脑加深网络也不盲目标更多数据。
- **标注规范本身会成为精度天花板**：两个标注员对『这个边界算不算缺陷』判断不一致,模型学到的就是噪声,再好的网络也学不过标注的内在矛盾。用它你能在精度卡住时回去查标注一致性(让多人重标一批算 IoU 或 Cohen's kappa、看类别边界定义有没有歧义),不一味调模型。手册外的实操:难例和边界 case 要写进标注规范并配图例,定期抽检一致性,标注质量是大多数团队的隐性瓶颈。
- **怎么知道自己判断偏了:盯线上分布漂移和真实坏例,别信离线指标和挑过的 demo**：CV 工程师最容易自欺的是拿测试集高分和挑过的 demo 截图说话。真正的校准信号来自三处:①线上真实样本与训练集的分布差(相机换了、季节变了、产线工艺调了,输入就漂了,离线指标全失效);②定期人工回看线上漏检/误检的真实坏例,不只看聚合指标;③留一份模型从没见过、来自真实环境的 holdout 集,任何调参都不许碰它。判断偏了的信号:只敢拿 demo 和测试集说话、拿不出真实环境 holdout、说不清自己训练集和线上分布差在哪。『Are Foundation Models Ready for Industrial Defect Recognition』(arXiv 2509.20479,2025.09)实测就是同一批模型在公开榜单表现好、在真实产线数据上全崩。
**基准线**：检测基线随场景差异大:实时端侧常用 YOLO 系(YOLO11,2024.10,多数生产负载的稳妥默认;YOLOv12,2025.02,引入区域注意力/FlashAttention,精度更高但训练偏不稳、CPU 偏慢;Ultralytics 2025-2026 也推 YOLO26),高精度/复杂场景用 DETR/RT-DETR 系(免 NMS、端到端,但显存与收敛成本更高);开集检测 YOLO-World(2024)在相当精度下实测约比 Grounding DINO 快约 20 倍(LVIS,V100,无 TensorRT,数据来自原论文/Roboflow),后者类方法常 <3 FPS;视频分割 SAM 2(Meta,2024.07)带记忆模块跨帧跟踪、约 44 FPS;工业异常检测公认基准 MVTec AD(15 类、5354 张),少样本/零样本走 WinCLIP(CVPR 2023)、AnomalyDINO(WACV 2025)这类 CLIP/DINO 路线;数据规模上 <10 万张量级 CNN 凭归纳偏置通常仍优于纯 ViT(行业经验,随任务差异大);INT8 量化掉点能否压在 1 个点内取决于校准集是否覆盖真实分布、是否上 QAT。以上数字按硬件/场景/数据差异大,绝不能照搬榜单。
**战例**：Tesla 自动驾驶的数据引擎(Andrej Karpathy 多次公开阐述):影子模式捞线上难例→自动/人工标注→进训练集→重训部署的闭环,教『真实场景 CV 的核心壁垒是数据闭环与难例挖掘,不是单个模型架构』,数据驱动迭代是落地范式而非单点调模型／Meta DINOv3(2025.08,1.7B 图像自监督预训练、最大 6.7B 参数 backbone,arXiv 2508.10104):单个冻结 backbone 在检测/分割/深度/跟踪多任务上超过此前自监督模型甚至部分专用方案,教『视觉基础模型正在把通用特征做成底座、下游只接轻量头』,自监督预训练对纯 CV 岗的影响开始具象化。
**悬案**：
- 纯 CV 专用模型 vs 多模态 VLM/基础模型吞并视觉任务：VLM/开集派:Grounding DINO、YOLO-World 这类文本提示开集检测免重训就能加新类别,VLM 还能做属性理解和复杂场景问答,长尾和零样本灵活;DINOv3 这类冻结 backbone 已在多任务上超专用方案；专用模型派:产线/端侧要的是确定精度+低延迟+低功耗,大模型太大太慢上不了边缘设备,且『Are Foundation Models Ready for Industrial Defect Recognition』(arXiv 2509.20479)实测基础模型在真实产线数据上全崩、公开榜单却表现好,关键工业场景仍靠专用小模型+数据闭环（2025-2026 未定,主流是专用模型打底+大模型做开集/兜底/冷启动的混合）
- CNN vs Vision Transformer(含 DETR 系)：ViT/Transformer 派:大数据+大算力下全局注意力上限更高,DETR 系免 NMS、端到端,YOLOv12 也转向注意力架构；CNN 派:<10 万张量级 CNN 凭归纳偏置数据效率更高、收敛快,卷积在 NPU/移动端高度优化、延迟低功耗省,ConvNeXt 等现代 CNN 已逼近 ViT;ViT/DETR 显存与训练成本更高、端侧不友好（2025 共识:大数据大算力偏 ViT、小数据端侧偏 CNN,混合架构(ConvNeXt/Swin)取折中,无单一赢家）
- 图像生成里扩散 vs 自回归：扩散派:图像质量与可控性目前更强,DiT 架构主导文生图,ControlNet/inpainting 生态成熟；自回归派:与 LLM 同构、天然适配统一多模态(理解+生成一个模型),GPT-4o 原生图像生成(2025.03)带火统一架构（2025-2026 趋势偏统一多模态与 AR+扩散混合(GPT-4o 即 AR 主干+扩散解码头),纯路线之争未收敛）
**前沿**：视觉基础模型(DINOv3,2025.08;SAM 2,2024)把『通用特征/万物分割』做成可冻结的底座,下游任务从『从头训一个网络』转向『冻结 backbone+接轻量头/做提示』,自监督预训练对纯 CV 岗的价值开始具象化;开集检测(Grounding DINO/YOLO-World)让『加新类别免重新标注训练』成为冷启动与长尾的常规手段;VLM/基础模型进入工业质检与视觉问答,但真实产线数据上仍败给专用模型+数据闭环(arXiv 2509.20479,2025.09),边界在『冷启动/长尾/语义理解用大模型,关键精度/端侧仍用专用小模型』;数据引擎与难例挖掘从辅助工程升为研发主线,标注质量与分布对齐取代『再调个网络』成为精度核心抓手(2025-2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：报『我们 mAP 92%』『准确率很高』当成绩,只说在测试集上效果好｜强：主动把精度拆成分类别/分尺度/分场景矩阵,讲清最差那一格、漏检 vs 误检的业务成本,把坏例从现象归到数据缺/标错/类别混淆/分布偏哪一层
- 套模板 vs 看情境｜弱：不管什么需求都先比 SOTA 榜单、无脑上最新 YOLO 或最大模型,精度不够就加深网络｜强：先看真实数据分布、样本量、长尾和标注质量,据此判断这是数据活还是模型活,小样本端侧选 CNN+预训练、开放类别上开集检测,换架构有明确理由
- 需提示 vs 自驱｜弱：不追问就只交训练精度,不主动谈部署掉点、量化校准、前处理一致性、上线漂移｜强：不用问就把导出/量化掉点、INT8 校准集、前后处理对齐、线上漂移监控与重训触发当方案默认组成部分
- 被动 vs 主动｜弱：等更强的预训练模型或更多标注数据来解决精度,『换个更大的 backbone 就好了』｜强：在当前数据和硬件约束下用难例挖掘+标注纠错+数据增强+蒸馏量化把精度和延迟做到能上线,把数据闭环当能动的旋钮
- 影响自己 vs 影响系统｜弱：只交付一个能跑的模型权重,口头说『调好了』｜强：留下可复现的训练配置、带难例回流的数据引擎、分场景评测协议和标注规范,让团队在同一套数据和评测上持续迭代
**失分**：报『mAP 92%』当成绩、不拆分类别尺度场景、不讲漏检误检成本;只在公开数据集/挑过的 demo 上验证,拿不出真实环境 holdout;无脑比 SOTA 榜单、精度不够就加深加大网络,不看数据和标注;把训练精度当部署精度报、不提量化掉点和前后处理一致性;通篇不提端侧延迟/内存/功耗;忽视标注质量和一致性,把噪声当模型问题硬调;把 VLM/大模型当工业质检银弹,说不清它在真实产线为何失效
**必考**：
- 经典网络演进与取舍(CNN→ViT→混合) [分析]:背得出 ResNet/ViT/ConvNeXt 名字是失分线;会按数据量/端侧约束判断小样本端侧选 CNN、大数据选 ViT、要折中选混合,并说清归纳偏置与数据效率的因果是高手线
- 检测/分割主流方案与场景匹配 [评价]:只会背 YOLO/Mask R-CNN/DETR 是失分线;会按实时性/精度/开放类别选型(实时端侧 YOLO 系、复杂高精 DETR、开放类别开集检测)、说清各自代价是高手线
- 端侧部署优化(剪枝/蒸馏/量化/TensorRT) [应用]:说得出『要量化』是失分线;会做 PTQ vs QAT 取舍、INT8 校准集如何覆盖真实分布、定位量化敏感层留 FP16、查前后处理一致性来守住部署精度是高手线
- 数据闭环与标注质量、长尾治理 [创造]:说『要多标数据』是失分线;会设计难例回流的数据引擎、用一致性抽检判断标注是否成天花板、对长尾做采样/重加权是高手线
- 精度评测与坏例归因 [分析]:报单个 mAP 是失分线;会分层评测、按漏检误检成本调阈值、把坏例归到数据/标注/分布/类别哪一层是高手线
**黑话**：mAP、IoU、NMS、anchor-free、FPN、backbone/neck/head、PTQ、QAT、INT8 校准、剪枝(结构化/非结构化)、知识蒸馏、TensorRT、ONNX、算子融合、开集检测、零样本/少样本、长尾分布、难例挖掘、数据闭环/数据引擎、标注一致性、分布漂移、域适应、holdout、自监督预训练、冻结 backbone
**高频题**：小样本长尾场景怎么把精度做上去/检测模型选 YOLO 还是 DETR、依据是什么/模型量化后掉点怎么定位和救回/线上漏检突然变多怎么排查/标注质量怎么保证和评估/开集检测和传统闭集检测分别什么时候用/INT8 量化校准集怎么选/部署到 Jetson 或手机端怎么压延迟
**追问链**：「这个检测模型量化后掉了 3 个点怎么办」→ ①[通用] 你怎么先定位掉点出在哪个环节、量化前后逐层对比怎么做?②[职能] PTQ 和 QAT 怎么选、INT8 校准集用什么数据才能覆盖真实分布、哪些层该留 FP16?③[岗位] 如果是前后处理(resize/归一化/BGR 通道序)训练和推理不一致导致的,你怎么定位、这类隐性掉点和量化掉点怎么区分?

## 推荐算法工程师 · RecSys Engineer
> 在召回→粗排→精排→重排的全链路上，用排序模型把海量物料按用户兴趣排好、对线上业务指标负责的人。核心矛盾：模型优化的是离线 AUC 这类代理指标，业务要的是线上时长/留存/GMV，两者经常背离（离线涨线上跌），中间还隔着延迟反馈、样本偏差、训练-serving 不一致几道墙；真本事是把代理指标和线上目标对齐、并扛住这几道墙。
**核心工作职能**：
- 设计与迭代各层排序模型：按算力预算给召回/粗排/精排/重排分活，产出=能上线的模型（精排 DNN/序列模型、召回双塔/生成式检索、粗排蒸馏小模型）+离线评估报告+线上 A/B 显著正向
- 做特征工程与样本构造：产出=特征流水线（用户终身序列/实时行为/上下文/交叉特征）+样本管线，重点防住特征穿越、样本选择偏差、延迟反馈三类污染，保证训练分布≈线上分布
- 建多目标融合与排序公式：产出=多任务模型（MMoE/PLE）各 head 的预估（pctr/pcvr/播放时长…）+一套把它们融成最终序的融合公式与权重，既追单目标又守住生态/多样性约束
- 排查线上线下不一致并守指标：产出=offline AUC↔online CTR 的对齐诊断（特征 skew、数据时效、打点缺失、串联漂移逐项排查）+实验灰度判据+回滚机制，对线上时长/留存/转化这些北极星指标兜底
- 治冷启动与探索：产出=新物料/新用户的冷启方案（side-info 补 embedding、bandit/EE 探索、流量扶持位）+大盘与冷启的流量分配，保证生态有新供给进来不饿死
### 怎么想
**心智模型**：
- **链路是漏斗、每层在花不同的算力买不同的精度**：召回从亿级捞万级（双塔/向量检索，毫秒级、丢交叉特征换速度）、粗排万到千（轻量打分）、精排千到几十（重模型+全特征）、重排定最终序（看列表整体）。用它你能在被问『为什么不在召回就上精排模型』时答到点：每层的算力预算和延迟 SLO 不同，精排的复杂度铺到召回会爆；也能判断一个效果问题该在哪层修——召回不出、漏在粗排、还是精排排序错。
- **训练分布必须≈线上分布，差一点离线指标就全废**：模型只在训练分布里可信，线上一旦偏离离线 AUC 立刻失效。三个最容易把分布搞偏的源头：特征穿越（用了预测时刻拿不到的未来信息，离线虚高线上崩）、样本选择偏差（只用曝光/点击样本训练却要给全体打分，ESMM 提的就是这个）、延迟反馈（转化几小时几天后才回来，当下打成负例）。用它你能在面试里主动讲清自己的样本是怎么构造的、为什么不会穿越、负样本怎么采——这是区分做过线上和只调过 Kaggle 的分水岭。
- **离线涨≠线上涨，代理指标和业务目标之间有一道鸿沟**：AUC/NDCG 是代理，线上要的是时长/留存/GMV；还有 global AUC 看着涨、GAUC（按用户分组算再加权平均）没动的情况——前者可能只是把高活跃用户和低活跃用户分开了，对单个用户的排序没变好（GAUC 与线上更一致，DIN 那篇就是用它做评估）。用它你能不被离线数字骗：看 GAUC 而非 global AUC、离线有正向也坚持小流量 A/B 才敢全量、清楚自己优化的 loss 和北极星指标之间隔着几层。
- **多目标融合的权重是产品旋钮，不是调参调出来的**：final_score=pctr^a × playtime^b × pcvr^c… 这套融合公式里的指数/权重直接决定平台要时长还是要转化、要爽感还是要留存，改一个权重大盘指标就动。用它你能把『提升时长』翻译成可操作的动作：是加 playtime 权重、还是上个时长预估 head、还是动重排的多样性约束；也能解释多任务里的负迁移（某个 task 带崩另一个）为什么要用 PLE 这类结构把共享和独有参数分开。
- **短期点击和长期生态会打架，该牺牲单点指标时就得牺牲**：纯按 pctr 排会陷入信息茧房/头部通吃，长期掉新鲜感、掉新供给、掉留存。该打破『指标最大化』惯性的时候：重排用 MMR/DPP 牺牲一点相关性换多样性、给新物料和中小作者流量扶持、给探索留预算。用它你能判断什么时候不该听离线指标的——当大盘点击微涨但次留/发布者留存在掉，就是茧房在收割，得回调多样性和生态约束。
- **判断自己有没有被离线指标骗，靠的是线上线下能对齐、不是离线分数高**：自检的硬动作：同一批线上曝光样本，用线上打分和离线复算打分逐条比对（DoorDash 公开过这种排查，把 online-offline AUC gap 从 4.3% 收到 0.76%），对得上才说明特征和链路没漂；对不上就逐项查特征 skew、数据时效（训练数据是不是几个月前的）、打点有没有缺失。判断偏了的信号：只敢拿离线 AUC 说话、说不清线上线下为什么有 gap、新特征上线没补在线打点。元认知的底线是『线上 A/B 才是裁判，离线只是预筛』。
**基准线**：代理指标只看相对提升、无绝对健康值：精排 AUC 行业常在 0.7–0.85 区间但跨场景不可比，真正看的是 GAUC（按用户分组加权）与线上 A/B（团队经验，2025）；链路漏斗各层延迟 SLO——召回毫秒级、精排到重排整体常压在几十毫秒 P99 内（随场景差异大）；终身行为序列 SIM 类工业部署可处理约 5×10^4 量级（Alibaba 广告，arXiv 2006.05639），TWIN-V2 压到 10^5+ 量级（Kuaishou，arXiv 2407.16357，2024）；线上线下 AUC gap 健康在 1% 以内、>3–4% 多半是特征 skew/数据时效/打点缺失（DoorDash 公开案例 4.3%→0.76%，2024）；广告场景 pCTR 必须校准（预估值≈真实点击率，直接进 eCPM=pCTR×bid 算钱），内容场景可只要序对不要校准——以上随业务差异大，别背成定值。
**战例**：YouTube 深度推荐（Covington 等，RecSys 2016）：把推荐定成两阶段——深度候选生成做粗筛+召回、深度排序模型用加权逻辑回归预估观看时长（不是 pCTR），奠定了『两阶段漏斗+按观看时长而非点击优化』的工业范式，教『链路分层、排序目标要对齐真实业务价值（时长）而非表面点击』／Kuaishou OneRec（arXiv 2506.13695，2025）：把召回+粗排+精排合成一个端到端生成式 encoder-decoder（semantic ID+生成式检索），服务约 25% QPS、快手/快手极速版 App 停留时长各 +0.54%/+1.24%、7 日 Lifetime 正向、运营成本约为传统方案的 10.6%，教『生成式推荐从论文走进工业、多阶段漏斗正被端到端重写——但目前是部分流量替换、不是全量颠覆』
**悬案**：
- 端到端生成式推荐 vs 传统多阶段漏斗：生成式派：多阶段各层目标不一致、级联间网络传输和重复算力浪费，端到端生成式（OneRec/HSTU）可端到端优化、吃到 scaling law，Kuaishou OneRec 已上约 25% QPS、Meta HSTU 1.5T 参数线上 A/B +12.4%；漏斗派：生成式自回归解码延迟难压进精排 P99（几十毫秒）、长序列受 SLO 严格限制，可解释性/可控性/多目标融合都更弱，目前多是部分流量替换且常需级联/缓存兜底，全量颠覆未到（2025–2026，未定论，主流仍是漏斗为主、生成式逐场景渗透）
- 特征/样本 scaling vs 模型 scaling：特征派：推荐的上限长期是特征工程和样本质量决定的，加交叉特征、加终身行为序列、修样本偏差的收益最实、最稳，堆模型容量边际递减；模型派：Meta HSTU/Kuaishou 证明把推荐当生成式序列建模后，模型质量随训练算力呈幂律（scaling law），推荐也有自己的 scaling law、该往大模型走，特征工程的人工红利会被模型吃掉（2024–2026，HSTU（arXiv 2402.17152）点燃，两条路线在工业界并存博弈）
- 短期点击/时长 vs 多样性与生态健康：效率派：平台靠核心互动指标（点击/时长/GMV）活着，排序就该最大化它们，多样性是软约束、可量化收益不明；生态派：纯效率最大化导致信息茧房、头部通吃、新供给饿死，长期掉留存和发布者生态，得用 MMR/DPP、冷启扶持、探索预算主动牺牲单点指标换长期健康（长期争论，2024 后随监管与内容生态压力，大厂普遍把多样性/生态指标纳入考核但权重各家不一）
**前沿**：生成式推荐重写链路：semantic ID+生成式检索把召回/粗排/精排往一个端到端模型收（Kuaishou OneRec 2025 上约 25% QPS、Meta HSTU 2024 证明推荐的 scaling law）；终身行为序列成标配，从 SIM/ETA 的万级压到 TWIN-V2 的十万级+（2024）；LLM 进推荐——做语义理解/冷启 side-info/可解释/对话式推荐（LLM4Rec），但延迟与成本仍卡在工业落地门口；评估与线上一致性诊断从辅助变主线，大模型推荐对算力利用率（MFU）和训练-serving 一致性提出新工程要求（2024–2026）。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：报『我们离线 AUC 0.82、提了 2 个点』当成绩，默认离线涨线上就涨｜强：主动区分 global AUC 与 GAUC、讲清自己看的是哪个，坚持离线正向也要小流量 A/B 才算数，能说出离线涨线上没涨的几种典型原因（特征穿越/分布漂移/校准坏了）
- 套模板 vs 看情境｜弱：不管什么场景都套『双塔召回+DIN 精排+MMoE 多目标』一把梭，把 multi-task 当默认银弹｜强：先问场景：广告还是内容（要不要 pCTR 校准）、即时反馈还是延迟转化（样本怎么构造）、有没有强生态约束（要不要重排多样性），再反推用什么结构和目标
- 需提示 vs 自驱｜弱：不追问就只讲模型结构，不主动提样本怎么造、特征会不会穿越、线上线下怎么对齐｜强：不用问就把样本构造、防穿越、负采样、延迟反馈处理、线上线下一致性诊断当方案默认组成部分讲出来
- 被动 vs 主动｜弱：等更大模型/更多特征解决问题，效果不好归因『数据不够好』『等下个模型』｜强：在现有数据和算力下，通过修样本偏差、补在线打点、调融合权重、加探索把线上指标做上去，把可控的旋钮一个个拧
- 影响自己 vs 影响系统｜弱：只交付一个离线指标更好的模型，口头说『模型调好了』，不管上线后掉点谁来查｜强：留下可复用的样本管线、线上线下对齐的诊断流程、A/B 与回滚判据、多目标融合的可解释权重，让团队能在同一套评估上持续迭代不踩老坑
**失分**：报离线 AUC 当业务成绩、说不清离线涨线上为什么会跌；分不清 global AUC 和 GAUC、用错评估指标；样本构造讲不清，意识不到特征穿越/样本选择偏差/延迟反馈；把『多目标多任务』当万能，说不清负迁移和融合权重怎么定；广告场景不提 pCTR 校准、把排序问题和计费问题混为一谈；通篇不提线上 A/B，拿离线和 demo 体感下结论；只谈精排模型，对召回/粗排/重排的分工和算力预算没概念；只追单点点击、对信息茧房和生态健康完全无感。
**必考**：
- 全链路分层与算力分配 [分析]：背得出『召回-粗排-精排-重排』四个词是失分线；会判断每层的算力预算/延迟 SLO/特征取舍、能定位一个效果问题漏在哪一层是高手线
- 样本构造与三类污染 [应用]：知道『要做特征工程』是失分线；能讲清特征穿越怎么防、样本选择偏差为什么要 entire-space（ESMM）、延迟反馈怎么用 importance sampling/elapsed-time 处理是高手线
- 线上线下不一致排查 [评价]：只会说『线上线下会有 gap』是失分线；能给出逐项排查法（同批样本线上离线打分比对、查特征 skew/数据时效/打点缺失）、并知道线上 A/B 才是裁判是高手线
- 多目标融合与权重设计 [创造]：会列 MMoE/PLE 名词是失分线；能解释负迁移为什么要分共享/独有参数、融合公式的权重怎么对应业务取舍、改权重大盘怎么动是高手线
- 评估指标的选择 [理解]：只知道 AUC 是失分线；能讲清 GAUC 为什么比 global AUC 更贴用户体验、广告为什么要校准而内容可只要序、离线指标和北极星之间隔几层是高手线
**黑话**：召回／粗排／精排／重排、双塔模型、向量检索ANN、DIN/DIEN、MMoE/PLE、ESMM、entire-space、样本选择偏差、特征穿越、延迟反馈、importance sampling、终身行为序列、GSU/ESU(SIM/TWIN)、GAUC、pCTR校准、MMR/DPP、负采样、生成式推荐、semantic ID、scaling law、bandit/EE探索、信息茧房、线上线下一致性
**高频题**：讲一下推荐全链路、每层在干嘛算力怎么分／离线 AUC 涨了线上 CTR 没涨怎么查／多目标(点击/时长/转化)怎么融成一个序、权重怎么定／样本怎么构造、怎么防特征穿越和样本偏差／新物料/新用户冷启动怎么做／召回为什么用双塔、能不能上更复杂的模型／怎么看信息茧房、多样性和短期点击怎么权衡
**追问链**：「离线 AUC 涨了线上 CTR 没涨，你怎么查」→ ①[通用] 先确认是不是真没涨：看的是 global AUC 还是 GAUC、线上 A/B 的样本量和显著性够不够、有没有看错指标？②[职能] 是不是离线评估本身有问题：测试集分布和线上一致吗、有没有特征穿越导致离线虚高、训练数据是不是几个月前的过期了？③[岗位] 拿同一批线上曝光样本用线上和离线各打一遍分逐条比对，gap 在哪一层、是特征 skew(在线打点缺失/口径不一致)还是融合公式/校准的问题，定位到具体特征或环节再修？
**定级**：初级筛『懂全链路分层、会用主流模型(双塔/DIN/MMoE)做出一个能跑的排序模型、能讲清评估指标和样本构造的存在』；资深筛『扛得住线上业务指标、能从样本-特征-模型-融合-线上一致性全链路定位问题、设计得了多目标融合与冷启/探索策略、判断得出离线涨线上不涨的根因、知道什么时候该牺牲单点指标换生态健康、对生成式推荐这类前沿能讲清落地的收益与卡点』
**来源**：YouTube 两阶段+观看时长排序：Covington, Adams, Sargin, "Deep Neural Networks for YouTube Recommendations", RecSys 2016（候选生成+排序，加权逻辑回归预估 expected watch time）；OneRec 端到端生成式：Kuaishou, "OneRec Technical Report", arXiv 2506.13695, 2025（约 25% QPS、快手/极速版 App 停留时长 +0.54%/+1.24%、7 日 Lifetime 正向、运营成本约传统方案 10.6%、训练/推理 MFU 23.7%/28.8%）；HSTU 生成式推荐 scaling law：Zhai 等, "Actions Speak Louder than Words: Trillion-Parameter Sequential Transducers for Generative Recommendations", arXiv 2402.17152, 2024（1.5T 参数、线上 A/B +12.4%、质量随算力幂律）；TWIN-V2 终身序列：Kuaishou, arXiv 2407.16357, CIKM 2024（层级聚类压缩 life-cycle 行为，10^5+ 量级）；SIM 终身序列+GSU/ESU：Pi 等, "Search-based User Interest Modeling…", arXiv 2006.05639, CIKM 2020（Alibaba 广告自 2019 部署、序列长至 ~5.4 万、CTR +7.1%/RPM +4.4%）；ESMM entire-space 治样本选择偏差：Ma 等, "Entire Space Multi-Task Model", arXiv 1804.07931, SIGIR 2018（Taobao）；GAUC（按用户分组加权、与线上更一致）：Zhou 等, "Deep Interest Network for CTR Prediction"（DIN）, KDD 2018, Alibaba；线上线下一致性诊断：DoorDash Eng Blog, "How to investigate the online vs offline performance for DNN models", 2024（online-offline AUC gap 4.3%→0.76%）。

## 搜索算法工程师 · Search / IR Engineer
> 做查询理解、召回、排序,让用户带着一个明确 query 一次搜到想要的、对相关性负责的人(区别于推荐:搜索有显式 query,意图更强、容错更低)。核心矛盾:相关性是给用户的、却没有唯一真值——同一个 query 不同人想要的不一样,你只能靠分层评测把"好"近似出来,再在离线 NDCG 涨、线上点击/转化未必涨的缝里反复对账。
**核心工作职能**：
- 查询理解链路:把原始 query 拆成分词/纠错/同义改写/意图分类/实体识别,产出=结构化 query 与改写候选,而非只把字符串丢给检索;难点是短 query 歧义消解与长尾纠错
- 召回设计与融合:搭倒排(BM25)+向量(ANN/HNSW)双路召回,用 RRF/加权在 rank 层融合,产出=召回集+融合策略+召回率(recall@k)看板,保证想要的文档进了候选池
- 相关性排序:做多阶段排序(粗排→精排 LTR/LambdaMART→cross-encoder 重排),产出=排序模型、特征体系、线上序;对头部体验和尾部坏 case 同时负责
- 搭评测体系并做 bad case 归因:产出=带相关性标注的评测集、NDCG/MRR 离线指标、线上 interleaving/A-B 与人工 side-by-side,以及一套把坏 case 归到召回漏了/排序错了/query 理解偏了哪一层的流程
- 平衡相关性与业务约束:把相关性、点击/转化、商业化置顶、时效/多样性翻译成可优化的混合目标与重排规则,产出=带护栏的排序策略(相关性不破线的前提下服务业务)
### 怎么想
**心智模型**：
- **先分召回还是排序的锅,别一上来调模型**：用户搜不到东西,老手第一刀是分层:目标文档根本没进召回集(recall 问题)、还是进了但排太后(ranking 问题)。用它你能把一个'搜不准'的模糊抱怨,拆成'先看 recall@100/recall@1000 里有没有它'——没有就去查 query 理解/召回路,有就去查排序特征和模型。新手一上来就调排序、加重排,目标文档压根没召回回来,白调。
- **关键词和向量是互补、不是二选一**：BM25 死磕字面精确匹配(SKU、错误码、型号、人名、专有名词),向量召回抓语义近似(同义、口语化、跨语言),各自的强项是对方的盲区——纯向量会把'iPhone 15'和'iPhone 14'判得很近、把精确 ID 搜飞。用它你能默认上混合检索,用 RRF 在 rank 层融合(两路打分尺度不可比,靠位次而非分数融合),而不是争论哪个更好。把所有场景都押向量,是这两年最常见的外行病。
- **排序看的是整页序、不是单条打分**：相关性活在'用户从上往下扫'这个行为里:NDCG 给前排的正确性加权、给后排打折,前 3 条错一个的代价远大于第 20 条。用它你能在'平均相关性'之外盯头部精度(P@1/P@3)和坏 case 进没进前排,而不是报一个全局准确率就交差。只优化平均、不看位置权重,是把搜索当分类做。
- **query 越短越要靠先验,长尾纠错靠行为**：短 query('苹果')歧义最大、字面信息最少,真正能消歧的是用户先验和上下文(类目分布、历史、地域);长尾错拼('faceboook')词典覆盖不到,得靠点击/共现这类行为信号去学。用它你能判断一个 query 该走规则改写、该走意图模型、还是该让召回多路兜底,而不是给所有 query 套同一条改写链。把每个 query 都丢给一个在线 LLM 改写器,延迟和成本会先崩。
- **相关性该不该为业务让路,看错一次伤多大**：什么时候能把相关性往下压一点给商业化/转化让路:看这个场景错排一次的代价。导航类(搜品牌官网)、强意图(搜具体型号)碰不得相关性,动了就是体验事故;探索类、宽泛 query 有让步空间,可以塞多样性和业务加权。用它你能把'要不要给广告置顶'从拍脑袋变成按 query 意图分档的护栏规则,而不是一刀切让相关性服从 GMV。
- **判断自己偏没偏,只信线上分布和坏 case 抽样**：搜索工程师怎么知道自己判断偏了:不是看离线指标涨没涨(会过拟合评测集),不是看团队体感'搜得准多了'(头部好不代表尾部好),是定期抽样真实线上 query(尤其无点击 query、二次搜索 query、长尾段)做人工 side-by-side,看自己的标注/相关性标准跟用户行为有没有漂。判断偏了的信号:评测集半年没换血、拿不出无点击 query 的归因、说不清自己的标注标准在哪类 query 上会跟用户想要的不一致。
**基准线**：召回评测看 recall@k(召回率,k 常取 100/1000,目标文档进候选池的比例),排序评测看 NDCG@10 与 MRR(也常看 P@k、MAP)。BM25 vs 向量的相对强弱随时间在变:在 BEIR 这类零样本/跨域评测上,BM25 在 2021 年是出了名的难打基线,但到 2024–2026 稠密召回在 BEIR 多数数据集上已稳定领先 BM25 约 15–25%,BM25 的剩余优势集中在精确匹配(ID/型号/专名)、跨域泛化、零训练冷启动和可解释上;混合检索相比单路通常还能再拿个位数百分点,是当前生产标配(BEIR 论文 2021 + 2024–2026 复测,口径随领域差异大)。多阶段排序里 cross-encoder 重排成本高、只对粗排后的 top-N(常 50–200 条)做:开源 BGE-reranker 在 GPU 上约数十到百毫秒量级、商用 Cohere/Voyage rerank API 约 600ms 量级(2024–2026 各家公开基准,随并发、文本长度、是否走 GPU 差异很大);交互式搜索召回+排序整体延迟一般压在百毫秒量级。评测集相关性标注核心 query 起步几百到上千 query×每 query 若干文档是常见经验值,够不够取决于能否覆盖长尾与歧义 query。生成式搜索冲击:在触发 AI Overviews 的 query 上,这类 query 的零点击率约 83%(Similarweb 2025);触发 AIO 的 query 自然结果 CTR 下滑约 61%、首位结果降幅更大(Seer Interactive 2025;口径随研究差异大)。multi-vector(ColBERT)原始索引按 token 数膨胀、可达单向量的几个数量级,但 ColBERTv2 残差压缩(约 6–10×)能把体积拉回到接近单向量量级(ColBERTv2 论文 2021 + 2024–2026 工程实践)。
**战例**：Que2Search(Facebook 商品搜索查询理解,KDD 2021 / arXiv 2108.02374):用 XLM-R 多任务多模态把 query 与商品对齐,离线相关性 +5% 以上、线上互动 +4% 以上,且把模型压到 CPU 上 <1.5ms@P99——教『召回质量与线上延迟要同时扛、query 理解是大厂搜索的胜负手而不是后处理』／Airbnb 搜索排序(Ronny Kohavi 公开复盘):约 250 个搜索排序实验里只有约 20 个真正推动了核心指标,这些小改动累计带来约 6% 的预订/营收提升(价值上亿美元)——教『搜索是靠海量 A-B 实验微调出来的、绝大多数 idea 不动指标、相关性最终要落到一个能验证的业务北极星(bookings-per-user)上,不是离线 NDCG 一把梭』。
**悬案**：
- 关键词 vs 向量语义召回(及混合)：向量派:语义召回解决同义/口语/跨语言/长尾,稠密召回在 BEIR 等基准上已普遍领先 BM25,embedding 够强、向量+ANN 能覆盖大部分意图,字面匹配是补位项；关键词派:BM25 在精确匹配(ID/型号/错误码/专有名词)、可解释、零训练冷启动、跨域泛化上仍稳,向量会把近义实体判得过近、还有索引成本和分布漂移（2025–2026 共识收敛到混合检索+RRF 融合(rank 层融合绕开打分不可比),但两路权重、何时偏关键词何时偏向量随场景无定论(2026)）
- LLM 改写/生成式搜索是否取代传统召回排序：取代派:LLM query 改写+RAG+生成式答案(AI Overviews)直接给答案,触发 AIO 的 query 零点击大涨,传统'十条蓝链+排序'范式在被生成式重写；保留派:生成式底下仍要召回+排序+重排把对的文档喂给模型(检索质量决定生成质量),LLM 改写有延迟/成本/幻觉、长尾与精确意图还得靠传统链路,且长上下文有 Lost in the Middle(Liu et al. 2023)等检索缺陷（2024–2026 偏'生成式在前端改变交互、传统 IR 在底层做 retrieval 骨架',边界与分工未定(2026)）
- 相关性 vs 广告/商业化置顶：相关性优先派:动相关性给商业化让路会慢性损伤信任和长期留存,导航/强意图 query 尤其碰不得；业务优先派:搜索是核心变现入口,合理的商业化置顶与转化加权能在相关性可接受区间内显著提收入,纯相关性不等于用户最终满意（业界长期张力,2025 主流做法=按 query 意图分档设相关性护栏、强意图不让步、探索类可加业务权重(2026)）
**前沿**：LLM 在重写这岗:query 理解端用 LLM 做改写/扩展/意图理解(尤其会话式、长尾、跨语言),但要解决延迟成本与幻觉、多走离线预计算或蒸馏成小模型上线;召回端 embedding 与混合检索成标配、late-interaction(ColBERT 类)在质量与索引成本间找平衡;排序端 LLM-as-reranker 与 cross-encoder 并存(cross-encoder 更省更稳);最大变量是生成式搜索(RAG/AI Overviews)把'搜索'从给链接变成给答案,相关性工程的下游从'用户点击'变成'喂给生成模型的上下文质量',评测也随之从点击指标向'引用是否正确/答案是否被支撑'扩展(2025–2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：用户搜不到就说'加点召回''调下排序权重',报一个'准确率/相关性 90%'当成绩｜强：先分召回还是排序的锅(查 recall@k 里目标文档在不在),把坏 case 归到 query 理解/召回/排序/融合哪一层,讲清头部精度和长尾分布、不只报平均
- 套模板 vs 看情境｜弱：不管什么 query 都上同一套(全押向量召回、或所有 query 都 LLM 改写),把混合检索当万能｜强：先看 query 意图(导航/强意图/探索)和错排代价,再决定关键词偏重还是语义偏重、要不要 LLM 改写、相关性能不能给业务让步
- 需提示 vs 自驱｜弱：不追问就只讲'用了 BM25+向量+重排',不主动谈评测集怎么标、离线线上差距、bad case 怎么归因｜强：不用问就把评测体系(NDCG+线上 interleaving+人工 side-by-side)、离线线上一致性、长尾/无点击 query 监控、相关性护栏当方案默认部分
- 被动 vs 主动｜弱：等更强的 embedding/更大的模型解决相关性,'换个更好的向量模型就行了'｜强：在现有模型下用 query 理解+多路召回+特征工程+重排+护栏规则把相关性做到能上线,把离线-线上缝、长尾、歧义当能动的旋钮去拧
- 影响自己 vs 影响系统｜弱：只调出一个离线 NDCG 更高的排序模型,口头说'相关性优化好了'｜强：留下可复用的分层评测集、bad case 归因流程、相关性护栏与 A-B 实验框架,让召回/排序/query 理解和业务在同一套评测与北极星上协作迭代
**失分**：报一个全局'相关性/准确率 90%'当成绩、不分召回与排序、不讲头部精度和长尾;只看离线 NDCG、没有线上 A-B/interleaving 和人工 side-by-side,被线下涨线上跌打脸;把所有场景都押纯向量召回、说不清向量在精确匹配上会飞;通篇不提评测集怎么标、怎么换血、标注标准会不会跟用户意图漂;把相关性一刀切服从 GMV、不按 query 意图分护栏档;把 LLM 改写当万能解法堆、不算延迟成本幻觉、说不清何时不该用
**必考**：
- 从 0 设计搜索评测体系并做 bad case 归因 [创造]:背得出'要做带标注的评测集、看 NDCG'是失分线;会分召回(recall@k)与排序(NDCG/MRR)两层指标、配线上 interleaving/A-B 与人工 side-by-side、把坏 case 归到 query 理解/召回/排序/融合哪一层、并讲清离线线上差距怎么对账才是高手线
- 召回与排序分层定位 + 多阶段架构 [分析]:只会说'用了召回和排序'是失分线;能先用 recall@100 判断目标文档进没进候选池来分召回还是排序的锅、讲清粗排→精排 LTR→cross-encoder 重排各阶段为什么这么切(成本与质量)是高手线
- 关键词 vs 向量召回的取舍与混合 [评价]:只会背'向量做语义、BM25 做字面'是失分线;能讲出纯向量在精确匹配(ID/型号)上为什么飞、RRF 为什么在 rank 层融合(打分不可比)、按 query 类型怎么调两路权重是高手线
- 相关性排序方法演进(BM25→LTR→语义/重排) [理解]:只会报模型名是失分线;能讲清 LambdaMART 的特征怎么搭、cross-encoder 为什么只对 top-N 重排、ColBERT 的质量与索引成本权衡是高手线
- 相关性 vs 商业化/业务约束的平衡 [应用]:只说'听产品的'或'相关性最重要'是失分线;能按 query 意图分档设相关性护栏(导航/强意图不让步、探索类可加业务权重)、用混合目标和 A-B 验证长期影响是高手线
**黑话**：倒排索引、BM25、TF-IDF、向量召回、ANN/HNSW、recall@k、NDCG、MRR、MAP、P@k、LTR、LambdaMART、pointwise/pairwise/listwise、cross-encoder、bi-encoder、重排(rerank)、RRF、混合检索、ColBERT/late interaction、query 改写/扩展、意图分类、纠错(spell correction)、同义改写、interleaving、side-by-side、judgment、relevance label、bad case 归因、零点击、生成式搜索/RAG
**高频题**：从 0 设计一套搜索相关性评测体系/用户反馈搜不准你怎么定位是召回还是排序的问题/什么场景用关键词召回、什么用向量、怎么融合/离线 NDCG 涨了线上点击没涨甚至跌怎么查/相关性和商业化置顶冲突时你怎么权衡/BM25→LTR→语义排序怎么一步步演进、各自解决什么/短 query 和长尾 query 怎么做 query 理解
**追问链**：「从 0 设计搜索相关性评测体系」→ ①[通用] 离线和线上指标各看什么、为什么不能只看离线?②[职能] 评测集怎么标、标注标准怎么定、过拟合/分布漂了怎么发现和换血?③[岗位] 离线 NDCG 涨但线上点击跌,你怎么定位是标注标准跟用户意图有偏、还是召回漏了、还是排序过拟合,怎么补?(再深:长尾和无点击 query 你怎么纳入评测、怎么校准人工标注跟真实用户行为的不一致)
**定级**：初级筛'懂倒排/BM25/向量召回基本原理、会用现成框架搭一条召回+排序链路、知道 NDCG 怎么算、能讲清评测和 bad case 的存在';资深筛'扛得住召回×排序×业务约束的三方账、能从 0 定义分层评测与 bad case 归因体系、判得清关键词 vs 向量 vs 混合在什么场景怎么选、把得住相关性与商业化的护栏、知道离线线上的缝在哪以及怎么对账、知道什么时候不该上 LLM 改写/不该押纯向量'

## NLP 算法工程师 · NLP Engineer
> 把文本变成业务能用的结构化结果的人——分类、抽取、检索、问答这些任务,在现成大模型和自训小模型之间选路、做评测、控成本,落到能上线。这岗每天在划的那条线:同一个文本任务,大模型 prompt 几小时跑通但贵、慢、不可控,微调小模型便宜快可控但要标数据要养评测,什么时候走哪条、什么时候从大模型蒸馏回小模型,是反复做的判断而非一次性技术选型。
**核心工作职能**：
- 选型与切线:同一文本任务在 zero-shot LLM / few-shot / 微调小模型 / 规则混合之间做技术路线决策,产出=带成本-延迟-质量三档对比的选型结论与切换条件(什么时候从 LLM 蒸馏到小模型),不默认上大模型也不默认训小模型
- 搭文本表示与匹配/检索链路:产出=embedding 选型(召回用双塔、精排用交叉编码器)、向量库+BM25 混合召回、reranker 精排的两段式管线,带召回率@k 与端到端延迟的量化指标
- 做信息抽取与意图识别落地:把抽实体/抽关系/判意图做成可上线的服务,产出=schema 约束的结构化输出(JSON)、置信度阈值分档、抽不准/抽空时的兜底,不只交一个离线 F1 高的模型
- 建评测集与坏例闭环:产出=分层标注集(核心+长尾坏例+holdout)、回归不劣化的 CI 门、一套把 badcase 从召回/表示/抽取/阈值哪一环归因的流程,以及线上分布漂移监控
- 控标注成本:产出=用 LLM 弱标注+人工校验+主动学习挑难例的标注方案与冷启动路径,而不是开口就要标几万条
### 怎么想
**心智模型**：
- **先看任务形态和错误成本,再谈用什么模型**：老手接一个文本需求,第一件事是问:这是分类/抽取/检索/生成里的哪类?标签空间多大、长尾多严重?错一条的代价多大、错了谁兜?用它你能在五分钟内排除掉一半技术方案——十个固定意图分类不该上大模型,开放域抽未知实体类型才轮到 LLM 或 GLiNER 这类零样本路子。一上来就纠结 GPT 还是开源模型、prompt 怎么调,是把最后一步当起点。
- **召回与精排是两个阶段、用两种模型**：双塔(bi-encoder)把 query 和文档各自编码成向量、毫秒级召回但精度一般;交叉编码器(cross-encoder)把 query-文档拼一起算,精度高但慢、只能给召回出的几十条精排。用它你能把检索/匹配链路拆对:双塔召回 N=50-100,reranker 精排到 top-k。把双塔当精排用、或召回只取 top-5 再精排,是这岗最常见的链路设计错。
- **离线 F1 高不等于线上能用,要看阈值后的分布和长尾**：一个 macro-F1 0.9 的意图模型,真正决定能不能上线的是:卡多高置信度阈值能 auto、中间带怎么转人工、低置信怎么兜底,以及长尾意图和 OOD(域外)输入上崩不崩。用它你能把模型指标翻译成产品判据——报『准确率 95%』是失分线,会按错误成本设三档阈值(高置信自动/中间带澄清或转人工/低置信兜底,行业常起步 0.85-0.95 再按每类调)才是上线思维。
- **标注成本是可设计的,不是开口要几万条**：冷启动别一上来标大批。用它你能把标注成本压下来:LLM 先做弱标注铺量(Wang 2021 实测达同等下游效果用 GPT-3 标比纯人工省 50-96% 成本、但噪声更大)、人工只校验和挑歧义难例(主动学习)、再把这批数据蒸馏进小模型上线。手册外的实操是知道哪些类必须人工金标(高风险、判官靠它对齐)、哪些可以 LLM 标了直接用。
- **该上规则/小模型时就别硬上大模型**：不是所有文本任务都该交给 LLM。固定格式抽取、闭集分类、对延迟成本敏感的高 QPS 场景,微调小模型(甚至 DistilBERT/GLiNER 这类几百 M 的)往往更准更快更可控——有论文实测微调小模型在文本分类上仍稳定胜过 zero-shot 大模型(arXiv 2406.08660,2024)。用它你能在『跟得上潮流』和『做得出能上线的东西』之间不犯轴,知道什么时候反过来从大模型蒸馏回小模型。
- **怎么知道自己的判断偏了:盯线上分布漂移和真实坏例,不信离线指标也不信体感**：NLP 工程师最容易自欺的地方:评测集刷到很高就以为搞定了。校准的办法是把评测当活资产养——定期看线上输入分布有没有偏离评测分布(漂移)、定期换血坏例、留一份模型没见过的 holdout、用 LLM 当判官时按月拿人工金标对齐一次(专家类任务 LLM 与人一致率会掉到 64-68%,见 arXiv 2410.20266/IUI 2025)。判断偏了的信号:只敢拿离线 F1 说话、拿不出 holdout、说不清自己评测集会被什么污染、判官多久没跟人对齐过。
**基准线**：embedding 选型看 MTEB 这类公开榜(覆盖分类/聚类/成对分类/重排/检索/语义相似/摘要/双语挖掘八类任务,MTEB v2 2026 起分数与 v1 不可直接比),但榜分只是起点、垂类要自测;两段式检索常见配置=双塔召回 N=50-100、交叉编码器精排到 top-k,reranker 至少喂 30-50 条候选才有意义(取 top-5 再精排基本是白排),交叉编码器逐条候选过一次前向、延迟随候选数近似线性增(行业经验约每条数毫秒、随模型/硬件差异大,几十条候选常加百毫秒级);意图/抽取 F1 健康区间随任务差异极大、闭集意图常能到 0.9+ 而开放域抽取低得多,真正的上线判据是阈值后的 auto 率与转人工率;置信度三档阈值高位常起步 0.85-0.95、按每类的转移成本单独调(团队经验,无统一值);LLM 弱标注相对纯人工省约 50-96% 成本但更噪(Wang 2021);蒸馏后小模型推理常快数倍(行业经验,看架构与硬件)。精确数字都随场景大幅波动,别背死。
**战例**：GLiNER(NAACL 2024,arXiv 2311.08526)与后续 GLiNER2(EMNLP 2025 Demo,arXiv 2507.18546,约 0.3B):一个几百 M 的双向编码器零样本信息抽取模型,原 GLiNER 在 20 个 NER 基准中 13 个取得最佳、零样本平均胜过 ChatGPT 和微调大模型约 2 个点、且并行抽取比 LLM 逐 token 生成快得多——教『不是什么文本任务都该交给大模型,选对架构的小模型在抽取上又快又准又便宜』;／ 用 GPT 系做数据标注的成本研究(Wang et al. 2021《Want To Reduce Labeling Cost? GPT-3 Can Help》,EMNLP Findings):要让下游模型达到同等效果,用 GPT-3 弱标注比纯人工省 50-96% 成本、但数据更噪,团队随后把这些标签蒸馏进小模型上线——教『标注成本是可设计的:LLM 铺量+人工校验难例+蒸馏落地,而非开口要几万条人工标』。
**悬案**：
- 大模型 prompt vs 微调专用小模型,谁做文本任务更对：prompt 派:zero/few-shot LLM 几小时跑通、不用标数据、改需求只改 prompt,长尾和开放类任务上泛化好,迭代快；微调派:固定任务上微调小模型(乃至 DistilBERT/GLiNER 量级)往往更准更快更可控、单位成本低一两个数量级,有论文实测分类任务上仍稳胜 zero-shot 大模型(arXiv 2406.08660),且不依赖外部 API（2024-2026 未收敛,实务上按任务形态/QPS/成本分流,常见落法是 LLM 起步跑通再蒸馏到小模型上线）
- 长上下文塞进去 vs RAG 检索增强 vs 微调进权重：长上下文派:窗口够大,相关文档直接全塞进 prompt,省掉检索链路的工程复杂度和召回漏检；RAG 派:长上下文有 lost-in-the-middle(信息埋在中间召回率显著下降、呈 U 形曲线,Liu et al. Stanford 等 2023 起、各模型族复现到 2025)和成本随长度近似线性涨,且单针测试可能高估真实多针场景;微调派则主张稳定知识该进权重（2025-2026 偏混合,长文档场景仍以 RAG+精排为主,切换边界无定论）
- 评测用 LLM 当判官 vs 人工标注：LLM-judge 派:人工标注慢且贵,LLM 判官能规模化、对齐平均人类评分尚可,加少样本和校准能再拉高一致性；人工派:LLM 判官在专家/垂类任务上与人一致率掉到 64-68%(arXiv 2410.20266,IUI 2025);类别不平衡时还有过度接受倾向(TPR 高、TNR 低)虚高可靠性(『Beyond Consensus』arXiv 2510.11822,2025)、并会自己漂（2025-2026 共识=LLM-judge 可用但必须定期拿人工金标校准、分歧高即触发重标,纯靠它或纯靠人都不够）
**前沿**：LLM 把这岗的活分成两头:一头是用 zero/few-shot 大模型快速跑通新任务、做弱标注铺数据,另一头是把验证过的能力蒸馏进小模型上线控成本——『LLM 探路+小模型量产』成为 2024-2026 主流落法。零样本抽取(GLiNER/GLiNER2)与 schema 约束的结构化输出(JSON mode / 工具调用)正在吃掉一部分传统 NER/正则的活;评测从辅助环节升为研发主线(eval-driven),LLM-as-judge 配人工校准成为标配;embedding 与 reranker 持续刷新公开榜(MTEB v2 2026),多模态统一向量空间开始出现。这岗的稀缺度从『会调模型』迁到『会选型切线+会建评测坏例闭环+会算成本延迟账』。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：报『我们模型 F1 0.92』当成绩,只说一个总体数字,讲不清在哪类样本上崩、坏例长什么样｜强：主动拆 macro vs micro、讲长尾类和 OOD 上的表现、把 badcase 归到召回/表示/抽取/阈值哪一环,知道线上分布偏了离线 F1 就全失效
- 套模板 vs 看情境｜弱：不管什么文本任务都先想用哪个大模型、prompt 怎么写,或反过来什么都要微调,把 RAG/大模型当万能解｜强：先判任务形态(分类/抽取/检索/生成)和错误成本→再定 zero-shot/few-shot/微调/规则混合→才谈具体模型,固定闭集任务敢说『这个不该上 LLM』
- 需提示 vs 自驱｜弱：不追问就只交一个离线指标高的模型,不主动谈评测集怎么建、上线后怎么监控、抽不准怎么兜底｜强：不用问就把评测分层、holdout、线上漂移监控、置信度阈值分档、兜底方案当方案的默认组成部分
- 被动 vs 主动｜弱：等更强的模型或更大的标注预算来解决问题,『再等下一代模型』『数据不够标不出来』｜强：在当前模型和有限标注下用弱标注+主动学习+蒸馏+阈值兜底把任务做到能上线,把标注成本和可靠性当能动的旋钮
- 影响自己 vs 影响系统｜弱：只交付一个能跑的模型文件,口头说『调好了』,换个人接手不知道评测集在哪、坏例怎么归因｜强：留下可复用的分层评测集、召回/抽取的归因流程、阈值与上线判据、标注规范,让团队在同一套评测上迭代
**失分**：报单个总体 F1/准确率当成绩、不讲长尾和 OOD、不讲坏例分布;没有 holdout、靠离线指标或体感判断好坏,说不清评测集会被什么污染或漂移;把双塔当精排用、reranker 只喂几条候选、不分召回与精排两阶段;什么文本任务都默认上大模型(或反过来什么都微调),固定闭集任务也不敢说『这不该上 LLM』;通篇不提一次成本、延迟、QPS;抽取/意图只交模型不设置信度阈值分档和抽空兜底;LLM 当判官配好就不管、从不拿人工金标校准;冷启动开口就要标几万条、不知道 LLM 弱标注+主动学习能省成本。
**必考**：
- 给一个文本任务选技术路线(zero-shot/few-shot/微调/规则混合)并说清切换条件——背得出『大模型泛化好小模型便宜』是失分线;会按任务形态+错误成本+QPS+标注预算做分流、能讲清什么时候从 LLM 蒸馏到小模型,是高手线 [评价]
- 从 0 设计文本任务的评测集与坏例闭环——只会说『要做测试集』是失分线;会判断指标分几层(macro/micro/分类目)、守门线谁拍、坏例怎么归因到召回/表示/抽取/阈值、怎么发现污染漂移、留 holdout,是高手线 [创造]
- 设计召回+精排两段式检索/匹配链路——只会说『用 embedding 算相似度』是失分线;能讲双塔召回 N 条+交叉编码器精排 top-k、混合 BM25、reranker 候选数和延迟的取舍,是高手线 [应用]
- 信息抽取/意图识别的可靠性设计——只交一个 F1 高的模型是失分线;能按置信度分档(自动/转人工/兜底)、schema 约束输出、抽空和抽错怎么处理、长尾类怎么办,是高手线 [分析]
- 标注成本控制与冷启动——开口要标几万条是失分线;会用 LLM 弱标注铺量+人工校验难例(主动学习)+蒸馏落地、知道哪些类必须人工金标,是高手线 [理解]
**黑话**：双塔/bi-encoder、交叉编码器/cross-encoder、reranker 精排、召回率@k、BM25、混合检索、MTEB、向量库、zero-shot/few-shot、PEFT/LoRA 微调、知识蒸馏、GLiNER、schema 约束输出/JSON mode、NER/实体抽取、关系抽取、意图识别、置信度阈值、OOD 域外、长尾、macro-F1、lost in the middle、context rot、LLM-as-judge、弱监督/弱标注、主动学习、holdout、分布漂移、eval-driven
**高频题**：给你一个意图分类/实体抽取需求,你怎么选技术路线、为什么/embedding 怎么选、双塔和交叉编码器分别用在哪/离线 F1 很高但线上被业务投诉准确率差,你怎么查/标注预算只够标几百条,这个任务怎么冷启动/抽取服务抽不准或抽空了怎么兜底/什么任务该上大模型、什么该微调小模型/检索召回不全怎么优化
**追问链**：「从 0 给一个意图识别任务设计评测和上线方案」→ ①[通用] 评测集怎么分层、什么指标守门、守门线谁拍板?→ ②[职能/算法] 离线 F1 高但线上分布漂了你怎么发现、怎么补、评测集被过拟合或污染怎么换血、holdout 怎么留?→ ③[NLP 深层] 长尾意图和 OOD 输入上模型不可靠,你怎么设置信度阈值分档兜底、低资源的长尾类怎么用弱标注+主动学习补数据、如果用 LLM 当判官评这套你怎么校准它多久重标?
**定级**：初级筛『会用现成模型/微调把一个文本任务(分类/抽取/检索)做出来,能讲清评测和坏例的存在、跑得通召回+精排』;资深筛『扛得住选型×成本×延迟×标注的多方账,能从 0 在 zero-shot/微调/规则间定路线并讲清切换条件、从 0 建分层评测与坏例归因闭环、设计可靠性兜底与置信度分档、用弱标注+主动学习+蒸馏控成本,且知道什么任务不该上大模型』。
**来源**：GLiNER: Generalist Model for NER using Bidirectional Transformer(NAACL 2024,arXiv 2311.08526)——零样本在 20 个 NER 基准中 13 个最佳、平均胜过 ChatGPT 与微调大模型约 2 点;GLiNER2: Schema-Driven Multi-Task Learning for Structured Information Extraction(EMNLP 2025 System Demo,arXiv 2507.18546,约 0.3B,统一 NER/分类/结构化抽取/关系抽取);Fine-Tuned 'Small' LLMs (Still) Significantly Outperform Zero-Shot Generative AI Models in Text Classification(Bucher & Martini,arXiv 2406.08660,2024);Wang et al. 《Want To Reduce Labeling Cost? ## 语音算法工程师 · Speech Engineer
> 让机器在真实声学环境里听懂人话、说出人声的人:做 ASR/TTS/唤醒/声纹算法,对实验室刷不出来的那部分鲁棒性负责。核心矛盾:实验室 WER 早刷到 2% 以下、真实场景却还在两位数,指标进步的边际收益越来越小,钱、口碑、合规风险全压在噪声/口音/远场/打断这些训练集喂不饱的长尾分布上。
**核心工作职能**：
- 搭/调声学与语言建模:把 ASR 或 TTS 的端到端架构(Conformer-Transducer/AED、神经 codec LM/flow-matching)落到目标场景,产出=可上线的模型 + 离线/在线两套指标(WER、CER、RTF、首包延迟、MOS/相似度)
- 治真实场景鲁棒性:对噪声/远场/口音/多说话人/打断这些分布外样本做数据增广、域适配、前端增强,产出=分场景 WER 矩阵(安静/嘈杂/远场/口音各一档),不是一个平均数交差
- 做流式与延迟的工程权衡:在 chunk 大小/lookahead/endpointing 之间定档,产出=延迟预算分解(首字延迟、尾点延迟)+ 对应 WER 退化曲线,卡死端上算力/内存
- 建数据采集与标注合规管线:定义采集场景配比、标注规范、转写质检、隐私脱敏与授权链路,产出=可追溯来源的数据集 + 标注一致性指标(IAA),voice clone 还要授权与水印
- 对下游兜底负责:把识别错误/合成异常翻译成下游能接的置信度信号与降级策略,产出=按错误成本分档的兜底方案(置信度门限、N-best、重听确认、拒识),交的不止一个 WER 数字
### 怎么想
**心智模型**：
- **先听 badcase 的声音、不先看 WER 数字**：老手拿到一个识别错误,第一反应是把那段音频调出来听:是底噪、混响、口音、口语化吞音、还是切词/endpointing 切早了。用它你能在 10 个真实 badcase 里定位到错误集中在前端(信噪比)还是后端(语言模型/解码),不被一个平均 WER 糊住——平均数把安静场景的高分和远场的崩盘混成一锅。
- **前端-声学-语言-解码,错误会沿链传播**：一句识别错可能源头在很前面:VAD 切错→送进声学的就是半句;前端降噪过猛→把弱辅音也削掉;声学没见过这口音→后面语言模型再强也救不回。用它你能逆着链路定位真正的源头,避免在解码端调 LM 权重去补一个其实是前端造成的洞。
- **看尾部分布和置信度形态、不看均值**：WER 8% 不告诉你风险在哪——可能 90% 的句子近乎全对、10% 的远场/重口音句子错得离谱。老手盯的是分场景 WER、句级 WER 的分布尾巴、以及置信度和真实正确率对不对得上(校准)。用它你能判断这模型是均匀地差、还是在某类输入上系统性崩,后者才是上线事故的来源。
- **数据增广和域匹配常比换架构更值钱**：手册说换更大的 Conformer、上自监督预训练;实战里把目标场景的真实噪声、混响(RIR 卷积)、远场多通道、目标口音按真实配比掺进训练,往往比堆模型更直接降目标场景 WER。用它你能在算力不变的前提下,用数据把分布外样本拉回分布内,不靠下一代架构来救。
- **该牺牲精度保延迟、或反过来,看下游错误成本**：流式场景里 chunk 调小、lookahead 砍掉能压首字延迟,代价是 WER 升。什么时候该破‘精度优先’这条默认规则:语音助手抢话、实时字幕,用户对卡顿的容忍度低于对个别错字的容忍度,这时主动牺牲 1-2% WER 换两三百毫秒延迟是对的;医疗听写、法律转写掉过来,延迟可以让,错一个字代价高。用它你能按场景而不是按习惯定档。
- **离线指标好不等于线上好,只能靠盯线上分布和真实回流校准**：语音工程师怎么知道自己判断偏了:测试集刷得漂亮、线上被投诉,八成是测试集分布和真实流量分布不一致(测试集太干净、口音覆盖不全、麦克风型号单一)。校准的办法是建线上音频回流抽样 + 人工转写复核,定期算线上真实 WER 和测试集 WER 的 gap,gap 大就说明测试集在骗你。光看离线榜单、光听 demo、光信‘我们刷到 2%’,都是判断会偏的信号。
**基准线**：实验室 WER 已很低:LibriSpeech test-clean 上 wav2vec 2.0/Conformer 全监督约 1.8-2.0%、Whisper large 零样本约 2.7%(arXiv 2510.12827 ASR 综述,2025;另有专用纠错路线把 test-clean 推到约 1.5%)。真实场景普遍掉到 8-12% WER,强噪声/远场可恶化到约 30%(噪声鲁棒性评测,2025),随麦克风、信噪比、口音差异极大。流式首字延迟交互式产品一般压在数百毫秒量级(Moshi 实测约 200ms),随 chunk/lookahead 配置和算力差异大。TTS 自然度近年 MOS 逼近真人、zero-shot 克隆 3 秒参考音即可(VALL-E,2023 起),相似度与口音/情感保真仍是短板。以上区间为行业经验,随数据集与场景差异大,绝非固定值。
**战例**：Whisper(OpenAI,2022.12):约 68 万小时弱监督互联网音频训练,零样本就在多个标准集打平专用模型,把‘数据规模与多样性可替代精修数据集’变成行业共识——教‘大规模弱监督 + 端到端会吃掉大半精调红利,但它在噪声/专有词上照样掉到两位数,demo 跑通不等于真场景能用’的模式／Arup 深度伪造诈骗(2024.02 曝光,损失约 2 亿港币、约 2560 万美元):骗子用公开视频音频克隆 CFO 及同事的脸和声音开视频会,香港员工被骗分 15 笔转账——教‘语音克隆/声纹这类能力一旦做出来,合规与反滥用(活体检测、水印、授权链)就是产品本体的一部分,做语音的人对误用后果有连带责任’的模式。
**悬案**：
- 端到端语音大模型 vs 级联(ASR→NLU/LLM→TTS)：端到端派:Moshi、GPT-4o realtime 把听-想-说放进一个模型,延迟低、能保留语气/情感/打断等副语言信息,级联每多一段就丢一层信息加一段延迟；级联派:ASR/NLU/TTS 分开可独立调试、独立换代、错误可定位归因,文本中间层方便加业务规则/安全过滤/可审计,端到端是黑盒、出错难定位难纠偏、数据要求高（2024-2026 仍在演进,产线多为级联、对话语音往端到端探,无定论）
- 流式 vs 非流式:精度-延迟怎么权衡：流式派:真实交互(助手、实时字幕、同传)必须边说边出,RNN-T 天然流式、chunk attention 可控延迟,用户对卡顿零容忍；非流式派:整句看全上下文 WER 明显更低,离线转写、字幕后期、听写场景延迟可让、应优先精度;流式为压延迟砍 lookahead 带来的 WER 退化在长尾场景被放大（2025 倾向按场景分,CUSIDE 类‘模拟未来帧’(arXiv 2203.16758,2022)试图兼得两端）
- 统一语音大模型 vs 专用小模型：统一派:一个多任务多语种大模型(Whisper 式)零样本覆盖广、维护一套、长尾语种受益于迁移；专用派:垂直场景(车载远场、医疗术语、特定方言)精调小模型 WER 更低、RTF 更小、端上跑得动、可控可审计,通用大模型在专有词和强噪声上并不够（2025-2026 偏‘大模型打底 + 场景精调/蒸馏’混合,边界未定）
**前沿**：语音大模型与全双工对话语音在重写技术栈:Moshi(Kyutai,2024.09)、GPT-4o realtime 把 ASR/对话/TTS 端到端化,带来打断、backchannel、重叠说话的真实建模,Full-Duplex-Bench(arXiv 2503.04721,2025.03)等专门评测随之出现;TTS 从自回归神经 codec LM(VALL-E,2023)转向 flow-matching(Voicebox、Matcha-TTS)与因子化扩散(NaturalSpeech 3),3 秒参考音 zero-shot 克隆成熟。同时合规变成硬约束:EU AI Act 第 50 条要求合成音频机读水印 + 披露,核心义务 2026.08 起适用(机读标记义务有过渡期),voice clone 的授权链、活体检测、水印从加分项变准入项。自监督预训练(wav2vec 2.0/HuBERT)让小标注量出好模型,数据合规与隐私脱敏的权重反超纯刷点(2023-2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：汇报‘我们 WER 做到 5%’当成绩,一个平均数交差,被问就只说‘再调调模型’｜强：主动拆分场景 WER(安静/嘈杂/远场/口音各一档)、讲句级分布尾巴和置信度校准,把一条 badcase 逆着前端-声学-语言-解码链归因到源头那一层
- 套模板 vs 看情境｜弱：不管什么场景都先想换更大模型/上自监督预训练/堆数据,流式一律砍 lookahead 压延迟｜强：先问场景的错误成本和延迟容忍度→定可接受 WER 与首字延迟预算→才反推架构档位、chunk/lookahead 配置和数据增广方向
- 需提示 vs 自驱｜弱：不追问就只报离线指标,不主动谈线上回流、数据合规、识别错误的下游兜底｜强：不用问就把线上音频回流抽检、分场景监控、置信度门限兜底、采集标注合规当方案默认组成部分
- 被动 vs 主动｜弱：线上 badcase 多就等‘下一代模型/更多数据’解决,把鲁棒性寄托在外部｜强：在当前模型下用数据增广(真实噪声/RIR 混响/口音掺训)、前端增强、域适配、解码兜底主动把目标场景 WER 拉下来,把鲁棒性当能动的旋钮
- 影响自己 vs 影响系统｜弱：只交付一个 WER 达标的模型,口头说‘调好了’｜强：留下可复用的分场景评测集、badcase 归因流程、线上回流与校准管线、对下游的置信度契约,让数据/前端/下游团队在同一套指标上协作迭代
**失分**：只报一个平均 WER、不讲分场景和尾部分布;测试集太干净/口音单一/麦克风单型号,刷得漂亮线上被打脸,且说不清离线-线上 gap;把 TTS 只当‘合成清楚’、不提相似度/情感/克隆合规与水印;流式场景通篇不提延迟预算、或盲目砍 lookahead 不看 WER 退化;只交模型不给下游置信度/兜底信号,识别错了下游直接崩;voice clone/声纹只谈效果、对授权链与反滥用一句不提
**必考**：
- 端到端 ASR 主流架构与取舍(CTC/RNN-T/AED、Conformer)——能背出名字是失分线;会判断流式选 RNN-T/chunk attention、离线选 AED 看全上下文、以及各自 WER-延迟代价才是高手线 [分析]
- 真实场景鲁棒性怎么治(噪声/远场/口音/多说话人)——只说‘加数据’是失分线;能讲清真实噪声+RIR 混响增广、域适配、前端增强如何按目标场景配比、并用分场景 WER 矩阵验证是高手线 [创造]
- 流式延迟-精度权衡——背得出‘chunk 越小延迟越低’是失分线;会做延迟预算分解(首字/尾点延迟)、按下游错误成本定 chunk/lookahead 档、说清 endpointing 切早切晚的代价是高手线 [评价]
- 识别错误对下游的兜底与置信度——只说‘加个人工复核’是失分线;能按错误成本设计置信度门限/N-best/重听确认/拒识分档、并讲清置信度要做校准才可信是高手线 [应用]
- WER/CER/MOS 等指标的含义与局限——能定义是基础;能讲清平均 WER 掩盖尾部、测试集分布偏差让指标骗人、TTS 的 MOS/相似度/可懂度要分开看,才是理解到位 [理解]
**黑话**：WER、CER、RTF(实时率)、MOS、首字延迟/尾点延迟、Conformer、RNN-T/Transducer、AED、CTC、chunk attention、lookahead、endpointing、VAD、声学模型/语言模型、神经 codec、flow-matching、zero-shot voice cloning、声纹/说话人验证、diarization(说话人分离)、RIR(房间冲激响应)、波束成形、AEC(回声消除)、自监督预训练(wav2vec2/HuBERT)、置信度校准、全双工、N-best
**高频题**：实验室 WER 2% 线上为什么掉到两位数、怎么查怎么治／流式 ASR 延迟和精度怎么权衡、chunk 和 endpointing 怎么定／远场或带口音场景识别崩了你怎么提升鲁棒性／识别有错的时候下游怎么兜底、置信度怎么用／TTS 自然度和音色相似度怎么平衡、voice clone 怎么防滥用／端到端语音大模型和级联 pipeline 你怎么选
**追问链**：「线上 ASR 准确率不行怎么排查」→ ①[通用] 你先怎么定位是数据问题、模型问题还是工程问题?②[职能] 离线测试集刷得好但线上差,gap 出在哪、怎么建线上回流去量它?③[岗位] 假设定位到远场+口音这类长尾,前端增强、RIR/噪声增广、域适配你具体怎么配比和验证,怎么保证不把安静场景的 WER 拉回去?
**定级**：初级筛:会用主流框架(Kaldi/ESPnet/WeNet/NeMo 等)训出一个能跑的 ASR/TTS、讲得清 WER/RTF/MOS 是什么、知道噪声口音会让模型变差。资深筛:扛得住‘真实场景鲁棒性 × 流式延迟 × 端上算力’的三方账、能从 0 定义分场景评测与 badcase 归因体系、把数据采集标注合规管线建起来、设计得了对下游的置信度契约与兜底、并对 voice clone/声纹的反滥用与合规风险有判断。

## 机器学习工程师 · ML Engineer
> 把模型变成稳定线上服务的人:特征平台、训练/推理管线、模型服务与监控,价值在模型之外的工程可靠性。核心矛盾:模型离线指标好≠线上能用——训练用的是干净、静态、能时间旅行的历史快照,线上是脏、实时、会漂的流,这两套数据/特征一旦不一致,离线 AUC 全是虚高;这岗的活就是把这条缝焊死、并持续盯它别再裂。
**核心工作职能**：
- 搭训练/推理管线并保证特征一致性:产出=同一份特征定义离线训练与在线服务共用(feature store/统一计算)、point-in-time 正确的训练集构造、线上线下特征一致性的自动校验,而不是两套各写各的 pipeline
- 把模型服务做到能扛线上 SLA:产出=吞吐/延迟达标的推理服务(批处理/动态 batching/缓存/量化档位)、p99 延迟与 GPU 利用率上 dashboard、容量与扩缩容方案
- 设计上线灰度与回滚:产出=shadow/canary/champion-challenger 的发布流程、分流与守门指标、秒级回滚开关(钉旧模型版本/翻 flag),不做一把全量替换
- 建模型监控与漂移告警:产出=数据漂移/概念漂移/预测分布/线上线下偏移的监控面板、告警阈值、坏样本回流,把'指标悄悄退化'变成可观测
- 设计自动重训与兜底:产出=触发条件明确的重训流水线(漂移触发 vs 定时)、新模型必须过的离线门+影子验证才放量、模型挂了/超时的降级策略
### 怎么想
**心智模型**：
- **线上线下一致性是第一性,offline 指标只是参考**：老手接一个上线需求,第一眼不看模型多准,先问:训练这份特征和线上服务那份特征是不是同一套逻辑算出来的、训练集有没有 point-in-time 正确。用它你能在上线前就预判'离线好线上崩'——只要特征是两套代码各写各的,或训练时混进了预测时刻拿不到的未来信息,offline AUC 再高都是虚的(point-in-time 错误常把 AUC 虚高约 5–20%)。把 feature store 当存储优化、没意识到它本质是治 train-serve skew,是这岗最典型的认知缺失。
- **一个特征值从产生到喂进模型要走完整条因果链**：用它你能把任何线上故障定位到链路某一环:原始事件→特征计算(批/流)→离线存储(可时间旅行)+在线存储(低延迟)→训练集 as-of join→模型→推理→监控回流。线上预测变差,老手顺着链子查:是上游 schema 变了、特征计算的批流口径不一致、还是 online store 没及时物化、拿到的是陈旧值。看不懂这条链,就只会在'是不是该重训了'上瞎猜。
- **可靠性活在尾部和分布偏移里,不在平均准确率**：用它你能判断一个服务真实健不健康:看 p99/p999 延迟、不只看 p50;看预测分布和输入分布有没有漂、不只看 AUC。老手知道概念漂移(输入没变但 x→y 关系变了,比如产品改版后'30天不活跃'不再预示流失)离线指标根本测不出来,得靠线上真实 label 回流才暴露;数据漂移(分布变了关系没变)可以无监督用 PSI/KS 这类分布检验在线测,Page-Hinkley 这类序贯变点检测则常挂在误差或某个监控量上。把监控只挂准确率、分不清这两种漂移,是新手最常见的盲区。
- **GPU 利用率和动态 batching 是推理成本的总开关**：用它你能在不换模型的前提下把单位推理成本压下来:一块 GPU 跑在 30% 利用率,单次推理成本约是跑满时的 3.3 倍(成本随空闲反比放大,10% 利用率就≈10 倍);上 continuous batching/PagedAttention 能把利用率从约 15–30% 拉到 60–80%、同样硬件吞吐提升约 3–4 倍(vLLM,2025)。老手算账时知道:自建推理划不划算不只看利用率,还要算够大的稳定 token 量和一个专职推理工程师的人力,三者凑齐才比调 API 省,量小时人力成本就把省下的吃光。通篇不提利用率和 batching、上来就要加卡,是把成本当不可控量。
- **模型不是越新越好、重训不是越勤越好**：用它你能判断何时该按住不动:模型权重自己不会漂,数据漂了才需要动;模型表现好、数据没变,定时每周重训纯烧钱(2025 共识)。但反过来,反馈周期长的场景(信贷违约要等 12 个月看结果)、或受监管要审批的模型,事件触发不现实,定时+人工审批更稳。老手据场景的反馈速度和错误成本选触发方式,不无脑上'持续训练'。
- **怎么知道自己判断偏了:靠线上真实 label 回流和影子对账,不靠离线分和体感**：这岗校准自己的硬办法:把线上真实结果回流回来,拿当时的预测对账,算真实线上指标——离线 holdout 分高、团队'感觉模型变好了'都可能是 train-serve skew 或评测集污染造成的假象。老手上新模型不直接信离线门,先 shadow 跑真实流量、对比新旧预测分布和线上指标,确认了再灰度。判断偏了的信号:说不清线上线下指标差多少、没有 label 回流闭环、只敢拿离线 AUC 和 demo 说话、漂移监控从来没报过警(往往是没接对真实分布)。
**基准线**：在线特征服务 p99 延迟交互式场景常压在个位数到几十毫秒量级(成熟商用特征平台对外标 sub-10ms 服务,Tecton,2025;自建 Redis 类在线 store 基线小并发约几十毫秒,随特征数与并发差异大);point-in-time 错误/特征泄漏会把离线 AUC 虚高约 5–20%(可见公开案例 0.95→0.78,2026);GPU 跑在 30% 利用率单次推理成本约为跑满时的 3.3 倍(成本随空闲反比放大,10% 利用率≈10 倍,2026 行业测算),自建推理划算需同时满足利用率稳过约 50%、足够大的稳定 token 量(约 5 亿 token/天量级)和专职推理工程师人力,量小时人力成本吃光节省;continuous batching/PagedAttention 把 GPU 利用率从约 15–30% 拉到 60–80%、吞吐提升约 3–4 倍(vLLM,2025),高并发下相对 TGI 吞吐差距可拉到一个数量级;自建开源特征平台(Feast)运维约需 0.3 FTE+基础设施成本(随规模差异大);Uber Michelangelo 量级约 10 万亿次特征计算/天、约 1 万特征、约 1 千模型(Uber 公开数据,作规模参照而非通用基准)。
**战例**：Uber Michelangelo / DoorDash Fabricator 等大厂自建特征平台:Airbnb、Netflix、Uber 都是因为'手搓训练集太容易引入数据泄漏、且线上线下口径对不齐'才不得不造特征平台(Michelangelo 用统一 PipelineModel 强制线上线下同一套预处理消除 skew,DoorDash Fabricator 称把特征工程时间砍约 90%、特征迭代从天缩到小时),教『特征一致性是平台第一性问题、不是基础设施复杂度问题』(Uber/DoorDash 公开工程博客,Fabricator 2022) ／ vLLM 用 PagedAttention + continuous batching:模型没变,靠 KV cache 分页和迭代级调度把 GPU 利用率和吞吐拉数倍、高并发下相对 TGI 吞吐差距可达一个数量级(2025 多份基准),叠加 Tecton 2025.08 被 Databricks 收购,教『ML 工程的赢家赢在服务/特征基础设施这层、不在模型算法本身,且独立特征平台正在被云数据平台整合』(vLLM 项目 / Databricks 2025 收购公告)
**悬案**：
- 在线/离线特征一致性:双写 vs 统一引擎：双写派:特征算一次,分别物化进离线 store(可时间旅行做训练集)和在线 store(低延迟服务),靠 Kafka/同一份 schema 走最终一致(Hopsworks 路线),架构成熟、各 store 按各自负载选型；统一引擎派:同一套特征变换代码既跑离线又跑在线、避免两条物化路径口径漂移(PipelineModel/部分托管平台路线),但实时计算和历史回填合到一个引擎,工程更重（2025–2026 仍无定论,主流是双写+严格 schema 一致校验,但谁来保证两条路口径不漂仍是各家自己解）
- 自动重训触发:漂移触发 vs 定时：漂移/事件触发派:检测到分布漂移或线上指标破阈值才重训,省算力、漂得猛时不用等下个周期(2025 多方称为更优方向),适合欺诈/定价/推荐这类反馈快的场景；定时派:固定周期重训简单可审计、不依赖漂移检测器本身的可靠性;反馈周期长(信贷违约等 12 个月看 label)或受监管要审批的模型,事件触发不现实,定时+人工反而更稳（2026 共识=按场景反馈速度和监管选,无放之四海皆准的触发方式）
- 特征平台/MLOps 栈:自建开源 vs SaaS：自建派(Feast 等):掌控基础设施、无 vendor lock-in、成本透明,适合有工程余量的团队;但需有人懂物化架构、约 0.3 FTE 长期维护,流式特征和监控要自己补；SaaS 派(Tecton/云厂托管):开箱即用、流式特征和监控原生、省人力,但消费计费、深度绑定厂商;Tecton 2025.08 被 Databricks 收购后,'独立特征平台'本身的生存空间也成了变量（2025–2026 偏'小团队买、规模大且工程强自建',且特征平台正被云数据平台吸收整合）
**前沿**：LLMOps 把这岗的活改写了一半:多数团队不再自己训模型、改用托管基座(GPT/Claude 类),成本从'训练贵'变成'每次推理贵',监控从'模型内部指标'变成'系统级指标'(厂商静默更新模型、工具 schema 会变,得当外部依赖盯)。新增技能=推理服务优化(continuous batching/量化/投机解码)、RAG plumbing、eval harness 设计;评测从辅助升为研发主线(线上 trace 全量跑启发式 eval 兜底、再抽 10–20% 跑 LLM-as-judge)。但传统 MLOps 没消失=特征平台、漂移监控、train-serve 一致性在排序/推荐/风控这些自训模型场景仍是硬地基;LLMOps 是叠在 MLOps 上的扩展,不是替代(2025–2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：被问'怎么保证模型上线效果',答'离线评测集上 AUC 0.9 就上线';故障了第一反应'是不是该重训了'｜强：主动讲 train-serve skew:训练特征和线上特征是不是同一套逻辑、训练集有没有 point-in-time 正确、线上线下偏移怎么监控;故障先顺特征因果链定位到批流口径/陈旧物化/schema 变更哪一环
- 套模板 vs 看情境｜弱：不管什么模型都上'持续训练'、都要自建特征平台、都堆 GPU;把 multi-stage pipeline 当标准答案背｜强：先问场景反馈速度和错误成本→定重训用漂移触发还是定时、用 shadow 还是 canary、自建还是买 SaaS;信贷类长反馈和欺诈类快反馈给完全不同方案
- 需提示 vs 自驱｜弱：不追问就只讲'把模型部署成 API';不主动谈监控、漂移、回滚、成本｜强：不用问就把漂移监控(数据漂移+概念漂移分开)、灰度发布、秒级回滚、p99 延迟和 GPU 利用率当方案默认组成部分,且说得清各自阈值谁拍板
- 被动 vs 主动｜弱：'等数据团队把特征算好我来训''线上慢就加卡';把可靠性当模型本身的属性｜强：在现有模型能力下用动态 batching/缓存/量化把成本延迟压下来、用 shadow+影子对账主动验证、把可靠性当能调的工程旋钮;利用率不过 50% 先优化再谈加卡
- 影响自己 vs 影响系统｜弱：只交付一个能跑通的训练脚本和一个 API endpoint,特征算法藏在自己 notebook 里｜强：留下可复用的特征定义(离线在线共用)、point-in-time 训练集构造、线上线下一致性校验、漂移监控和回滚判据,让算法/数据/业务在同一套平台上协作迭代
**失分**：把 feature store 当普通缓存/存储优化、说不清它治的是 train-serve skew;训练集构造不做 point-in-time as-of join、混进未来信息还报虚高 AUC 当成绩;监控只挂准确率、分不清数据漂移和概念漂移、概念漂移没 label 回流根本测不出;通篇不提 p99 延迟和 GPU 利用率、上来就要加卡;上线一把全量替换、没有 shadow/canary 和秒级回滚;无脑'持续训练'、说不清何时该按住不重训;把 LLMOps 当万能、忘了排序/风控场景传统 MLOps 那套地基还在
**必考**：
- 线上线下特征一致性与 point-in-time 正确(几乎必问) [分析]:背得出'要用 feature store'是失分线;能讲清 skew 怎么产生、as-of join 怎么防未来信息泄漏、双写/统一引擎怎么保一致、怎么自动校验线上线下偏移才是高手线
- 漂移监控与重训触发设计 [评价]:只说'监控准确率'是失分线;能分开数据漂移(无监督 PSI/KS、序贯检测 Page-Hinkley)和概念漂移(必须真实 label 回流)、按场景反馈速度选漂移触发还是定时重训、说清新模型放量前要过哪些门是高手线
- 上线灰度与回滚策略 [应用]:答'部署成 API'是失分线;能区分 shadow(不影响决策只对账)/canary(小流量灰度)/champion-challenger(同 holdout 对打),并设计秒级回滚(钉旧版本/翻 flag)是高手线
- 推理服务的吞吐/延迟/成本优化 [应用]:只会'加卡'是失分线;能用 continuous batching/缓存/量化/投机解码把 GPU 利用率和吞吐拉上去、算清自建 vs API 在什么利用率和量级下划算、看 p99 不只看 p50 是高手线
- 从 0 设计一条生产 ML 管线并定位线上故障 [创造]:能背出管线各阶段是理解线;能顺着'原始事件→特征→离线/在线 store→训练集→推理→监控回流'这条因果链把一个真实线上退化定位到具体某一环、并给出修法,是高手线
**黑话**：train-serve skew、point-in-time 正确、as-of join、feature store(在线/离线)、特征物化 materialization、数据漂移、概念漂移、PSI、KS 检验、Page-Hinkley、shadow deployment、canary、champion-challenger、continuous batching、PagedAttention、KV cache、投机解码、量化、p99/p999、GPU 利用率、影子验证、label 回流、CT 持续训练、LLMOps
**高频题**：怎么保证训练和线上用的特征一致／线上指标好但上线后变差怎么排查／怎么设计模型上线的灰度和回滚／什么时候该触发重训、用漂移触发还是定时／一个推理服务延迟高/成本高怎么优化／怎么监控模型漂移、数据漂移和概念漂移怎么分别测／feature store 自建还是买、解决什么问题
**追问链**：「怎么保证训练和线上用的特征一致?」→ ①[通用] 你会怎么搭这条从数据到上线的管线、哪些环节最容易出问题?②[职能] 离线训练和在线服务的特征怎么做到同一套逻辑、双写和统一引擎你选哪个、为什么?③[岗位] 训练集构造怎么保证 point-in-time 正确防止未来信息泄漏、上线后怎么自动校验线上线下偏移、偏了怎么报警和定位到批流口径哪一环?
**定级**：初级筛『能把一个模型部署成线上服务、知道 feature store / 漂移监控 / 灰度回滚这些东西存在、能讲清楚一条基本训练-推理管线』;资深筛『扛得住线上线下一致性×推理成本×延迟的三方账、能从 0 设计特征平台与 point-in-time 训练集构造、做得了漂移监控与重训触发的体系化设计、定位得了真实线上退化故障、知道什么场景该上 LLMOps 那套、什么场景传统 MLOps 地基不能丢』
**来源**：vLLM 吞吐/利用率:vLLM 官方 + 多份 2025 推理运行时基准(continuous batching/PagedAttention 把利用率从约 15–30% 拉到 60–80%、吞吐约 3–4 倍,高并发下相对 TGI 差距可达一个数量级;2025);Databricks 收购 Tecton:Databricks 2025.08 公告 + 行业报道(~$900M 量级估值);DoorDash Fabricator:DoorDash 工程博客《Introducing Fabricator》(特征工程时间砍约 90%、迭代从天到小时,2022);GPU 利用率成本/自建 vs API break-even:2026 多份自建 LLM vs API 成本测算(10% 利用率≈10 倍成本、7B 自建需约 50%+ 利用率且约 5 亿 token/天量级、专职推理工程师人力主导小量场景);数据/概念漂移检测:PSI(阈值≈0.25)、KS 检验、Page-Hinkley 序贯变点、概念漂移需真实 label(DataCamp/Encord/2026 漂移检测综述);point-in-time 泄漏致 AUC 虚高约 5–20%(公开案例 0.95→0.78,2026);Feast 自建运维约 0.3 FTE(2026 特征平台对比);Uber Michelangelo 约 10 万亿次特征计算/天、约 1 万特征、约 1 千模型(Uber 官方博客 Scaling Michelangelo)。

## 风控 / 反欺诈算法工程师 · Risk / Anti-Fraud Engineer
> 用规则、模型、名单和图/序列特征在毫秒级识别欺诈/套现/薅羊毛,和会主动绕过你的黑产实时对抗的人。核心矛盾:你优化的不是准确率,是误杀(挡住真实用户、毁转化)和漏杀(放过欺诈、吃损失)两笔业务代价的不对称权衡——对手盯着你的策略持续变形,标签还要等几十天才回来,等于蒙着眼打一个会还手的活靶子。
**行业**：金融
**细分**：支付与金融科技
**核心工作职能**：
- 规则与模型分层处置:产出=一套分层决策(规则/名单拦明确恶意+模型打分卡灰区+人工审核高代价单),每条规则/每个模型有命中量、误伤率、可解释理由,不是单一黑盒打个分
- 按业务代价定阈值而非按 AUC 调模型:产出=误杀成本×漏杀成本的不对称账,据此定拦截/放行/转审三档阈值与各档预期 FPR/召回,阈值改动前先估对转化和资损的影响
- 养对抗性特征与图/序列建模:产出=设备指纹、行为序列、关联图(同设备/同收款/同 IP 团伙)等抗变形特征,以及对应的 GNN/序列模型,假设对手会针对单一特征变形
- 处理极不均衡与标签滞后:产出=正样本千分位级的训练方案(代价敏感/重采样/PU 学习)+早期标签代理(规则命中、客诉、人工复核)补偿几十天的 chargeback 滞后,线上用 PR-AUC/分档召回而非 accuracy 看效果
- 策略迭代与黑产攻防复盘:产出=新欺诈模式的归因(查到怎么绕的→补特征/补规则/重训)、灰度与回滚判据、名单与策略的生命周期管理(进/出/过期),把一次性堵漏沉淀成可复用的对抗资产
### 怎么想
**心智模型**：
- **先算误杀和漏杀的不对称代价,再谈模型**：接一个风控需求,第一件事不是选 XGBoost 还是 GNN、调多少特征,而是问:这个场景误杀一单真实用户损失多少(转化/客诉/品牌),漏杀一单欺诈损失多少(资损/合规)。两者代价差几个数量级时,阈值和召回目标完全不同——支付盗刷漏杀贵、要高召回;营销薅羊毛误杀贵(挡住真用户领券毁活动)、要保精度。用它你能在第一轮就把目标从『准确率高』翻译成『FPR 压在 X、召回保 Y』,而不是炼完丹才发现方向错了。
- **对手会还手:任何单一特征都会被变形**：风控和推荐最大的不同——你的数据分布是对手主动制造的,他盯着你的策略改。封 IP 他上代理池,查设备指纹他用改机/云手机农场,看注册时间他模拟人类停顿。所以好特征是『变形成本高』的特征:设备指纹组合、行为序列节奏、资金/关联图的团伙结构,比单点字段抗造。用它你能预判一条规则上线后黑产怎么绕、下一步往哪补,而不是被动等召回掉下来才反应。
- **伪装与异质性:坏人会主动连好人、装成好人**：图建模里的老手才看见的坑:欺诈节点会做两种伪装——特征伪装(把行为做得像正常用户)和关系伪装(故意和正常账户建连接稀释嫌疑)。这让欺诈图天然异质(fraud 连 benign),普通 GNN 邻居聚合会把坏样本洗白。CARE-GNN(CIKM 2020)这类工作就专门用标签感知的邻居筛选对抗伪装。用它你看一张关联图,会先怀疑稠密连接里混了伪装边,而不是直接信『连得多就是团伙』。
- **标签是滞后的、被污染的、还会幸存者偏差**：风控最反直觉的一条:你今天的判断,真标签(chargeback/确认欺诈)要等几十天才陆续回来(支付侧 dispute 窗口通常到 120 天),而且被你拦掉的单永远不知道对错(拦了就没有 chargeback,幸存者偏差)。所以不能干等标签——手册外的实操是搭早期标签代理(规则命中、客诉、人工抽审、试投放小流量看真实表现),并定期给被拦流量放行小样本量真标签来校准。用它你能在标签回流前就发现模型在漂,而不是几十天后才从资损报表里看出问题。
- **该用规则就别硬上模型,该容忍漏杀就别追零漏过**：何时打破『模型更先进』的惯性:明确的恶意模式(命中黑名单、已知欺诈 BIN、撞库特征)用规则/名单更快更可解释,没必要喂给模型;某些场景(如低客单价、高频小额)漏杀的资损还不如误杀掉的转化值钱,这时就该主动放宽、容忍一定漏过。监管/合规场景(AML)又翻过来——宁可误报一堆也不能漏报,因为漏报是法律责任。用它你能按场景在『高召回/高精度/可解释/合规优先』之间切换,而不是不管什么场景都追同一个 F1。
- **怎么知道自己被黑产绕过了:盯命中结构和放行抽样,不信整体指标**：风控的自我校准最难,因为整体指标会骗你:对手攻击集中在某个细分(某渠道/某金额段/某新玩法),整体 FPR/召回纹丝不动,局部已经被打穿。校准靠三样,都不是体感:①盯规则/模型命中量的结构突变(某条规则命中量一夜翻倍或归零=要么被绕要么误伤),②对被拦流量做放行抽样拿真标签估真实精度(否则永远活在幸存者偏差里),③用稳定的人工复核金标做基准,模型分和复核结论分歧变大就触发重检。判断偏了的信号:只敢拿离线 AUC 说话、说不清最近一次黑产怎么绕进来的、给不出被拦流量的真实误伤率。
**基准线**：欺诈正样本占比通常在千分位到万分位级(Kaggle 信用卡盗刷公开数据集 492/284,807≈0.172%,ULB 2013,行业实际随场景差异大);chargeback/确认欺诈标签滞后约几十天到上百天——支付侧卡组织 dispute 窗口标准约 120 天(部分欺诈类可延至 540 天),实操里多数在 30–90 天陆续回流(Visa/Mastercard 争议规则,2025–2026);误杀的业务代价常被低估——行业测算被误拦的合法交易损失可达真实欺诈损失的数倍乃至数十倍(Aite-Novarica 测算口径不一,数量级可信);AML 交易监控告警约 90–95% 是误报(PwC 广引数据,2020s 持续被引);PSD2/EBA TRA 豁免按欺诈率分档(总体欺诈率 ≤0.13% 可豁免到 €100、≤0.06% 到 €250、≤0.01% 到 €500,每 90 天向监管报数,EBA RTS),是少有的把『可接受欺诈率』写进监管的硬阈值;实时拦截延迟一般压在 ~100ms 量级内(支付场景经验,超了就挡转化)。模型主指标用 PR-AUC / 分档召回而非 accuracy(极不均衡下 accuracy 失效)。
**战例**：CARE-GNN(Dou 等,CIKM 2020,arXiv 2008.08692):专门对抗欺诈节点的特征伪装与关系伪装,用标签感知相似度+强化学习筛选邻居——教『图反欺诈的真难点不是建图,是对手会主动连好人、装成好人、制造异质性把坏样本洗白,普通 GNN 邻居聚合会帮倒忙』／PwC 广引的『AML 交易监控告警约 90–95% 是误报』:静态阈值规则在极不均衡+对手变形下要么淹没分析师要么漏过真案——教『风控成败在误杀/漏杀的成本权衡和告警质量,不在堆规则;高误报会拖垮人工复核、让真 alert 淹死在噪音里』
**悬案**：
- 规则引擎 vs 机器学习谁主导：规则派:可解释(命中哪条一目了然、能向监管/业务交代)、冷启动即可用无需标签、改起来快,明确恶意模式(黑名单/已知欺诈特征)规则更对；模型派:规则只堵已知模式、对新型变形和长尾盲、维护成本随规则膨胀爆炸,ML 能抓非线性组合和未知模式、召回更高（业界共识 2020s 收敛到分层混合:规则/名单做第一道明确拦截+模型抓灰区与未知,二者输出汇总成处置决策,高代价单留人工 final say(2026)）
- 可解释性 vs 召回率：可解释派:风控要向用户解释为何被拒、向监管举证、给人工复核抓手,黑盒高召回但拒因说不清=合规和申诉灾难,逻辑回归/评分卡/规则可审计；高召回派:对手在进化,牺牲一点可解释换更高召回就是少吃资损,GNN/深度序列模型抓得到规则和线性模型抓不到的团伙与变形,可解释靠事后归因(SHAP/特征贡献)补（无定论、按场景分:营销/支付风控偏召回+事后归因,信贷/AML 偏可解释(强监管要求拒因可举证)(2025–2026)）
- 无监督异常检测 vs 有监督建模：无监督派:欺诈标签滞后又稀缺、新型攻击根本没标签,异常检测/图社区发现/规则挖掘能抓没见过的模式、不依赖回流标签；有监督派:无监督误报高、抓到的『异常』很多是合法长尾(新用户/大额正常交易),有标签的有监督模型精度和可落地性高得多,异常只配做线索不配做拦截（实践多为两段式:无监督/图找线索与新模式→人工确认转成标签→喂有监督模型固化拦截,纯无监督直接拦截误伤大(2025–2026)）
**前沿**：攻防两端都被生成式 AI 重写:黑产侧深伪换脸过活体、合成身份(用真假拼接的身份养号、无真人受害者报案故潜伏更久)、深伪即服务/欺诈即服务(DaaS/FaaS)把作案门槛降到几乎零技术,行业报告称深伪攻击近三年涨幅以千倍计、2025–2026 注入式攻击(虚拟摄像头把伪造视频直灌进活体核验管线)和自动化攻击 agent 显著上升(Sumsub/Cyble 2026 等,具体倍数各家口径差异大);防守侧设备指纹/行为生物特征/TLS 指纹对抗改机与 headless 浏览器,LLM 开始用于可疑交易/工单的推理研判与告警降噪(多角色 prompt、RAG 检索相似案例),但拦截主力仍是规则+图/序列模型(LLM 太慢太贵进不了毫秒级拦截链路)。监管侧 PSD2/EBA 用欺诈率阈值反向逼着风控既要低误杀(豁免换转化)又要控真欺诈率(2025–2026)。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：上来报『我们模型 AUC 0.98 / 准确率 99%』当成绩,默认准确率越高越好｜强：先说极不均衡下 accuracy 没意义、要看 PR-AUC 和分档召回,主动把误杀/漏杀拆成两笔不对称业务代价,讲清拦掉的单看不到真标签(幸存者偏差)、得放行抽样估真实精度
- 套模板 vs 看情境｜弱：不管支付盗刷、营销薅羊毛还是 AML,都套同一套『提特征→XGBoost→调阈值追 F1』｜强：先问场景:支付漏杀贵→冲召回;营销误杀贵(挡真用户毁活动)→保精度;AML 漏报是法律责任→宁误勿漏;据此才定模型、阈值、可解释要求
- 需提示 vs 自驱｜弱：不追问就只讲离线建模,不主动提对手会绕、标签滞后、误报拖垮人工、上线后怎么监控｜强：不用问就把对抗变形预案、早期标签代理、命中结构监控、放行抽样校准、灰度回滚当方案的默认组成部分
- 被动 vs 主动｜弱：等召回掉了才被动补规则、打地鼠式堵漏,一个漏洞补一条规则、不归因｜强：把每次黑产突破都做根因归因(查到怎么绕的→补抗变形特征/重训/调名单生命周期),提前预判下一个变形方向,把堵漏沉淀成可复用对抗资产
- 影响自己 vs 影响系统｜弱：只交付一个跑通的模型,口头说『效果不错』,没有可复用的处置分层、监控和复核流程｜强：留下分层决策框架、误杀/漏杀成本台账、命中监控与放行抽样校准机制、名单与策略生命周期,让风控/算法/业务/合规在同一套代价口径上协作迭代
**失分**：报『准确率/AUC 99%』当成绩、不提极不均衡下该看 PR-AUC 和分档召回;通篇不提误杀的业务代价(只想着多抓欺诈、不算挡掉真用户的转化损失);默认 SMOTE/重采样一上就行、不讲它会在欺诈这种边界混杂数据上造噪声、不提代价敏感与阈值移动也是手段;忘了被拦流量没有真标签(幸存者偏差),拿线上『没 chargeback』当模型很准;把欺诈当静态分类问题、不假设对手会针对策略主动变形;直接拿无监督异常检测的『异常』当拦截依据(大量合法长尾被误伤);只会建图/堆 GNN、说不清伪装与异质性会让邻居聚合帮倒忙;AML/信贷场景里只追召回、不给可解释拒因(监管和申诉过不去)。
**必考**：
- 极不均衡处理与正确评估 [应用]:背得出『用 SMOTE/过采样』是失分线;能讲清重采样在欺诈边界数据上会造噪声、代价敏感/PU 学习/阈值移动各自适用场景、且坚持用 PR-AUC 与分档召回而非 accuracy/ROC-AUC 评估才是高手线
- 误杀 vs 漏杀的不对称代价权衡 [评价]:能说『要平衡精度和召回』只是失分线;会把两类错误折算成具体业务代价(误杀=转化/客诉损失,漏杀=资损/合规),并据此定分档阈值、按场景倒过来选目标(支付冲召回/营销保精度/AML 宁误勿漏)才是高手线
- 标签滞后与幸存者偏差怎么破 [分析]:知道『chargeback 会延迟』是失分线;能设计早期标签代理(规则/客诉/人工抽审)补几十天滞后、并对被拦流量做放行抽样拿真标签校准、识别出拦掉的单没有真标签这件事本身才是高手线
- 对抗性思维——黑产怎么绕、你怎么挡 [创造]:把欺诈当普通分类问题是失分线;能具体推演封 IP→代理池、查设备→改机/云手机农场、看时间→模拟人类停顿,并据此选『变形成本高』的特征(设备指纹组合/行为序列/关联图)才是高手线
- 图/序列建模与伪装异质性 [理解]:会说『用 GNN 抓团伙』是失分线;能讲清欺诈节点的特征伪装+关系伪装会制造异质性、让普通邻居聚合把坏样本洗白,知道 CARE-GNN 这类标签感知筛邻居的应对思路才是高手线
**黑话**：误杀(false positive/误拦)、漏杀(false negative/漏过)、PR-AUC、分档召回、代价敏感学习、类别不均衡、SMOTE、PU 学习、标签滞后、chargeback、幸存者偏差、设备指纹、改机/云手机农场、行为序列、关联图、团伙挖掘、GNN、特征伪装、关系伪装、异质性/heterophily、名单(黑/白/灰名单)、策略引擎、对抗样本、合成身份、深伪、活体检测、人机 loop/HITL、champion-challenger、概念漂移、SCA/3DS、TRA 豁免
**高频题**：正样本千分之一怎么训和评估,为什么不能只看准确率/AUC／拦截阈值怎么定、误杀和漏杀哪个更贵你怎么算这笔账／黑产会怎么绕过你这条规则、你下一步怎么补／chargeback 标签要等几十天才回来,这段时间你怎么知道模型有没有漂／什么场景上规则、什么上模型、什么上图算法／用 GNN 抓团伙时欺诈节点伪装成正常用户怎么办／被你拦掉的交易没有真实标签,你怎么评估它们到底误伤了多少
**追问链**：「正样本只有千分之一的欺诈,你怎么建模和评估?」→ ①[通用] 不均衡怎么处理:重采样/代价敏感/阈值移动各有什么坑,为什么 accuracy 在这里没意义、该看什么指标?→ ②[职能] 上线后召回慢慢掉了,你怎么判断是概念漂移、数据问题、还是对手在变形,分别怎么补?→ ③[岗位] chargeback 标签滞后几十天、而且被你拦掉的单永远没有真标签(幸存者偏差),这两个问题叠在一起,你具体用什么机制在标签回流前就估出真实误杀率和漏杀率、并校准模型?
**定级**：初级筛『能用规则/常见模型搭出一个能跑的欺诈识别、知道要处理不均衡、能讲清精度召回的区别和误杀漏杀的存在』;资深筛『扛得住误杀×漏杀×对抗变形×标签滞后四方账,能按业务代价从 0 定阈值与处置分层,有对抗性思维(预判黑产怎么绕并主动补)、会用图/序列建模且懂伪装异质性的坑,能搭早期标签代理+放行抽样校准破解幸存者偏差,知道什么场景该用规则/该容忍漏杀/该宁误勿漏(合规)』
**来源**：CARE-GNN(Dou, Liu, Sun, Deng, Peng, Yu),"Enhancing Graph Neural Network-based Fraud Detectors against Camouflaged Fraudsters",CIKM 2020,arXiv:2008.08692(核实=标题/作者/会议/arXiv ID 全对,标签感知相似度+RL 邻居筛选对抗特征/关系伪装);Kaggle Credit Card Fraud Detection 数据集(ULB,2013,492/284,807≈0.172% 正样本,核实);PSD2 EBA RTS 转账风险分析(TRA)豁免欺诈率阈值=0.13%→€100 / 0.06%→€250 / 0.01%→€500,每 90 天向监管报数(EBA RTS / EBA Single Rulebook Q&A,2024–2026 现行);AML 交易监控约 90–95% 告警为误报(PwC 广引,2020s 持续被引,2025);信用卡 chargeback dispute 窗口标准约 120 天、部分可延至 540 天(Visa/Mastercard 争议规则,2025–2026);误拦合法交易损失可达真实欺诈损失数倍乃至数十倍(Aite-Novarica false-decline 测算,口径不一,2023–2025);深伪/合成身份/DaaS-FaaS 与注入式攻击 2025–2026 显著上升(Sumsub 2026 身份欺诈趋势报告 / Cyble 2026 / Biometric Update 2026,具体倍数各家口径差异大)

## 自动驾驶感知算法工程师 · AD Perception Engineer
> 用相机/激光/毫米波让车实时看懂三维路况、对长尾 corner case 和功能安全负责的人。核心矛盾：感知是概率的、长尾无穷，车规却要有界、可验证、能签字担责——穷举不出 100% 召回，只能用多传感器冗余、占用表示兜未知物、靠数据闭环把尾部一例例收进来，再用功能安全框架证明残余风险可接受。
**行业**：智能制造
**细分**：汽车
**核心工作职能**：
- 搭车端 3D 感知模型并压进算力预算：产出=BEV/Occupancy 下的目标检测+跟踪+占用网络，在 Orin/Thor 量级 SoC 上 INT8 量化后多路相机端到端时延压到帧周期内（常见 ~100ms），mAP/NDS 与延迟/功耗一起进验收表
- 设计多传感器融合与失效降级：产出=相机/激光/4D 毫米波的前融合或中融合方案+传感器互不信任时的仲裁逻辑+单传感器失效（脏污/逆光/雨雾）下的降级策略与冗余链路
- 跑长尾 corner case 的数据闭环：产出=车队影子模式回传触发器、坏例自动挖掘、4D 自动标注/重建管线，把一类 corner case 从发现到进训练集到回归验证闭环，而非手标一批就完事
- 对功能安全与 corner case 负责：产出=按 ISO 26262(故障)与 ISO 21448 SOTIF(功能不足)拆的感知失效模式、误检/漏检的不对称指标、残余风险论证，能在 release gate 上为感知签字
- 建可复现的评测与回归体系：产出=分场景分天气的离线评测集+holdout+影子模式线上指标，新模型上车前误检率/漏检率/跟踪 ID switch 不劣化的 CI 门，离线-在线指标 gap 有人盯
### 怎么想
**心智模型**：
- **先看漏检的代价、再看 mAP**：老手接一个感知 case，第一反应不是冲高 mAP，是问这一类目标漏一次会怎样：漏个静止的事故车=可能撞上去，漏个远处行人=可能来不及刹。误检和漏检代价极不对称——用它你能把召回阈值、NMS、跟踪起报逻辑按错误成本调，而不是一刀切优化总体精度。把行人召回和锥桶召回当一个指标优化，是这岗最典型的外行病。
- **传感器是互补的、也会互相矛盾**：相机给语义和纹理但缺深度、怕逆光雨雾；激光给精确几何但贵、雨雪里有噪点回波；4D 毫米波给径向速度和恶劣天气鲁棒但稀疏、有多径鬼影。用它你能为一个场景选对融合层级（前融合精度高但要严格时空对齐、中融合在 BEV 里对齐最灵活、后融合简单但丢协同），更要紧的是想清楚两个传感器打架时信谁——这套仲裁逻辑才是融合工程师的真活。
- **已知类别会有，未知障碍物也得兜住**：基于 3D 框的检测只认训练过的类别，遇到翻倒的卡车、掉落的轮胎、动物这类长尾就抓瞎。占用网络（Occupancy）退一步只问每个体素被不被占、往哪动，不依赖类别本体——用它你能给规控一个对未知物也安全的几何兜底。老手做感知会同时留 3D 框（给规控语义和速度）和占用（给几何安全网），不赌检测头认全世界。
- **算力预算是硬约束、是先决条件不是优化项**：论文里 SOTA 的 BEVFormer 在车上可能根本跑不动。Orin 标称 254 INT8 TOPS（稀疏算力，稠密约 127），还要分给 8 路相机+激光+多任务头，留给单模型的算力很有限。用它你能在选型时就把 backbone、BEV 分辨率、时序帧数按延迟预算砍，靠 INT8/FP8 量化和算子融合落地——把『先训出好模型再想部署』当流程，到上车阶段精度全被量化和裁剪吃回去。
- **该退回模块化、该信冗余，别被端到端潮流绑架**：端到端（E2E）省掉模块间误差累积、上限高，但是个黑盒、坏例难归因、出了事说不清哪一步错。用它你能判断什么时候不该一把梭端到端：安全关键链路上，可解释的模块化感知+一条独立的占用安全网，比纯黑盒更好做功能安全论证和兜底。打破常规的另一面——纯视觉路线在成本和数据规模上有它的道理，没激光不等于一定不安全，要看 ODD 和验证证据。
- **离线涨点≠路上安全，体感顺≠真变好**：感知工程师怎么知道自己判断偏了：离线 nuScenes 涨两个点不代表那类 corner case 真解决了，测试集会过拟合、线上分布一漂移指标全失效；也别信『路上感觉顺多了』的体感，那是 happy path。校准靠影子模式——新模型在车队后台跟真实分布跑、和量产模型比分歧、专挖它出错的尾部场景，再回灌训练。判断偏了的信号：只敢拿 benchmark 说话、拿不出 holdout、说不清自己漏检集中在哪类场景哪种天气。
**基准线**：相机 3D 检测在 nuScenes 上以 mAP/NDS 衡量，BEVFormer 2022 测试集 NDS 56.9%、当年比此前最佳高约 9 个点、追平部分激光基线，之后纯视觉与融合方法持续上涨（榜单年年变，别背绝对数当现状）；车端感知延迟一般要压在帧周期内、相机多为 ~10–30fps 即单帧 ~30–100ms 量级（随 SoC 与传感器路数差异大）；量产域控算力 NVIDIA Orin 标称 254 INT8 TOPS（稀疏，稠密约 127）、Thor 上千 INT8 TOPS（2025，均需分摊给全部传感器与多任务）；模型上车普遍走 INT8 量化、对延迟敏感场景用 FP8（行业经验）；数据闭环里合成数据占比据中国闭环市场报告从 2023 的约 20–30% 升到 2025 的约 50–60%；Waymo 截至 2025.12 累计 rider-only 行驶超 1.7 亿英里、重伤级及以上事故较人类基准约少九成（其同行评审研究覆盖 5670 万英里，人机口径差异大、人类侧轻微事故常漏报）。
**战例**：特斯拉占用网络（Occupancy Network，CVPR 2022 WAD 主题演讲，Ashok Elluswamy）——纯视觉下放弃『先分类再检测』，改成预测每个体素被不被占+占用流，给任意未知障碍物一个几何兜底，教『长尾未知物要靠类别无关的占用表示兜、别赌检测头认全世界』；Cruise 拖行行人事故（2023.10 旧金山，行人被前车撞入车道后又被 Cruise 车拖行约 20 英尺；NHTSA 因其未完整上报事故处 150 万美元民事罚款，DOJ 另因提交虚假报告处 50 万美元刑事罚金，加州 DMV 吊销其无人驾驶牌照），教『感知/系统失效的尾部代价是人命与合规生死、误漏检指标和事故上报的诚实比 demo 漂亮重要一万倍』。
**悬案**：
- 纯视觉 vs 多传感器融合（含激光雷达）：纯视觉派（特斯拉路线）：相机信息密度最高、成本可规模化，靠占用网络+海量车队数据补深度，多一种传感器就多一处矛盾源（两传感器打架信谁本身是新风险）；融合派（多数 Robotaxi 与中国新势力）：激光给确定的几何真值、恶劣天气和远距更稳，安全冗余不能赌单一模态，公开对比测试里带激光的车在部分极端场景过测更多（2026 仍未收敛；趋势是激光成本下探后中端车也上、行业偏向视觉为主+激光/4D 毫米波做安全冗余的混合，但纯视觉在 ODD 内是否够安全无定论）
- 端到端 E2E vs 模块化感知-规控：端到端派：单网络从像素直接到轨迹/控制，消除模块间误差累积、上限高，特斯拉 FSD v12（2024 初）以单网络替掉 30 万行以上 C++ 规则、UniAD（CVPR 2023 最佳论文）证明感知-预测-规控联合训练增益；模块化派：感知/预测/规控分模块可解释、坏例能归因到具体环节、好做功能安全论证，纯黑盒出了事说不清哪步错、难过车规验证（2024–2026 量产在往端到端走但普遍保留独立安全兜底层（如占用安全网）；可解释性与安全验证仍是端到端最大未决问题）
- 占用网络 Occupancy vs 3D 框检测：占用派：体素级占用+占用流类别无关，能兜未知障碍物、表达不规则与悬空物（吊臂、断树），是长尾安全网；3D 框派：框紧凑、带类别语义和速度、下游规控好用、算力省、标注成熟，占用体素多算力贵、远处稀疏（2025–2026 共识趋向两者并存：3D 框给规控语义、占用给几何安全网，谁主谁辅按 ODD 与算力定，非此即彼少见）
**前沿**：BEV+Transformer（BEVFormer 2022 起）已成多相机感知主流范式、把透视图统一进鸟瞰空间；占用网络/占用预测（Occupancy）从特斯拉 2022 扩散为行业常见的未知物安全网；端到端（UniAD 2023、VAD/VADv2、特斯拉 FSD v12 2024）把感知-预测-规控联合训练，感知边界开始和规控耦合（出现用规划先验反向引导感知往哪看的 perception-in-plan 类思路）；3D 高斯泼溅/世界模型（Gaussian Splatting、RAD/WorldSplat、Waymo World Model 等 2024–2026）做可编辑场景重建与闭环仿真，让长尾事故可批量合成、补真实路采采不到的尾部；视觉语言/VLA 模型（如理想 2025 的 VLA 架构）开始进感知-决策做开放词汇与场景理解（2025–2026）。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：报『我们检测 mAP 95%』当成绩、当作模型好的证明｜强：主动拆误检/漏检的不对称代价、讲清漏检集中在哪类目标哪种天气、把坏例归因到传感器/标注/融合/时序哪一环，谈尾部不谈均值
- 套模板 vs 看情境｜弱：不管什么场景都先想堆激光做融合、或先想上端到端，把某个范式当银弹｜强：先问 ODD 和这类目标漏检的代价→定可接受漏检率与是否要冗余兜底→才反推传感器配置、融合层级和模型档位
- 需提示 vs 自驱｜弱：不追问就只讲离线刷点，不主动谈量化部署、算力预算、失效降级、数据闭环｜强：不用问就把 INT8 量化后的车端延迟/功耗、单传感器失效降级、影子模式回归、corner case 闭环当方案默认组成部分
- 被动 vs 主动｜弱：漏检了就说『等下一代模型/再加点数据就好了』，把长尾当能等来的｜强：在当前模型能力下用多传感器冗余+占用安全网+影子模式主动挖尾部+功能安全论证，把残余风险当能动管理的对象
- 影响自己 vs 影响系统｜弱：只交付一个 mAP 更高的模型、口头说『调好了』｜强：留下可复现的分场景评测集+holdout、坏例归因流程、数据闭环管线和 SOTIF 失效模式分析，让全组在同一套评测和安全框架上迭代
**失分**：报检测 mAP 当成绩、不讲误漏检不对称和长尾召回；把行人和锥桶当同一个召回指标优化；通篇不提车端算力预算和量化部署、拿论文 SOTA 当能上车；只会堆激光做融合、说不清两传感器矛盾时信谁；把端到端当银弹、答不出安全兜底和坏例怎么归因；不提功能安全、分不清 ISO 26262（故障）与 SOTIF（功能不足）；靠离线 benchmark 和路上体感判断好坏、拿不出 holdout 和影子模式
**必考**：
- 多传感器融合的取舍与仲裁（几乎必问） [评价]：背得出『相机+激光+毫米波互补』是失分线；会按场景选前/中/后融合、说清各自时空对齐与算力代价、尤其讲清两传感器打架时的仲裁逻辑和单传感器失效降级，是高手线
- 长尾 corner case 的发现与数据闭环 [创造]：只会说『多采点数据』是失分线；会设计影子模式触发器+坏例自动挖掘+4D 自动标注/重建+从发现到回归验证的闭环、并知道用占用兜未知物，是高手线
- 车端实时性与算力约束下的部署 [应用]：背 TOPS 数字是失分线；能把 backbone/BEV 分辨率/时序帧数按延迟预算砍、讲清 INT8/FP8 量化对精度的影响和算子融合落地、知道算力要分摊给全部传感器，是高手线
- 功能安全与冗余设计 [分析]：只说『加个冗余』是失分线；能分清 ISO 26262 治故障 vs SOTIF 治功能不足、按误检/漏检不对称设计指标、讲清感知失效模式与降级链路和残余风险论证，是高手线
- BEV/占用网络的原理与适用边界 [理解]：能说出 LSS 显式预测深度分布做投影 vs BEVFormer 用可变形注意力采样（无显式深度、有深度歧义）的差别、占用相对 3D 框何时更优、各自算力代价，是高手线；只会背 BEV/Occupancy 名词是失分线
**黑话**：BEV、Occupancy 占用网络、占用流 occupancy flow、LSS/Lift-Splat-Shoot、BEVFormer、3D 检测、多目标跟踪 MOT、ID switch、前融合/中融合/后融合、4D 毫米波、点云、体素 voxel、nuScenes、NDS/mAP、ODD、ISO 26262/ASIL、SOTIF(ISO 21448)、冗余与降级、影子模式 shadow mode、数据闭环、4D 自动标注、corner case/长尾、INT8/FP8 量化、Orin/Thor、端到端 E2E、世界模型、高斯泼溅

**追问链**：「夜间逆光下漏检了一个横穿行人，怎么办」→ ①[通用] 怎么定位是哪个环节的问题、复现这一类坏例？②[职能] 是相机这类场景本身欠曝、还是融合策略在低光下过度信了相机、激光/毫米波那一路有没有兜住？③[岗位] 怎么把这一类（夜间+逆光+横穿）做成数据闭环触发器批量挖回来、用占用网络做几何兜底、并在 SOTIF 框架里把它登记为已知功能不足并论证残余风险可接受？
**定级**：初级筛『能在 BEV/检测框架里训出一个能跑的 3D 感知模型、讲清传感器互补和评测指标的存在』；资深筛『扛得住精度×算力×功能安全的三方账、能定多传感器融合与失效降级策略、能从 0 搭长尾数据闭环、用 ISO 26262/SOTIF 为感知签字担责、知道什么时候不该一把梭端到端/不该只靠纯视觉』。

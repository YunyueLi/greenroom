# 互联网

> 流量生意的总称：广告、交易抽佣、增值服务三种变现，增长见顶后全行业在卷存量效率。
**细分**：游戏／电商／社区内容／短视频直播／本地生活／在线旅游／企业服务 SaaS
**格局**：大盘从增量转存量，超级 App 生态化；变现三板斧=广告／交易抽佣／会员增值；出海是普遍的第二曲线。
**必懂**：DAU/MAU 与留存曲线；LTV/CAC 回收账；A/B 实验文化；算法分发与流量池机制。
**高频行业题**：存量时代增长从哪来／给一个 DAU 跌 10% 的产品做归因／商业化加载和用户体验怎么平衡。
**职能差异**：产品=数据驱动与实验设计是基本功，直觉要能被数据证伪；运营=精细化分层经营替代粗放投放；技术=高并发与成本优化并重，降本是显性 KPI；市场营销=投放 ROI 颗粒度到素材级。

## 细分导读：游戏
> 内容驱动的注意力生意：用一个核心循环把玩家留住，再用养成/付费/社交把时长变成流水；难点是「留存×付费×买量回收」三者要同时成立，缺一环就亏。
**格局**：端游/手游/主机三分，国内手游占大头；变现以 F2P 内购为主（海外混搭买断+订阅+广告 IAA）；大厂寡头（腾讯/网易/米哈游级）+ 独立长尾，版号是国内的硬闸门；出海几乎是所有有产能团队的第二曲线。
**必懂**：核心循环与留存漏斗（次留/7留/30留）；LTV/CAC 与买量回收周期（F2P 的生死线）；付费结构（付费率个位数、收入高度长尾靠鲸鱼）；品类范式（MMO/卡牌/SLG/休闲/二次元各有数值与留存逻辑）；版号、概率公示、未成年防沉迷等合规红线；流水≠利润（买量与渠道分成吃掉大头）。
**高频行业题**：一款新游怎么判断有没有戏、看哪些早期指标／为什么 DAU 很大却不赚钱／买量越来越贵、ROI 打不正怎么办／为什么国内厂都在出海、难在哪／某游戏流水下滑，从版本、数值还是买量先查。
**职能差异**：策划=核心玩法与留存付费一体设计，作品集要能拆解反推设计意图；运营=版本节奏、活动矩阵与玩家生态，既算流水账也共情玩家；数值=经济闭环与付费深度建模；发行/UA=买量 ROI 颗粒到素材级、回收模型的真实手感；技术=性能、热更与防作弊；美术=风格统一与管线协作、资源过性能关。

## 系统策划 · Systems Designer
> 设计玩法系统与成长框架（养成线、循环、规则），对系统留住玩家的能力负责。核心矛盾：系统深度与上手门槛——太浅留不住、太复杂劝退新人。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **核心循环优先**：先把"做什么→获得什么→投入回哪"的核心循环跑通，再挂系统；用它你不会做出一堆没有回收出口的散装系统。
- **系统是目标供给**：每个系统本质在制造"下一个想要的东西"，不产生欲望的系统是装饰。
- **横向耦合还是纵向养成**：新系统是接进已有循环（耦合）还是另起一条养成线（增量），错配会撕裂经济。
- **提案三段式**：任何系统提案先说要解决的玩家 / 业务目标，再说机制，最后说怎么用数据验证。
**基准线**：校招系统提案题占笔试很大比重（约四成，行业经验）；核心循环时长（单局 / 单日）是系统的节奏锚；次留 / 7 留 / 30 留是系统有效性的终判。
**战例**：《原神》圣遗物——用随机词条把养成做成长期追求，争议但极有效（教"用随机性制造长尾目标"） ／ 体力系统——经典节奏闸门，控制内容消耗速度（教"系统也是节奏调节器"）。
**悬案**：
- 系统深度 vs 上手门槛：硬核派认为深度系统是留存护城河；大众派认为复杂系统是新手流失主因；取决于目标人群与品类。
- 系统驱动 vs 内容驱动：系统型可长线运营但易数值膨胀，内容型体验好但产能压力大；服务型手游与买断制各执一端。
**前沿**：AI 生成内容（关卡 / 任务 / 数值）正在松动"系统产能"的约束；UGC（玩家造玩法）成为新的留存增量方向（2024-2025）。
### 怎么考
**分水岭**：强候选人讲系统先讲它在核心循环里的位置和回收出口、能讲清"砍掉哪个子系统不伤主体验"；弱候选人罗列系统功能、讲不出系统间的耦合与经济影响。
**失分**：把系统设计讲成功能清单；做了系统讲不出它制造了什么玩家欲望；不提数值与经济的连带影响。
**必考**：核心循环与系统耦合；养成线与经济出入口；提案三段式（目标-机制-验证）；竞品系统拆解功底。
**黑话**：core loop、目标供给、养成线、横向耦合 / 纵向养成、数值膨胀、回收出口、节奏闸门。
**高频题**：拆解你最熟的游戏的核心循环／设计一个赛季成长系统／给一个老游戏加新系统、怎么不破坏现有经济。
**追问链**：「设计赛季成长系统」→ ①[职能] 这系统接进哪个循环、回收出口在哪？②[岗位] 老玩家数值膨胀怎么消化？③[岗位] 怎么验证有效、调参看什么指标？
**定级**：初级筛"能把一个系统设计自洽"；资深筛"能为整个系统群的经济与节奏负责、敢砍系统"。

## 数值策划 · Numerical Designer
> 用数学建模搭游戏的经济与成长：伤害公式、成长曲线、投放回收、付费深度。核心矛盾：付费深度与公平体验——氪度不够不赚钱、太狠伤口碑和留存。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **一切是经济闭环（产出-消耗-沉淀）**：每种资源都要有产出口、消耗口、沉淀池，三者失衡就通胀或枯竭；用它你能预判"发了新资源三个月后崩盘"。
- **成长曲线是体验节奏**：先定"玩家每个阶段该有多强"的体验曲线、再反推公式，不是从公式硬算。
- **付费深度分层（首充 / 月卡 / 小R / 大R / 鲸鱼）**：每层要有不同的"想要"，一刀切要么逼走小R要么喂不饱大R。
- **数值膨胀是必然、要预留通胀通道**：长线数值必涨，提前设计回收旧数值 / 重置赛道的机制，别等崩了再救。
**基准线**：付费率（国内手游约 2-5%）、ARPPU、LTV、首充转化是核心盘口；7 日 / 30 日留存与付费曲线是数值健康的体检（具体随品类差异大）。
**战例**：《原神》圣遗物 / 《阴阳师》御魂——把养成做成概率长尾（教"随机性是付费深度的引擎、也是口碑的雷"） ／ MMO 的转生 / 数值重置——经典的数值膨胀通胀通道。
**悬案**：
- 概率公开 vs 黑盒：公开提升信任与策略深度，黑盒保护付费设计；与各地概率公示法规直接相关。
- 强养成 vs 弱养成：强养成长线收入高但劝退非R，弱养成友好但变现弱；与品类和市场相关。
**前沿**：概率公示法规收紧，逼数值从"信息差变现"转向"体验变现"；AI 仿真 / 自动调参开始辅助平衡（2024-2025）。
### 怎么考
**分水岭**：强候选人张口是经济闭环和分层付费、能现场推一条成长曲线并说明体验意图、讲得出一次数值救火（通胀或崩盘）；弱候选人只会套现成公式、讲不出数值背后的体验与经济意图、没碰过线上调参。
**失分**：把数值讲成"调表格"；只讲怎么让玩家氪、不讲对留存口碑的代价；资源各自为政没有闭环；不会用 Excel / 仿真验证。
**必考**：经济闭环（产出 / 消耗 / 沉淀）；成长曲线与战力体系；付费深度分层与定价；数值膨胀治理 + Excel 建模实操。
**黑话**：经济闭环、产出 / 消耗 / 沉淀、ARPPU / LTV / 付费率、成长曲线、战力公式、数值膨胀、概率长尾、首充 / 月卡 / 大R。
**高频题**：现场设计一条角色成长曲线／一个新资源上线后通胀了怎么救／某游戏付费率低、你从数值侧怎么排查。
**追问链**：「成长曲线怎么设计」→ ①[岗位] 先定体验节奏还是先定公式？②[岗位] 这条线的回收出口和通胀通道在哪？③[职能] 怎么灰度验证、看哪些指标？
**定级**：初级筛"能把一套数值算自洽"；资深筛"能为全局经济与付费结构负责、救过盘、平衡过线上"。

## 战斗策划 · Combat Designer
> 设计战斗的手感、技能机制与平衡：帧数据、打击感、强度曲线、职业平衡。核心矛盾：爽快手感与公平平衡——手感靠"过载"反馈、平衡靠"克制"，天然打架。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **手感是帧的艺术**：打击感的本质是帧数据（前摇 / 命中 / 后摇 / 硬直）+ 反馈（顿帧 / 震屏 / 音效）的精确编排，不是堆特效；用它你能定位"这招为什么打着不爽"。
- **平衡看分布、不看单点**：一个技能强不强要放进 build / 职业 / 版本的整体分布看，孤立调单点会连锁失衡。
- **强度 ≠ 体验**：T0 不一定好玩、冷门不一定弱；既要管胜率也要管"被玩的乐趣"。
- **数据驱动调参 + 手感主观把关**：平衡靠胜率 / 使用率 / ban 率等数据，但手感是数据测不出的、要靠设计师体感守门。
**基准线**：竞技向角色胜率健康区间约 45-55%、使用率 / ban 率是平衡核心盘口；帧数据（前摇 / 硬直）是手感的可量化抓手（具体随品类差异大）。
**战例**：格斗游戏的帧数据体系（街霸 / 拳皇）——手感工程化的鼻祖（教"手感可量化、可调"） ／ MOBA 的版本平衡（LoL / 王者）——数据 + 小步快跑迭代（教"平衡是持续运营、不是一次设计"）。
**悬案**：
- 数据平衡 vs 手感直觉：数据派认为胜率使用率说话，手感派认为强度数据掩盖体验问题（胜率 50% 却打着难受没人玩）；顶尖战斗策划两者都要。
- 强度统一 vs 差异化：大一统平衡公平但同质，鼓励 OP / 克制循环有记忆点但易失衡；竞技与娱乐取向不同。
**前沿**：AI 对战 / 自动仿真开始预测改动影响；动作手感的"可解释性"（把体感拆成可调参数）在被工具化（2024-2025）。
### 怎么考
**分水岭**：强候选人能把"不爽"拆到帧 / 反馈层并给改法、把一个技能放进版本分布里谈平衡、讲得出一次平衡救火（OP 角色或版本崩坏）；弱候选人只会说"手感不好 / 这个太强"、给不出可调的具体参数、孤立调单点。
**失分**：把打击感等同于特效音效堆料；平衡只盯单个技能数值、不看分布；只讲数据不讲手感（或反过来）；没碰过线上平衡迭代。
**必考**：帧数据与打击感机制；技能 / 职业平衡框架（胜率 / 使用率 / ban 率）；强度曲线与 build 体系；数据驱动调参 + 手感把关。
**黑话**：帧数据、前摇 / 后摇 / 硬直、顿帧 / 震屏、打击感、胜率 / 使用率 / ban 率、强度分布、OP / 克制、build。
**高频题**：玩家反馈某技能"打着不爽"、你怎么排查和改／某角色胜率过高、你怎么调才不连锁崩／设计一个新职业、怎么进版本不破坏平衡。
**追问链**：「角色胜率过高怎么调」→ ①[岗位] 先动数值还是动机制、为什么？②[岗位] 怎么避免一调就连锁失衡？③[职能] 赛季内怎么验证改对了？
**定级**：初级筛"能调一个技能 / 角色的手感与强度"；资深筛"能为整个战斗系统的手感基调与版本平衡负责、救过版本"。

## 关卡策划 · Level Designer
> 把机制装进具体空间，对"走一遍爽不爽、迷不迷路、节奏对不对"负责。核心矛盾：作者意图与玩家自由——你心里有条"该这么走"的金路径，但大部分玩家会乱逛、卡住、走反方向，引导太硬像被牵着鼻子、太软就迷路弃游，得在玩家以为是自己选的前提下把他领到你想要的地方。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **玩家物理参数是尺子**：先量死跳跃距离/移动速度/台阶高度/视高，整张图的间距、掩体、落差全按这把尺子摆；不锚物理参数，关卡要么处处过不去要么白给。但《关卡设计手册》同时警告"metrics 不是魔法、量不出好体验"——参数保证能走通，好不好玩还得靠盲测。
- **金路径 vs 真实轨迹**：金路径（critical/golden path）是你设计的理想动线，真实轨迹是玩家实际走出来的热力图；只盯金路径不看回放，就会把'我以为很清楚'当成'玩家真看懂了'——设计师对自己的图早脱敏，这道偏差只能拿真人补。
- **先 blockout 后美术**：白模阶段反复跑、反复改空间和节奏，确认对了才上美术；白模改一刀几乎免费、终版美术返工极贵，关卡死法第一名就是没验证就上料。Psychonauts 2 甚至在编辑器里做跳跃弧线预览，省得反复进游戏试跳。
- **张弛曲线**：把一关画成强度起伏图——遭遇/解谜的高峰后必须留探索或喘息的低谷做存档点；只堆高峰没有谷，玩家疲劳麻木，全是谷又松散无聊。存档点是节奏闸门不是补给站：放在高峰前给"无退路"压力，放得太密反而泄掉紧张感。
**基准线**：关卡设计第一锚=玩家物理参数（移动速度/跳跃距离/台阶高度），全图间距都从它推（《关卡设计手册》通识，但该书也强调 metrics 不能替代盲测）；多人对战 PvP 经验值=WorldOfLevelDesign 的 CS 系列经验法则：双方约 5-12 秒到达 chokepoint、防守方略早几秒以先占位（不让进攻方在防守方刚到位时直接冲过），具体随地图尺寸/移速差异大；"每条 lane 一个 chokepoint、全图 3-4 个""对称图攻防 50%±5%"属设计师经验区间、非硬标准，随品类/版本浮动；难度调参常看通关时长与平均尝试次数，但这是诊断信号不是验收线，最终看盲测里玩家卡没卡、弃没弃。
**战例**：《黑暗之魂1》互联地图＋篝火节奏——遭遇高压段后用篝火与回环捷径给喘息，篝火间距制造"无退路点"的张弛；玩家社区普遍批评 DS3 部分篝火挨太近（如某些 Boss 后十秒脚程内又一个）削弱了带魂的紧张感与 ebb-and-flow——这是玩家讨论而非官方设计准则，但正好教"存档点是节奏闸门不是补给站"。／无声引导优于 UI 箭头的通用做法（光/对比/地标 weenie）——"weenie"出自迪士尼幻想工程（Walt 拿热狗引狗的典故，指远处可见、勾人走过去的视觉磁石，如睡美人城堡），被关卡设计沿用；Mirror's Edge 用红色高亮可交互的攀爬物、《最后生还者》用光与色块指路，都是"在玩家以为自己选的前提下领他走"。（注：常被传的"《古惑狼》打光照亮该走的路"系误传——Andy Gavin 自述靠的是走廊式几何遮挡＋摄像机沿轨＋角色配色辨向，不是用灯光指路。）
**悬案**：
- 数据调参 vs 设计师手感：数据派：埋点热力图看死亡点/卡关点/绕路，玩家身体最诚实，凭感觉只是设计师自嗨；上线后靠遥测持续调平衡；手感派：遥测只在有量玩家后才有、单机首发更是没数据，且业界working consensus是"数据擅长发现问题、不擅长设计解法"，过度优化会磨平作者风格做出最大公约数的平庸图（持续(2020s)）
- 对称竞技图 vs 攻防不对称图：对称派：镜像图天然攻防平衡、好调，但场场体感雷同、缺记忆点，且对称未必公平（出生朝向/光照/先手仍有偏差）；不对称派：CS/Valorant 式攻防分边能做出独特地图性格与战术深度，但平衡极难、要靠版本反复调 chokepoint 和点位，且容易长期一边倒（持续）
**前沿**：AI/PCG 生成基础布局松动"关卡产能"约束，关卡策划重心从手搓几何往"定规则＋遥测调参的闭环"和精修关键节点移；UGC 地图工坊把关卡变持续增量内容，社区数据反过来喂官方调参（2024-2025）。
### 怎么考
**分水岭**：强候选人讲关卡先报玩家物理参数、再讲金路径怎么靠光/地标/掩体无声引导、能拿热力图说"这里玩家集体绕路所以我改了什么"，并讲清砍哪段不伤整体节奏；弱候选人只描述"这里很酷有个大场面"、讲不出引导手段也讲不出怎么验证、把美术效果当关卡设计。这岗直觉部分可信——空间好不好走当场能体感，但"我以为很清楚"的引导和难度曲线必须拿真人盲测纠偏：设计师对自己的图早已脱敏（每个点位、敌人刷新都背下来了，感受不到难度也感受不到迷路），自己玩一百遍只会越来越顺。
**失分**：把关卡讲成场景美术（"这里光影氛围特别好"）；描述空间但讲不出怎么引导玩家、玩家凭什么往那走；没在白模阶段验证、直接谈成品；难度只会说"做难一点/简单一点"，给不出可调参数（敌人数量/血量/掩体间距/检查点密度）；自己不迷路就断定玩家不迷路、把通关数据当验收而不去看真人盲测。
**必考**：玩家物理参数与关卡尺度的关系；金路径/关键路径与无声引导（光/地标/对比/掩体）；blockout 白模迭代纪律；难度曲线与张弛节奏（含存档/喘息点）；遭遇编排（敌人组合/节奏/掩体布局）。
**黑话**：blockout/greybox 白模、critical path/golden path 金路径、weenie/地标、sightline 视线、chokepoint 卡点、affordance 可供性/可交互暗示、心流（challenge-skill 平衡）、pacing/ebb-and-flow 张弛、heatmap 热力图、metrics(玩家物理参数)。
**高频题**：拆解你最爱的一关、它的引导与节奏怎么做的／给定一套玩家移动跳跃参数、设计一段平台跳跃或一个遭遇／一张多人对战图怎么平衡攻防与视线／玩家在某处集体卡关，你怎么定位和改。
**追问链**：设计一段战斗遭遇 → ①[通用]这段在整关节奏曲线的哪个位置、前后是高峰还是喘息？②[职能]玩家怎么知道该往哪打、靠什么引导（光/地标/掩体）而不靠 UI 箭头？③[岗位]给定移动速度和跳跃距离，掩体间距和敌人站位具体怎么摆、太难了你先调哪个参数（敌人数/血量/掩体密度）、靠通关时长和尝试次数定位还是直接看盲测录像？
**定级**：初级筛"能把一段空间做得好走、引导清楚、能跑通一个遭遇"；资深筛"能为整关甚至整张图的节奏曲线与攻防平衡负责、看热力图诊断并迭代、敢砍场面保节奏、能定义白模到终版的关卡生产流程"。
**来源**：All Things Andy Gavin《Making Crash Bandicoot》part 3-4（2011，证伪打光误传、走廊几何+摄像机+配色） / The Level Design Book: metrics·critical path·flow·playtesting（玩家物理参数为锚但\"metrics 不是魔法\"、金路径术语、设计师脱敏） / WorldOfLevelDesign CS chokepoint 六原则（5-12 秒经验法则、双方几乎同时到、防守略早占位） / 迪士尼幻想工程 weenie 词源（Walt 热狗引狗典故，theoryofthemeparks/Wikipedia 2015+） / DS3 篝火过近批评=玩家社区讨论（Steam/GameFAQs，非官方准则） / Ian Schreiber 著《Game Balance》《Game Design Concepts》（无法确证其\"框定\"数据vs直觉辩论，已删归属）

## 玩法策划 · Gameplay Designer
> 定义"这游戏好玩在哪个核心机制"、对核心体验的原型与手感负责。核心矛盾：新奇 vs 顺手——一个动词足够新才有记忆点，但必须三分钟内会用、且禁得起几百小时重复，才撑得起一款游戏；越追新奇越容易做出酷但学不会、或第一小时惊艳第十小时就腻的东西。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **动词优先**：先定玩家反复做的那个核心动词（射/建/潜行/合成），再谈关卡数值剧情；用它你能一句话说清一款游戏，并立刻看穿那些'系统列了一长串、却说不出玩家此刻在干嘛'的项目空在哪。
- **机制创造体验（不是堆功能）**：先锁定要给玩家的那一种情绪/感觉，再反推哪条规则能逼出它——Doom 砍掉回血、把'回血'绑死在'处决'上，玩家想活就得往前冲；用它你做的是体验的因，不会攒出一堆各自合理、合起来没感觉的功能。
- **深度 vs 复杂度**：深度=玩家能做出更好决策的空间，复杂度=决策前先得背多少规则（Rosewater 的 elegance＝高深度低复杂度，即深度与复杂度之比）；用它你会优先去删规则、把省下的复杂度预算换成深度，不会用'规则多'伪装'有深度'。
- **灰盒先验（fun first）**：核心乐趣必须在无美术的灰盒原型里就成立、上手就好玩，再投美术和内容；不用它你会被精美包装骗过、把'看着爽'当'玩着爽'，拖到垂直切片才发现核心循环不成立——那是最贵的推倒重来。
**基准线**：游戏拆解/体验分析是玩法岗面试主轴，作品集里的拆解反推、现场出一个核心动词让你设计玩法、'没美术怎么验证好玩'这三类题命中率很高（国内校招/社招经验，2024-2025，具体占比随公司差异大，不必背死数字）；核心循环是否成立看灰盒原型的上手手感能直接体感，'耐不耐久'要靠核心循环结构判断、留存终判才看次留/7 留（随品类差异大）；可援引的成形 doctrine＝Halo 的 3 秒/30 秒/3 分钟三层嵌套循环（源自 Bungie 2002 GDC AI 演讲，Griesemer & Butcher）。
**战例**：Halo「30 秒乐趣」——遭遇一队敌人→偷袭近战一个→丢雷炸一群→清残敌，这 30 秒做爽，再换地形/武器/敌人组合无限复用；它真正的结构是 3 秒（开一枪/躲一颗雷）套在 30 秒（一场遭遇）套在 3 分钟（一段任务），每层都在变所以不腻（教"先打磨最小核心循环、再靠变量分层扩展，核心不爽包装救不了"，源自 Bungie 2002 GDC AI 演讲，'30 秒乐趣'这句话由 Griesemer 2004 后说红）／Doom 2016 推进式战斗——砍掉换弹与被动回血、血和弹药主要靠处决/电锯从敌人身上抠，用一条资源规则把"别苟、往前冲"逼成唯一活法（教"用一条机制规则塑造玩家行为与情绪，不靠说教不靠堆数值"，id Software，GDC 2018'Embracing Push Forward Combat in DOOM'）。
**悬案**：
- 系统化涌现 vs 手工编排：涌现派：给少量正交规则让它们自由相乘，产生设计师没预设的解法（旷野之息化学引擎、模拟经营/沙盒），耐玩、长尾、复玩高，但乐趣下限不可控、可能出现没人想要的退化解；编排派：手工设计每段体验、保证节奏与情绪精确可控（神秘海域、顽皮狗式叙事动作），单次体验上限更高、不赌玩家自己玩出乐趣，代价是产能贵、复玩低；二者产能与可控性此消彼长，按品类与团队工艺取舍（长期争论，2023-2025 因 UGC/沙盒/造物玩法走红再起）
- 深度 vs 上手门槛：硬核派：深度机制本身是核心乐趣与长留护城河，门槛磨平往往会顺手把深度也磨掉（只狼/魂系、硬核策略）；易上手派：上手复杂是新手流失的头号原因，门槛每高一档先在漏斗顶端劝退一批（休闲/大众向）；同一机制砍到多浅没有标准答案，取决于目标人群、品类与变现模型（贯穿争论，2024 仍无定论）
- 先做着玩 vs 先把玩法写清：原型派：玩法是玩出来的不是写出来的，乐趣只能在可玩原型里验证，文档写得再漂亮也测不出手感；文档派：核心机制不先在体验文档里把目标与边界讲清就开做，团队各做各的、迭代散乱、改方向代价更大；现实是两条工作流按团队规模与品类大量并存（小团队偏原型先行，大项目跨工种协作离不开文档）（持续分歧，无统一定论）
**前沿**：2024-2025 AI 把原型迭代从天压到小时，灰盒试错成本骤降，"先快速验证一个动词好不好玩"门槛大降，但这放大了'会找乐趣'的人价值、贬低了'只会把想法做出来'的人——能验证的多了，敢判断哪个值得做的人更稀缺；同时 UGC/玩家造玩法（地图编辑器、Roblox/UEFN 式）成新留存增量，玩法策划的活从"设计玩法"扩到"设计一套让玩家自己造出好玩法的规则与工具"，考核点从'你的玩法好不好玩'变成'你给的积木能不能让普通人拼出好玩的东西'。
### 怎么考
**分水岭**：强候选人张口先说核心动词和它要制造的那一种情绪、能把"好玩"拆到具体机制规则并讲清砍掉哪一条不伤核心（甚至更好）、拿灰盒原型而非美术 demo 论证乐趣成立、拆解游戏时反推得出设计意图（设计师在解决哪个体验问题、为此付了什么代价）；弱候选人差在：罗列功能与系统当成设计、"好玩"只停在形容词（"很爽很有趣"）给不出可调的机制旋钮、用美术/题材包装掩盖核心循环空洞、拆解只复述"它有哪些玩法"说不出"为什么这么设计"。这岗直觉部分可信——灰盒上手手感几分钟内就能体感对错（比系统/数值靠留存才反馈快得多），但"耐不耐百小时重复"骗不过短测、首玩爽不爽尤其会骗人，要靠核心循环的结构（每层有没有持续变化、决策空间会不会随时间坍塌）来判断，别只信第一次手感。
**失分**：把玩法设计讲成功能清单或玩法模式罗列；"好玩"只给形容词、拆不到具体机制规则与可调参数；分不清自己负责的核心动词与系统策划的养成框架、战斗策划的手感平衡、数值策划的经济，越界抢答暴露不懂边界；拆解游戏只复述"它有什么玩法"、讲不出"为什么这么设计、设计师在解决什么体验问题、付了什么代价"；只靠美术/题材谈乐趣、回避灰盒阶段核心循环是否成立；把首玩爽不爽当成耐玩的证据。
**必考**：核心动词与最小核心循环（3 秒/30 秒/3 分钟分层）；机制如何创造体验/情绪（因果链，不是配套数值）；深度 vs 复杂度与"删规则换深度"；灰盒原型与 fun-first 验证流程；与系统策划（养成框架）、战斗策划（手感平衡）、数值策划（经济）的职责边界。
**黑话**：核心动词、core loop、30 秒乐趣、机制创造体验、深度 vs 复杂度、elegance（优雅）、涌现 vs 编排、灰盒/graybox、垂直切片、find the fun、推进式战斗、玩家心流、最小可玩原型、退化解（dominant strategy）。
**高频题**：拆解你最熟的一款游戏的核心玩法、反推设计意图（几乎必考）／给一个核心动词（比如"重力翻转/时间倒流"）现场设计一套玩法／你设计的玩法怎么在没美术的灰盒阶段验证好不好玩／这个机制好玩、但玩家三分钟学不会、你怎么改。
**追问链**：「给重力翻转设计一套玩法」→ ①[通用] 你想给玩家哪一种核心体验/情绪、这个动词凭什么撑得起一款游戏？②[职能] 这套玩法接进什么核心循环、靠哪几个变量做出几百小时不腻的扩展、哪种组合会坍塌成无脑最优解（退化解）你怎么防？③[岗位] 灰盒阶段怎么验证它真好玩、新手三分钟学不会时你先动机制还是先动引导、判断依据是什么？
**定级**：初级筛"能围绕一个核心机制做出自洽且上手好玩的玩法、拆解游戏反推得出意图"；资深筛"能定义整款游戏的核心乐趣基调、在灰盒阶段判断核心循环成不成立、敢砍掉做了很久但被验证不好玩的方向、为'find the fun'这件全项目最不确定的事负责并扛住不确定性"。
**来源**：GDC 2002《The Illusion of Intelligence: The Integration of AI and Level Design in Halo》(Griesemer & Butcher，3s/30s/3min 嵌套循环出处) / Engadget 2011 Griesemer 访谈(澄清'30 秒乐趣'为后续说红、非 2002 doctrine) / GDC 2018《Embracing Push Forward Combat in DOOM》(id Software，推进式战斗与处决资源循环) / Mark Rosewater 关于 elegance＝depth／complexity 的设计文论(公开博文/访谈) / GDC 2017《Change and Constant — Breaking Conventions with The Legend of Zelda: Breath of the Wild》(化学引擎/multiplicative gameplay/涌现) / Jesse Schell《The Art of Game Design》(find the fun／原型验证乐趣) ／ 业界 graybox 通行实践

## 商业化策划 · Monetization Designer
> 设计「卖什么、怎么让玩家心甘情愿买、且不伤体验」的付费玩法（付费点、商品体系、卡池/礼包/通行证、转化漏斗）。核心矛盾：变现强度与体验信任——压得狠短期流水好但磨掉留存口碑、压得松玩家爽却养不活项目，两端必须同时握住。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **付费点是接住摩擦，还是制造新欲望**：一个付费点要么帮玩家越过他此刻正卡着的那道坎（差一口气、限时要错过），要么凭空制造一个新欲望硬塞——分辨的操作抓手是：把这个 offer 撤掉，玩家的局内行为会不会变？不会变就是硬塞，转化低且招骂。用它你能在评审时一眼判出哪些付费点是真需求、哪些是为了凑商城数量。
- **分层供给（小R喂得起，鲸鱼喂得饱）**：非付费/小R/中R/大R/鲸鱼每层要有不同的『想要』和买得起的台阶：首充转化器接小白、月卡养中间、专供 bundle 喂鲸鱼；一刀切的商品要么逼走小R要么喂不饱鲸鱼。用它你能解释『为什么同一件东西要拆成几个价位卖』——头部少数玩家在多数 F2P 里贡献了大头收入（top 10% 量级上贡献过半，行业经验、随品类差异大），喂不饱直接掉大头。
- **框架定价（锚定·诱饵·沉没成本）**：同一个商品卖多少由它旁边摆什么决定：先摆个贵的当锚、放个性价比明显差的诱饵把人推向你想卖的档、用通行证进度条把已投入变成『不买就亏』；用它你能解释『为什么礼包要做三档而不是一档』，不用它就只会标单价。
- **体验代价滞后、流水反馈即时——所以单看本周必高估**：每个变现动作两本账同时记：这次卖了多少（即时可见），磨掉了多少留存和信任（滞后数周才显）。关键不是『也算一下体验』，而是认清这两个反馈的时间差会系统性骗你——验证一个逼氪活动到底赚没赚，要用同期可比队列（给/不给这个 offer 的玩家）看 N 周后的留存与后续付费深度差，而不是活动后看流水曲线事后归因。用它你会提前预判『这周冲了流水、三周后留存塌』。
**基准线**：付费率（F2P 手游普遍个位数百分比，多数玩家从不付费；中重度 RPG/策略偏高、休闲偏低，行业经验、随品类与买量结构差异大）；鲸鱼集中度=付费高度长尾，Swrve 早年大样本测得付费玩家 top 10% 约贡献 64% 收入、top 1% 约 29%（具体比例随游戏与年份波动，别当固定常数）；首充后留存=首次付费玩家 D7/D30 留存通常是非付费的 2-3 倍（行业共识，所以首充转化是头号盘口）；通行证已成中重度标配的确定性变现轨（Fortnite 通行证约 950 V-Bucks/季≈$8，累计具体金额未官方披露）；ARPDAU/ARPPU 按品类差异极大，无统一基准。
**战例**：Fortnite 通行证——把『开箱抽』换成『买进度+靠玩解锁专属外观+赛季限时』，2022 年 FTC 就 dark patterns 与误扣费对 Epic 开出 $245M 退款令（另叠 $275M COPPA 罚款，合计 $520M）；通行证在欧美+主机+监管收紧的语境下成为新范式（教『用 FOMO+确定性回报替代赌博式随机，既变现又躲监管和口碑雷』）／原神卡池保底——用概率长尾+保底（小保底/大保底/歪了必中）把抽卡做成『可预期的长期追求』，争议极大但变现极强（教『保底是把随机付费从赌博拉回可控承诺的关键机制，也是口碑的雷区』）。
**悬案**：
- 首充/起步包：转化优先 vs 客单价优先：转化优先派：低价首充（¥6/¥1）的目的是把人从『非付费』推过付费门槛，首充后留存翻 2-3 倍、终身价值才打开；被买量和日活 KPI 逼着，多数团队默认先用诱人低价快速成交。；客单价优先派（Julian Runge 等，Deconstructor of Fun）：只盯转化会把首充定得过低、给本愿出 ¥30 的人只推 ¥6，低价锚死了玩家对全盘商品的预期，反而压住后续付费深度；该按『最高愿付价』分层定价而非一刀切低价。两边都对，差在你优化的是漏斗入口（转化率）还是终身价值（LTV）。（2024）
- 随机付费（卡池/开箱）vs 确定付费（通行证/直购外观）：随机派：卡池/开箱的付费深度最高、长尾收入最强（鲸鱼为概率买单），保底+概率公示能把它做得相对体面，东亚中重度市场至今靠它撑大头。；确定派：开箱在欧美被定性为赌博式深色模式、监管收紧（2022 FTC Epic 案、多国立法讨论），通行证/直购把『花钱=确定拿到』口碑更稳。真实情形不是『谁取代谁』——两者按付费深度分层共存；Fortnite 转向通行证是欧美+主机平台+监管这个特定语境下的选择，不能套成『行业整体已迁移』，亚太中重度的卡池收入照样最高。取决于品类、市场与对监管风险的胃口。（2022）
- 限时/首充/连充等催买机制用到多狠：强运营派：限时折扣、每日礼包、连充奖励是转化的高效杠杆，制造稀缺与紧迫能显著拉付费，live ops 标配。；克制派+合规压力：这些正是『深色模式』和监管的靶心——中国 2023《网络游戏管理办法（草案征求意见稿）》明确点名拟限制每日登录、首充、连充等诱导性奖励（后撤回未落地，但定调了方向）；用太狠短期冲量、长期磨信任且贴合规红线。强度到哪是这岗每天在拍的板，没有标准答案。（2023）
**前沿**：概率公示与防沉迷合规重塑设计空间：中国 2016 文化部要求抽卡/合成概率必须公示（落地形式有讨论，合规程度参差），2019 起未成年充值分档限额（8 岁以下禁止充值、8-16 岁单次≤¥50 月≤¥200、16-18 岁单次≤¥100 月≤¥400），把变现从『信息差』逼向『体验价值』；欧美开箱监管+FTC Epic 案（2022）推动部分品类往通行证/直购外观倾斜。AI 侧：动态/个性化定价与实时千人千面发券开始试水（按行为给非付费玩家低价入口、给鲸鱼专供 bundle），厂商宣称能抬 ARPU（具体幅度多为厂商口径、缺独立验证），但价格歧视的公平与合规争议同步放大（2024 起）。
### 怎么考
**分水岭**：强候选人讲一个付费点先讲它接住了玩家哪个『心动时刻』（或撤掉它行为会不会变）、卖给哪一层、为什么定这个价（锚定/诱饵/分层怎么摆），以及怎么用同期可比队列而非事后流水曲线验证有没有伤体验；能讲清和数值策划的分工（数值给经济模型与付费深度，我设计购买场景的玩法与包装）、能讲出一次『冲了流水却磨了留存』的取舍或救火。弱候选人把商业化讲成『多上几个礼包、把数值调贵点逼氪』，分不清自己和数值策划的边界，只盯流水不提体验代价与留存连带，给不出漏斗各环节的转化抓手。这岗直觉部分可信但危险：付费爽点的直觉有用，但『冲流水』的反馈即时、『磨留存口碑』的代价滞后数周才显，只看短期数字的直觉会系统性高估收益、把项目带向竭泽而渔。
**失分**：把商业化等同于『加礼包、调贵数值逼氪』；分不清和数值策划的边界（张口就推伤害公式、成长曲线，那是数值的活）；只报流水不讲对留存口碑的代价、不会用可比队列把体验代价量化出来；设计了付费点讲不出它接住玩家哪个欲望、卖给哪一层；不知道首充转化是头号盘口、不懂鲸鱼长尾结构；对概率公示/未成年充值分档限额等合规红线没概念，张口就来开箱诱导玩法。
**必考**：付费点设计（接住玩家正卡着的摩擦或制造新欲望、不是凭空插商城）；分层供给与首充转化漏斗（非付费→小R→鲸鱼，每层不同商品与台阶）；框架定价（锚定/诱饵/沉没成本，多档而非单价）；卡池/礼包/通行证三类玩法的账与适用场景；体验信任红线与合规（概率公示、未成年分档限额、深色模式风险）。
**黑话**：付费点、心动点/付费动机、首充转化器、付费率/ARPPU/ARPDAU/LTV、分层（小R/中R/大R/鲸鱼）、转化漏斗、价格锚定/诱饵定价、软硬通货双轨、保底（小保底/大保底）、通行证（免费轨/付费轨）、专供 bundle、限时/FOMO、深色模式、概率公示、可比队列/A-B 验证
**高频题**：拆一款你熟的游戏的整套付费结构（付费点、商品分层、靠什么赚大头）／给一款上线半年、付费率偏低的游戏设计首充转化方案／某个逼氪活动这周流水冲高、下周留存掉了，你怎么排查和补救／设计一档赛季通行证，免费轨和付费轨怎么分、定价怎么定。
**追问链**：题：「给一款付费率偏低的游戏设计首充转化方案」→ ①[通用]你先看哪些数据定位问题出在没人迈出第一步、还是付完不留？②[职能]这个首充礼包卖给哪一层、放在玩家哪个时刻弹出、为什么定这个价（怎么用锚定和诱饵）？③[岗位]怎么验证它真拉了转化而不是只把本来要花更多钱的人锚到低价——用同期可比队列看哪几个漏斗指标、会不会伤后续付费深度？
**定级**：初级筛「能把一个礼包/一档通行证设计自洽，讲清卖给谁、为什么这个价、放在哪个时机」；资深筛「能为整盘付费结构（首充→月卡→鲸鱼）的转化漏斗和体验红线负责，调过线上漏斗、扛过一次因变现太狠的口碑反噬并救回来」。
**来源**：FTC 2022 Epic Games 和解（$245M dark patterns 退款 + $275M COPPA = $520M）：ftc.gov 新闻稿 + Orrick/NPR 2022-12；鲸鱼集中度 top10%≈64%/top1%≈29%：Swrve 报告经 GameDeveloper/MCV 转述；中国未成年分档限额 2019（8 岁以下禁充/8-16 单次50月200/16-18 单次100月400）：GameDeveloper 2019 报道；2016 概率公示及实施 sub-optimal：Cambridge Behavioural Public Policy 研究；首充 2-3x 留存与转化&lt;10% 为业内共识：mobilefreetoplay/solar-engine；Fortnite 通行证约 $8/季：Business of Apps；首充转化 vs 客单价辩论：Deconstructor of Fun（Julian Runge）。年份均已标注。

## 剧情策划 · Narrative Designer
> 让玩家在意一个虚构世界和一群虚构人的设计者，靠把故事织进玩法、演出、场景来落地，而不是靠多写文本。核心矛盾：叙事是全游戏最可跳过的东西（玩家能一路跳过对话直冲战斗），却要做到不打断节奏的同时让人记住——既要文本能被略过也不崩，又要让在意的人能挖到底。
**细分**：游戏
**职能**：产品
### 怎么想
**心智模型**：
- **剧情策划不是编剧**：编剧管写什么（剧情、人物、台词），剧情策划管怎么让它被玩家体验到（用机制/关卡/演出/UI 把故事递出去）。用它看到：一个岗只会改台词、说不出靠哪种载体递叙事，就是把自己做成了文案外包。
- **叙事的三种载体（按可跳过性排序）**：剧情演出（authored，最强但最贵、最打断节奏、可被跳过）、环境叙事（场景道具自己讲，不占玩家操作、不可跳过）、系统/涌现叙事（玩法行为本身产生故事）。用它看到：把所有重量压在过场动画上的方案，玩家一跳过就什么都没剩；这三层的配比就是剧情策划真正在排的东西。
- **叙事预算 = 玩家在有 agency 之前的耐心**：玩家肯花在读/听上的时间是稀缺资源，最危险的不是总量，是花在哪——开场长 CG、不可跳过的解释性对话，是在玩家还没拿到操作权时就透支这份预算，留存悬崖往往就埋在这里。用它看到：会把一坨世界观切成能被玩家行为（进门/拾取/触发）触发的小块，而不是开局甩三屏设定。
- **叙事要能翻译成玩家的下一个行为**：好叙事不止制造情绪，要制造一个游戏能读到的下一步行为——想去那个点、想接这条支线、想再打一次。用它看到：能说出这段剧情让玩家更想做什么、并指出靠哪个指标验证（支线接取率/下一个目标点的导航行为）的，才是把叙事接回了玩法；只能说「玩家会被感动」的，是脱离玩法的自嗨。
**基准线**：载体可跳过性是核心约束：主线演出可被玩家跳过、环境/系统叙事天然不可跳过（行业共识，魂系把碎片化叙事推到极端=不主动读道具描述几乎看不懂主线，Demon's Souls 2009 起、Dark Souls 2011 成型）；ludonarrative dissonance（玩法叙事失调）由 Clint Hocking 2007 年以 BioShock 为原案例提出、成为该岗高频框架；分支叙事成本随选择膨胀，主流靠「假分支」收束到少数结局（Telltale《行尸走肉》2012、《底特律：成为人类》2018 是常被引的两端）；单局/单章的叙事节奏锚=战斗探索与情感停顿的交替密度，是演出排布的依据。具体「读完率/跳过率」阈值随品类（开放世界 vs 线性叙事、主机 vs 手游）差异极大，行业经验，无统一公开基准。
**战例**：魂系列碎片化叙事（Demon's Souls 2009、Dark Souls 2011 起）——把世界观拆进道具描述、场景废墟、NPC 残句，玩家主动拼凑（教「用环境与系统叙事做不可跳过、可深挖的叙事，绕开没人读长文本的难题」；其反面也是真争议，见悬案）／BioShock「Would you kindly」（2007，Hocking 失调论的原案例）——玩法给你自由意志、剧情却揭示你一直被一句指令操控，玩法体验本身成了主题（教「让玩法机制承载主题，叙事和玩法对齐而非各讲各的」）。
**悬案**：
- 碎片化/环境叙事 vs 明示叙事：魂系派：碎片化叙事不打断玩法、靠玩家主动挖掘制造沉浸与解读乐趣，是叙事与玩法不打架的最优解。；明示派：随用户盘扩大、难度门槛下降，大量玩家根本不读道具描述，故事门槛过高=多数人体验不到主线（《黄金树幽影》2024 评测普遍指其叙事比本体更晦涩、把这一矛盾摆上台面），该适度增加直接叙事。（2009–2024）
- 分支选择 vs 线性强作者叙事：分支派：玩家选择带来代入与重玩价值，agency 是互动叙事区别于影视的根本。；线性派：真分支成本指数膨胀、大量做成「假分支」最终收束（Telltale/Detroit 被批 illusion of choice），不如把资源砸进一条打磨到极致的线（Disco Elysium 证明重量来自心理深度、文本质感与海量 micro-reactivity，不靠分支爆炸；其文本量甚至撑爆了 articy 分支工具）。（2012–2019）
- 玩法叙事失调要不要消除：对齐派（源自 Hocking 2007）：玩法与叙事传递矛盾信息会破坏沉浸，神海主角是讨喜浪子却屠杀上千人就是反例，必须对齐。；可用派：Neil Druckmann 就 Uncharted 4 公开表示工作室「不买账」这套（认为风格化作品里死亡分量本就轻）；Spec Ops: The Line 的 Walt Williams 在 GDC 2013 主张主动拥抱失调、逼玩家直面自己的伪善（「你的角色永远不会比核心机制更正义」），失调可以是表达手段。（2007–2020）
**前沿**：LLM 驱动的动态对话/可生成 NPC 让「无限支线对话」在产能上成立，但把质控、世界观一致性、角色不崩人设变成新的叙事设计难题（2024–2025）；语音合成压低全配音成本，过场与支线配音的预算约束松动（2024–2025）；叙事消费的可观测性在变强——对话跳过率、CG 跳过率、支线完成率是已较普遍的埋点维度，用来反推哪段叙事真被消费；更细的「道具描述阅读率」等指标更多见于个别工作室或推断，未见广泛公开实践，引用宜谨慎。
### 怎么考
**分水岭**：强候选人开口先问这段叙事用哪种载体递、玩家会不会跳过、跳过了体验崩不崩，能把一个情节翻译成「玩家会做什么行为、在场景里看到什么、演出在哪个节奏点插入」，并预设大多数人不读长文本怎么办、关键信息怎么冗余进不可跳过的载体；讲玩法叙事失调时能给出对齐还是主动利用的判断（并知道这本身是有争议的，能各引一方）。弱候选人差在把岗位做成编剧——开口聊人物弧光和台词金句，讲不出靠什么载体落地、不考虑可跳过性、不提节奏与玩法耦合，把 ludonarrative dissonance 当口头禅念却给不出具体怎么对齐或利用，一被追问「玩家直接跳过这段怎么办」就卡住。这岗直觉部分可信但有系统性陷阱：自己写得动情不等于玩家会读，必须用跳过率/完成率这类数据校正「我觉得很感人」的自我感动。
**失分**：把剧情策划答成编剧，全程聊文笔/人物弧光/世界观宏大，讲不出叙事怎么经由机制和演出落地；做了一段叙事说不出它让玩家更想做什么下一步行为、用什么指标看；不考虑玩家会跳过文本、默认所有人都会认真读；演出/过场堆得打断节奏却讲不出取舍标准；聊分支选择只说「让玩家选」，不提分支成本与收束、假装能做无限真分支；把玩法叙事失调当名词背，给不出对齐或利用的具体判断、也不知道它本身是有争议的框架。
**必考**：玩法叙事失调（ludonarrative dissonance）及对齐 vs 主动利用的取舍（且知道它是争议框架）；三种叙事载体（演出/环境/系统涌现）及各自的可跳过性与成本；环境叙事与碎片化叙事的做法与门槛代价；分支叙事的成本膨胀与收束（真分支 vs 假分支）；叙事节奏与玩法节奏的耦合（情感停顿插在哪、演出取舍标准）。
**黑话**：ludonarrative dissonance（玩法叙事失调）、环境叙事、碎片化叙事、涌现叙事、embedded/emergent narrative、叙事载体、illusion of choice（假分支）、micro-reactivity（微反应）、story beat（叙事节拍）、世界观圣经（story bible）、角色弧光。
**高频题**：拆解你最近一款游戏的叙事手法，它靠什么载体讲故事／给一个老玩法加一段叙事，怎么不打断节奏／玩家大多会跳过对话，你怎么让他们还是接收到关键信息／举一个玩法和叙事打架的例子，你会怎么改／设计一条支线任务，它的叙事和奖励怎么结合。
**追问链**：「设计一条支线任务的叙事」→ ①[通用]这段故事想让玩家产生什么动机、下一步去做什么行为，怎么验证它真的让玩家想动？②[职能·游戏]用哪种载体递（演出/环境/系统）、为什么不全用过场动画，关键信息怎么冗余进不可跳过的载体？③[岗位]大多数玩家会跳过对话或不读道具描述，跳过了体验崩不崩、用什么埋点（对话/CG 跳过率、支线完成率）验证真被消费、数据不及预期你改载体还是改内容？
**定级**：初级筛「能把一段叙事用合适载体落地、不打断玩法、台词过关」；资深筛「能为整条叙事线的载体配比和节奏负责、敢砍打断节奏的演出、能在玩法叙事失调时做出对齐或主动利用的判断，并用跳过率/完成率反推叙事是否真被消费」。

## 游戏客户端程序 · Client Programmer
> 把策划的玩法和美术资源用引擎做成玩家设备上跑得稳、能持续更新的游戏。
**细分**：游戏
**职能**：技术
**核心工作职能**：
- 落地玩法逻辑与表现:把策划案和美术资源接成可玩的战斗/UI/数值循环,状态机、动画事件、特效音效卡点都对得上
- 守住帧率与内存预算:在目标机型矩阵上把帧率达标率、内存水位、DrawCall、GC 压在预算线内,用 Profiler 定位瓶颈再砍
- 搭热更新与版本管线:做代码/资源热更通道、灰度分包、回滚开关,让线上 bug 能当天修不等商店审核
- 做跨机型适配与崩溃治理:盯崩溃/ANR 看板,按机型分布做分级画质与降级策略,把高端机的酷炫和低端机的能跑都接住
- 对接服务端与引擎/TA/策划:定客户端-服务端协议与同步表现,接 TA 的 shader 和美术规范,把策划改的数值热更下去
### 怎么想
**心智模型**：
- **先看真机 Profiler 不看代码**：外行先看代码写得漂不漂亮,老手先在目标机型上挂 Profiler 截一段卡顿,看是 CPU 算逻辑、GPU 画不过来、还是 GC 卡了一刀。用它你能在没数据前先闭嘴,定位是 CPU bound 还是 GPU bound 再决定优化方向,别凭直觉去抠一个根本不是瓶颈的循环。
- **帧预算倒推法**：60 帧每帧只有 16.6ms,30 帧 33ms,这是硬墙;逻辑、渲染提交、UI 重建、GC 都从这个预算里扣。用它你能把'好像有点卡'翻译成'这帧逻辑吃了 8ms 超了',反推该砍谁;脱离帧预算谈优化都是玄学。
- **GC 卡顿是省卡顿不是省内存**：托管堆攒够垃圾触发一次 GC,默认 stop-the-world 会把主线程停一刀(分配多时可达上百毫秒),表现为周期性掉帧;Unity 现在默认开增量 GC 把这一刀摊到多帧降低尖峰,但摊不掉总量、且增量本身有写屏障开销。用它你能看见外行看不见的坑:string 拼接、装箱、闭包、每帧 new、协程 yield 都在偷偷产垃圾,要靠对象池和零分配写法把它压住,而不是等内存爆或指望增量 GC 兜底。
- **DrawCall/Batch 比三角形数更要命**：移动 GPU 的瓶颈常常不是画多少三角形,而是 CPU 一次次设渲染状态、提交 DrawCall 的开销;同材质合批、图集、GPU Instancing、SRP Batcher 都是为了把提交次数和状态切换压下来。用它你能解释为什么一个满屏粒子和 UI 叠层比一个高模角色还卡,先合批再说优化模型面数。
- **该上热更的时候才上热更**：默认能走商店正常更新就别引虚拟机/解释执行,热更框架会带性能损耗、首次加载开销、维护复杂度和 iOS 审核风险。用它你能判断打破常规的时机:只有当线上修复时效、活动配置频率、买量测试节奏逼到非热更不可时,才付这份工程代价,而不是为了酷默认上 Lua。
- **别信自己旗舰机的体感**：开发机和测试用的高端机永远不卡,真实玩家分布里大量是两三年前的中低端机和小内存机型。用它你能校准自己的判断:任何'我这跑得很顺'的结论都要拿目标最低端机型和真实机型/系统版本分布去验证,崩溃和卡顿往往只发生在你手上没有的那台设备上——拿不到机型分布数据,你对流畅度的判断大概率偏乐观。
**基准线**：帧率档主流是 30/60,部分高刷设备做到 120(随品类:重画面开放世界常保 30/60、竞技品类追稳定 60+);考核常看帧率达标率(稳定在目标帧的时间占比)而非峰值。内存水位移动端常按机型分档设预算(低端机要给系统留余量,OOM/FOOM 是崩溃大头),具体数随引擎/品类/纹理量差异大。崩溃率/ANR:腾讯 Bugly 等平台按设备数/用户数维度算,行业经验把崩溃率压到千分级(0.1% 量级算优秀、超 1% 很差)、ANR 更低视为健康,具体阈值随品类与渠道要求差异大,以上为行业经验非硬线。包体首包受渠道(尤其 Google Play/iOS App Store 的大小限制)约束,核心靠分包把首包压小、其余边玩边下。
**战例**：王者荣耀用帧同步(lockstep,只同步输入指令、客户端做确定性模拟)做 MOBA 实时对战——教"省带宽靠同步输入而非状态,代价是逻辑必须确定性(定点数/同步随机种子)、裸客户端易外挂、要靠 AI 顶替和断线重连追帧"／原神移动端用区块+LOD 流式加载+预取+按需卸载把开放世界压进内存预算,并提供资源管理让玩家选下载范围控存储——教"开放世界靠流式加载和按卸载半径卸载把内存压住,而不是全量常驻"。
**悬案**：
- 帧同步 vs 状态同步：帧同步派:只同步输入指令省带宽、天然适合 MOBA/格斗这类强交互高频对战,逻辑全在客户端、表现一致、支持录像回放(存输入序列即可复现)；状态同步派:服务端权威算逻辑、反外挂强(裸客户端的帧同步透视/加速/自瞄难防),不要求确定性(跨端浮点一致是噩梦),弱网下靠状态插值更平滑、不会因一人卡顿全场锁步等待（长期争论,随品类定(2010s 至今)）
- 热更方案之争:Lua(xLua) vs HybridCLR vs 不热更：Lua/xLua 派:成熟稳、改完即生效适合频繁改的 UI/活动逻辑,Lua 是解释执行、iOS 审核相对宽松;HybridCLR 派:直接热更 C# 全代码、能继承 MonoBehaviour、执行接近原生、省掉 Lua 与 C# 双语言交互的胶水成本；不热更派:热更带来解释执行的性能与首加载开销、维护复杂度,iOS 审核对'用下发代码改变 App 核心功能'有红线、踩线有下架风险,中小项目走正常商店更新更省心（华佗(Huatuo)2022 开源、后更名 HybridCLR 后争论升温,持续至今(2020s)）
- Unity UI:UGUI vs UI Toolkit：UI Toolkit 派:基于 web 技术的保留模式 UI(USS/Flexbox+数据绑定),重建开销可控、适合复杂数据驱动界面,是 Unity 主推方向；UGUI 派:同为保留模式但 GameObject/组件化、运行时生产验证多年,与 Animator/Timeline 动画和自定义 shader/遮罩生态成熟;UI Toolkit 运行时在复杂动画和渲染特效上还不够顺手,很多团队混用(列表数据用 Toolkit、需炫动效的用 UGUI)（UI Toolkit 2019 起推、运行时成熟度争论持续到 2024-2025）
**前沿**：AI 辅助写胶水/接口/补丁代码和单元测试已成日常,客户端这层重复的样板代码(数据类、协议绑定、UI 拼装)最先被生成;LLM 辅助生成 UI 布局与简单交互、自动化崩溃栈归因与去重、根据玩法描述生成状态机骨架都在试水(2024-2025)。重心从手敲样板往"定规范+审 AI 产出+守住性能/崩溃/内存的判断"移,真机调优、帧预算分配、跨机型适配这些要真设备和经验的活仍是人的核心价值。
### 怎么考
**分水岭**：
- 答表面 vs 识根本｜弱：卡了就说'优化一下代码''减少 DrawCall',不问到底卡在哪｜强：先问目标机型和当前帧耗,挂 Profiler 分清 CPU bound / GPU bound / GC 卡顿,再决定是合批、降逻辑频率还是治内存分配
- 套模板 vs 看情境｜弱：不管什么项目都说'上对象池''上热更''上 ECS',背方案清单｜强：按品类和阶段判断:小项目热更不划算、ECS 学习成本超收益、对象池只对高频分配的对象上,讲得出付这份复杂度的条件
- 需提示 vs 自驱｜弱：等需求文档和 bug 单,功能做完就交,不主动看线上数据｜强：主动盯崩溃/ANR/帧率看板,发现某机型崩溃飙升自己去拉栈定位,上线前自己拿低端机回归一遍流畅度
- 被动 vs 主动｜弱：策划改数值就改代码,服务端给啥协议接啥,出问题甩'是别人的问题'｜强：提前和策划约定配置可热更下发、和服务端定协议时就考虑客户端表现和弱网兜底、给 TA 提性能可控的美术规范,把问题挡在接口之前
- 影响自己 vs 影响系统｜弱：只关心自己那个功能跑通,改完留一堆临时埋点和魔法数｜强：沉淀通用的资源加载/UI/状态机框架、定团队的内存与帧预算规范和崩溃治理流程,把整个客户端的质量基线提上去
**失分**：不挂 Profiler 凭感觉优化、抠错瓶颈;只在自己旗舰机上测就断定不卡、不验证低端机和真实机型分布;把帧率掉锅全甩给美术资源,看不到 GC/DrawCall/UI 重建的客户端责任;张口就上热更/ECS/对象池讲不出付出的代价和适用条件;只管功能跑通、留一堆临时埋点和魔法数欠技术债;讲不清崩溃/ANR/OOM 怎么定位和分级治理;帧同步状态同步只会背定义,讲不出确定性、反外挂、弱网这些真权衡;把 UGUI 说成立即模式(它和 UI Toolkit 都是保留模式,立即模式是 IMGUI)
**必考**：
- 内存与 GC [应用]：背得出托管堆/GC 定义是失分线;能说出哪些写法产垃圾(string 拼接/装箱/闭包/每帧 new)、怎么用对象池和零分配压住、GC 卡顿表现为周期性掉帧、增量 GC 是摊尖峰不是减总量,才是高手线
- DrawCall 与渲染优化 [分析]：知道合批/图集/Instancing 名词是基础;能解释移动端瓶颈常在提交次数和状态切换而非三角形数、为什么 UI 叠层和满屏粒子比高模还卡,才是分析层
- 帧同步 vs 状态同步 [评价]：能背两者定义是失分线;能就具体品类(MOBA/卡牌/MMO)论证选哪个、讲清确定性/反外挂/带宽/弱网/断线重连追帧的真实权衡,才是评价层
- 热更新方案 [评价]：知道 Lua/ILRuntime/HybridCLR 是什么、各走解释执行还是扩 IL2CPP 是基础;能判断该不该上、各自的性能与维护代价、iOS 审核红线踩在哪,才是高手线
- 崩溃与跨机型适配 [应用]：能复述崩溃率/ANR 概念是基础;会拿真机和机型分布定位、做分级画质与降级策略、讲清怎么从崩溃栈/符号化归因到修复,才是应用层
**黑话**：DrawCall、合批/Batching、图集/Atlas、GPU Instancing、SRP Batcher、GC/托管堆/对象池/增量GC、Profiler、帧预算、CPU bound/GPU bound、AssetBundle/Addressables、首包/分包、热更新/灰度/回滚、帧同步/状态同步、确定性/lockstep、追帧/断线重连、状态机、协程、LOD、OOM/FOOM/ANR/崩溃栈/符号化、IL2CPP/Mono、UGUI/UI Toolkit/IMGUI

**定级**：初级筛:能用引擎把一个功能(战斗/UI/动画)做对、读懂 Profiler 找出明显瓶颈、知道 DrawCall 和 GC 是什么并会基本规避、改完会在真机上自测。资深筛:能为整个客户端的帧率/内存/崩溃基线负责、定资源加载和 UI 框架与性能规范、判断热更/同步方案的选型与代价、拿机型分布和线上看板做分级适配与崩溃治理、把质量挡在接口和上线之前并带得动团队的工程纪律。

**职能**：市场营销
**必考**：LTV/CAC 与回收周期测算；素材测试与衰减应对；区域市场差异（题材、渠道、定价）；混合变现（IAA+IAP）的账。
**高频题**：新游上线前的发行计划怎么排／买量成本涨了 50%，怎么办／一个区域 ROI 达标但量很小，加不加预算？
**内行**：筛「回收模型的真实手感」：LTV 预估的置信区间、素材衰减的应对节奏。只报 ROI 数字、讲不出预估和实际差异管理的没操过盘。
**追问链**：「买量成本涨 50%」→ ①先调出价、素材还是市场？②回收周期从 6 个月放到 12 个月的依据？③这个区域还值不值得投，怎么算？
**深度**：game-growth-ua

## 游戏美术 · Game Artist
> 产出游戏的视觉资产：角色、场景、UI，在风格与成本间平衡。
**细分**：游戏
**职能**：设计
**必考**：美术管线与协作（原画-建模-引擎的交接）；风格统一性的把控方法；资源性能意识（面数、贴图、内存）；作品集每张图的设计意图。
**高频题**：风格参考和实机效果差距大怎么收敛／工期砍半，美术质量怎么保／点评一款游戏的美术包装。
**内行**：筛「管线协作意识」：风格统一怎么落到规范、资源怎么过性能关。只展示个人作品、讲不出和 TA/程序协作案例的难进项目组。
**追问链**：「实机和概念差距大」→ ①问题出在哪个管线环节怎么定位？②性能预算砍面数，视觉损失怎么最小化？③外包质量参差怎么管？

## 技术美术 TA · Technical Artist
> 打通美术与程序：shader、工具链、性能优化。
**细分**：游戏
**职能**：技术
**必考**：渲染管线基础（光照模型、批处理、LOD）；shader 编写能力（讲一个你写过的效果）；美术工具链开发；性能 profile 与优化案例。
**高频题**：场景帧率不达标，从美术侧怎么优化／给美术团队做过什么提效工具／还原一个特殊画风的技术方案。
**内行**：筛「翻译能力」：把美术诉求转成技术方案、把性能约束转成美术语言。只会写 shader 不会做工具链和规范的是半个 TA。
**追问链**：「帧率不达标」→ ①GPU 还是 CPU bound 怎么快速判断？②砍效果的优先级和美术怎么谈？③长期的资源规范怎么建？

## 内容审核 / 风控 · Content Moderation
> 守平台内容安全：规则执行、边界判断、应急响应。
**职能**：运营
**细分**：社区内容
**必考**：审核标准的边界感（给模糊 case 现场判）；政策法规敏感度；高压审核下的效率与准确平衡；心理承受与团队管理（管理岗）。
**高频题**：给你三个边界 case 现场判并说理由／标准更新当天积压爆了怎么办／误删大 V 内容引发舆情怎么处理。
**内行**：筛「灰度判断的一致性」：同类 case 判罚是否稳定、能不能讲清规则背后的精神而非死磕条文。机审时代人审的价值在边界 case 和规则反哺。
**追问链**：「边界 case」→ ①你的判断依据是条文还是精神？②同事判的和你相反怎么对齐？③这类 case 怎么反哺规则和模型？

## 物流 / 仓储运营 · Logistics Operations
> 管仓配履约：库存准确率、时效、成本、旺季弹性。
**职能**：运营
**细分**：电商
**必考**：仓内流程优化（波次、动线、库位策略）；履约时效拆解（揽收-干线-末端）；旺季产能规划（人力弹性、爆仓预案）；一次降本或提效的量化案例。
**高频题**：大促单量翻三倍怎么保履约／库存准确率上不去的排查路径／干线成本涨了，时效和成本怎么取舍。
**内行**：筛「爆仓时刻的指挥力」：优先级怎么排（先保什么单）、应急预案是真演练过还是纸面的。没经历过大促洗礼的仓配运营是温室的。
**追问链**：「大促保履约」→ ①临时工效率只有正式工六成怎么排产？②爆仓了先停哪类入库？③时效赔付和加班成本怎么算账？

## 商品运营 · Merchandise Operations
> 管商品的全生命周期：选品、定价、库存、活动坑位，对 GMV 和毛利负责。
**细分**：电商
**职能**：运营
**必考**：选品逻辑（数据指标 + 供给盘点）；价格与促销机制（满减/直降/券的毛利账）；库存周转与滞销处理；大促坑位规划与货品结构。
**高频题**：大促前怎么定货品结构和坑位／一个品类 GMV 跌了 20% 怎么排查／滞销库存怎么清不伤价格体系？
**内行**：筛「毛利意识」：GMV 嘴上都会讲，能把毛利、周转、退货率连成一本账的才是干过的。只讲流量打法、没有库存周转天数概念的会被判成运营助理水平。
**追问链**：「大促货品结构怎么定」→ ①引流款亏多少你能接受，怎么算？②爆款断货和压货哪个更伤，为什么？③坑位给了数据不行的商家怎么收回？

## 短视频运营 · Short Video Operations
> 经营账号矩阵与内容流水线：选题、数据复盘、流量机制、商业化衔接。
**细分**：短视频直播
**职能**：运营
**必考**：平台分发机制理解（完播/互动权重、流量池递进）；选题与爆款方法论（流水线而非灵感）；数据复盘颗粒度（5 秒完播、跳出点定位）；账号矩阵与人设管理。
**高频题**：一条视频数据扑了，怎么归因／从 0 起一个账号，前 30 天做什么／自然流量和投流怎么配合？
**内行**：筛「把内容当实验」的人：讲得出 5 秒完播率、黄金 3 秒改过什么的是真做过；只会说「内容为王」的是看过几篇公众号。最失分是把爆款归因成运气。
**追问链**：「视频数据扑了怎么归因」→ ①完播曲线哪一秒掉的，对应画面是什么？②同选题换钩子重发，平台判不判重复？③这套归因批量化后，产能和质量怎么平衡？

## 游戏制作人 · Game Producer
> 对一款游戏的成败负总责：立项、团队、节奏、品质与商业化的总指挥。
**细分**：游戏
**职能**：产品
**必考**：立项判断（品类、目标用户、差异化、市场窗口）；研发节奏与里程碑管理（DEMO/首测/上线）；跨职能团队（策划/美术/程序）的协调与取舍；商业化与长线运营的平衡。
**高频题**：一个项目做了两年还不达标，砍还是续／首测数据一般，上不上线／团队在玩法方向上吵翻了你怎么拍板？
**内行**：筛「敢拍板并负责」：制作人是为结果负责的那个人，最怕和稀泥、不敢砍。讲不出一次顶着压力做取舍的没真正当过制作人。
**追问链**：「两年不达标」→ ①你用什么判断是方向错还是没做到位？②沉没成本这么大怎么说服老板砍？③要续，下一个里程碑的生死线怎么定？
